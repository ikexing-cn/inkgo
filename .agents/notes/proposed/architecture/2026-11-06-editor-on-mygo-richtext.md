# Agent Note: 正文编辑器以后换到 mygo 的 richtext

Status: proposed

## Problem

正文编辑器 `editor/` 是在 mygo 之上自己写的（[纯 Go 编辑器](../../implemented/architecture/2026-10-07-pure-go-native-editor.md)），约 3600 行。那篇记着两个已知上限：没有无障碍；章节越长，每次编辑越慢。mygo 后来有了富文本编辑器 `ui/richtext`，这两处它都有。

[盘点](2026-11-06-reinvented-wheels.md)第 18 条，作者说「考虑一下mygo的编辑器」；看过评估后说：「mygo 这个设计也保留笔记，也是后面再换」。本篇记下换的理由、现在换不了的原因，和以后换之前要等到、要验证的事。

## Proposal

### 它比我们好的

- **无障碍**：读屏软件（VoiceOver、Orca、讲述人）能读，我们完全没有。
- **超长章节**：rope 存文本，只排看得见的段落。Claude 2026-11-06 不开窗口实测，打一个字：

  | 段数 | 我们（只排版） | richtext（排版加画一帧） |
  |---|---|---|
  | 100 | 0.4 ms | 未测 |
  | 1000 | 2.5 ms | 约 5 ms |
  | 10000 | 26 ms | 约 5 ms |

  我们随段数线性变慢：正文是一整个 `[]rune`，每次编辑整份复制（`editor/doc.go` 的 `replace`），排版每段过一遍。一章通常几十到两百段，这个长度我们不慢。
- 首行缩进、段距是它主题里的现成项；复制粘贴认富文本。
- 输入法、撤销两边都有，不算差别。

### 现在换不了的

mygo v0.7.4 的 richtext 公开接口不够（Claude 核实过）：

- `EditorOptions` 只有标签、占位、字体、只读、两个链接回调、Tag 样式、主题（`ui/richtext/view.go` 18–46 行），没有按键回调，也没有绘制回调。
- 按字取屏幕位置的 `BoundsForRange` 是私有方法（`ime.go` 186 行）；公开的只有按段落取位置的 `VisibleParagraphs`。
- 没有「只显示、不进正文」的插入：AI 灰字、行内建议（原文划线、新字跟在后面）都要靠它。
- 没有公开的滚动接口。

所以这些现在做不出来，或者只能在上面再叠一层、自己复刻它的排版来算位置：AI 灰字续写和 Tab 接受、行内建议、补全弹窗、名字悬停、查找高亮（用格式做会进撤销栈）、按字定位的页边批注、手机预览的滚动锚点、打字机模式、分页预览。正文标记（伏笔、回收、检查、AI 采纳）能挂在 Tag 上，但我们的映射规则要重写。

[两端对齐](../feature/2026-11-02-justified-prose-and-adjustable-spacing.md)和[纯 Go 编辑器](../../implemented/architecture/2026-10-07-pure-go-native-editor.md)当初否掉 richtext、`TextArea`，理由是一样的。

### 以后换之前

- **要 mygo 先开放的**：按键回调（至少 Tab、Esc 和我们自己的快捷键）；按字取屏幕位置；只显示、不进正文的插入，或者自定义的绘制层；滚动位置的读写。请 mygo 加这些是对外的事，由作者定什么时候提。
- **先做的小样**：
  1. 灰字续写和行内建议在 richtext 上能不能做，光标位置准不准。
  2. 我们的快捷键能不能在它之前拿到。
  3. 同一台机器、同样的稿子，打字的耗时对比。
  4. 中文断行、避头尾对照：引号、破折号、省略号，三个平台都看。它用的是 go-text 的 UAX #14 断行，我们是手写规则。
- **换的方式**：整体换，不两套并存。正文标记、撤销、页边批注、手机预览一起迁。
- **在那之前**：第 5、19 条照旧在现在的编辑器里修，不算白做：mygo 开放接口要时间，19 是作者现在就看得见的问题。

## Alternatives considered

- **现在就换，缺的靠叠层复刻排版。** 最强的理由是马上拿到无障碍和长章的速度。没选：AI 功能会倒退，复刻的排版和它实际的排版会对不上；haiku 粗估两到三个月。
- **把 richtext 拷进仓库自己改。** 没选：它依赖 mygo 的 `internal` 包，要连着拷，等于维护一份分叉，mygo 0.x 版本间的变动都得自己跟。
- **一直留着自写的编辑器，只修长章节的慢。** 可行，比如把正文换成分段存。没选为方向：无障碍还是没有，作者要的是以后换到 mygo。

## Acceptance criteria

- mygo 开放了上面那几样接口以后，四个小样都做过，结果写回本篇，作者看过再定什么时候换。
- 换完以后：灰字、行内建议、补全、名字悬停、查找、页边批注、手机预览、正文标记都和换之前一样能用；有无障碍；一万段的章打一个字不明显变慢。
- [纯 Go 编辑器](../../implemented/architecture/2026-10-07-pure-go-native-editor.md)同步改，互链本篇。

## Risks

- 要等 mygo 加接口，什么时候有不由我们定。
- mygo 是 0.x，接口会变。2026-10-10 升级时已经碰到过两处变动。
- 换编辑器碰的地方多：desk、ext 里用 editor 包的地方都要改。
