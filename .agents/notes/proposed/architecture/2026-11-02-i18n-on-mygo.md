# Agent Note: 多语言用 mygo 自带的 i18n，中文为源语言

Status: proposed

## Problem

2026-11-02 作者要求现在就定下多语言方案，免得以后的需求被现在的写法卡住。

现状：

- 界面文案全写在 Go 字面量里。非测试代码里带汉字的行约 1700，`desk` 顶层约 1000；没有任何字符串表或语言设置。
- 应用没有注册翻译表。按 mygo 的规则，这样的应用「只有英文」，所以 mygo 自带的控件和 macOS 的默认菜单栏大概率显示英文（从 mygo 源码推断，没在应用里看过）。
- 错误直接显示 `err.Error()`（[desk/kit/status.go](../../../desk/kit/status.go)）。`workspace`、`model` 等包里的错误有中文也有英文技术前缀，没包装的英文会原样进提示条。
- 不少不是界面、但跟语言绑定的东西都假定是中文：字数按非空白字符数（`workspace/reads.go`），token 估算按中文调（`prompt/prompt.go`），导出写死 zh-CN、宋体、全角标点和缩进（`export/`），默认分类名（`workspace.Categories`），AI 提示词（`discussion/prompts.go`、`writing/rules.go`、`prompt/`）。
- mygo 0.7.4 自带一整套 i18n（`docs/i18n.md`、`i18n/catalog.go`）：
  - ARB 格式的 JSON 翻译表，ICU 消息语法（plural、select、selectordinal、数字、日期），复数按 CLDR。
  - `mygo generate` 给每个 key 生成一个带类型的 Go 函数；不带参数的消息说过一次就缓存，每帧再说只是一次查表。
  - 回退顺序：父语言 → 应用的源语言。
  - 伪语言 en-XA（加重音、拉长约四成）、ar-XB（从右往左）。只用 en-XA：作者 2026-11-02 定不做从右往左的语言，ar-XB 不加。
  - `i18n.NewLibraryCatalog(fsys, source, namespace)` 给库开一块带命名空间的表，`Catalog.Add` 能在运行时追加语言，并发安全。
  - 生成的代码提交进仓库后，`go build`、`go test` 不需要 mygo 命令行。

## Proposal

### 用 mygo 的 i18n

- 加 `mygo.json`：`{"i18n": {"dir": "locales", "source": "zh-Hans"}}`。翻译表放仓库根的 `locales/`；mygo 规定这个目录里只放翻译表和 Go 文件。
- 源语言是 zh-Hans：中文表必须写全，其他语言缺的回退到中文。
- key 用语义 ID，小驼峰，带区域前缀：`cmdNewChapter`、`toastUndo`、`settingsAiTitle`。生成的函数名就是 key，代码里读得懂；`@key` 里给译者写说明。不用中文原文当 key：改一个字 key 就跟着变，译文就失效了。
- 整句加占位符，never 拼字符串。中文用不上复数，带数量的消息照样写成 `{count, plural, other {…}}`，英文、俄文的表才有地方写。
- 底层包不出界面文案，也不 import `locales`：底层返回带类型的错误或固定的错误值，由 `desk` 翻成文案。
- 每个扩展模块带自己的表 `ext/<id>/locales/`，用 `NewLibraryCatalog`，命名空间是模块 ID。模块登记的命令、菜单、设置项，标题传 key，不传字符串（VS Code `package.nls.json` 的思路）。外部插件将来在清单里附带翻译表，经 `Catalog.Add` 加进来。见[扩展模块](2026-11-02-extension-modules.md)。

### 英文的术语

同一个词在英文表里只用一种说法（2026-11-02 定的草稿，作者看过英文界面再改）：

| 中文 | 英文 | 不用 |
|---|---|---|
| 作品 | Book | Work、Novel |
| 作品库 / 书架 | Library / Shelf | |
| 正文（页） / 正文（文字） | Write / Text | Body、Prose |
| 大纲（页） / 章纲 / 卷纲 | Outline / Chapter Outline / Volume Outline | Plan、Synopsis |
| 卷 | Volume | Part |
| 设定 | Lore | Setting（和「设置 Settings」撞） |
| 讨论 | Chat | Talk、Discussion |
| 伏笔 / 埋下 / 回收 | Foreshadowing / Plant / Pay Off（名词 Payoff） | Hook、Setup、Resolve |
| 批注 | Notes | Annotation、Comment |
| 检查 | Check | Review |
| 快照 / 回收站 / 备份 | Snapshot / Trash / Backup | |
| 专注写作 | Focus Mode | |

「第几章」是书里的字，跟书的语言，不翻（见下一节）。

### 数字

mygo 的格式化器，Go（`i18n/format.go` 的 `formatNumber`）和原型用的 TS 一样，数字默认按语言分组（1,820）。数量参数一律声明成 `int`（带小数的写 `double` 加 `::.0` 这类精度），英文的单复数才认得出；某处中文要写成不分组的 1820，就在中文那条消息里写 `{n, number, ::group-off}`，不要把参数改成 `String`。

- 原型里的字数、目标、上限现在都分组（3,000、5,000），原先有的分组有的不分，是各处自己拼的。目前没有一处用 `::group-off`。
- token 数按 DESIGN.md 写成「9.6K」，那几个参数仍是 `String`。
- 「万字」只有中文有：消息带两个参数，中文写以万计的 `value`，英文写完整的 `full`。源语言的消息必须提到译文用到的每个参数，否则 `mygo i18n check` 报错，所以中文写成 `{full, plural, other {{value, number, ::.0} 万字}}`，只拿 `full` 选复数的样子。
- 英文里「字」写成 characters（这本假书是中文的）。字数的单位以后跟书的语言走，见下一节。
- 应用还没有 `mygo.json` 时，可以在一个临时目录放 `locales/` 的副本加 `mygo.json`，用 `mygo i18n check` 查翻译表（2026-11-02 查过，只有上面那条「英文没用 value」的警告）。

### 书的语言和界面语言分开

`work.yaml` 加 `language`，默认 `zh-Hans`。字数口径、token 估算、导出的语言标记和字体、全角标点、默认分类名、AI 写作的输出语言，都跟书的语言走，不跟界面走。字段现在就加，以后再加就要迁移已有的书。

### AI 提示词先不翻译

规则继续用一种语言写，输出语言按书的语言注入。这方面能找到的研究很少，只当作以后要验证的取舍，不当规则。

### 迁移顺序

1. 建 `locales/zh-Hans.json` 和 `mygo.json`，接上 `mygo generate`，先迁 `desk/kit` 和 [desk/commands.go](../../../desk/commands.go)。
2. 底层包的错误改成带类型的，文案挪到 `desk`。
3. 功能拆到 `ext/` 时，同一次把它的文案抽进它自己的表，同一批文件不改两遍。
4. 迁完加检查：`desk`、`ext` 里除 `locales` 外不许再出现中文字面量。现成的 gosmopolitan 对中文源码误报太多，自己写一个范围小的。
5. 原型的语言切换见[原型按语言和平台预览](../process/2026-11-02-prototype-language-and-platform.md)，和应用共用 `locales/`。

## Alternatives considered

- **go-i18n v2** — 最强的理由是 Go 社区最常用，有 `goi18n extract/merge` 流程，CLDR 复数齐全。没选：mygo 自己的控件已经走 mygo 的 i18n，再起一套就有两个「当前语言」和两套回退；go-i18n 缺 key 在运行时才报错，mygo 生成的函数在编译时就报；go-i18n 的文档说运行时改 bundle 和读取并发不安全，插件带表进来不方便。
- **x/text/message + gotext** — 最强的理由是官方扩展库。没选：gotext 只从 Go 代码抽字符串，功能一直没做完，相关提案从 2022 年开着。
- **Fluent（hakastein/gofluent、lus/fluent.go）** — 最强的理由是消息模型最完整（terms、attributes）。没选：Go 实现都还没到 1.0，一个缺数字、日期函数，一个是借助 LLM 从 fluent.js 移植的。
- **中文原文当 key（gettext 式）** — 最强的理由是代码里直接看得到文案，缺译时自然回退。没选：改一个字就得改 key，AI 改文案时会顺手让一批译文失效。
- **提示词随界面语言翻译** — 最强的理由是模型看到的和作者用的是同一种语言。没选：每种语言都要单独调、单独测；输出语言要跟的是书，不是界面。

## Acceptance criteria

- 加了 zh-Hans 表以后，mygo 自带的控件、macOS 的默认菜单栏在中文系统上显示中文。
- 用 `MYGO_LOCALE=en-XA` 打开应用，界面上没有漏掉的中文字面量，文字被拉长后没有截断或重叠（`SHOT` 截图核对）。
- `go build`、`go test` 不装 mygo 命令行也能过；`mygo generate` 的翻译表检查进 `npm run verify`。
- 一个扩展模块带自己的表，切语言后它的文案跟着变，缺的回退到中文。
- 已有作品打开时 `language` 视为 `zh-Hans`，字数、导出和改前一致。

## Risks

- 1700 行的迁移是机械活，但抽错了会改掉文案的意思。要按包分批，每批截图对照。
- 原型在浏览器里用 `Intl` 算复数和数字，Go 这边用 CLDR 表，浏览器的 ICU 版本不同可能有细微差别。
- key 一旦定下就是生成的函数名，改名要全仓替换。前缀规矩要在第一批里定稳。
- 英文比中文长，按钮、菜单、侧栏会被撑开，DESIGN.md 里有些固定宽度要重新看。
