# Agent Note: 多语言用 mygo 自带的 i18n，中文为源语言

Status: proposed

## Problem

2026-11-02 作者要求现在就定下多语言方案，免得以后的需求被现在的写法卡住。

现状：

- 应用的界面文案全写在 Go 字面量里。非测试代码里带汉字的行约 1700，`desk` 顶层约 1000；应用没有语言设置。
- 翻译表已经有了，是原型做出来的（[原型按语言和平台预览](../process/2026-11-02-prototype-language-and-platform.md)）：仓库根的 `locales/zh-Hans.json`、`locales/en.json`，各 1104 条，key 的前缀约 40 种，作者 2026-11-02 看过英文界面。原型经 `L.cmdSave()` 这样的函数说话，名字和参数顺序与 mygo 将来给应用生成的 `locales.CmdSave()` 一致。
- 应用 2026-11-03 起用上这份表（见「迁移顺序」的进度）。之前应用没注册翻译表，按 mygo 的规则算「只有英文」，mygo 自带的控件和 macOS 的默认菜单栏会显示英文。
- 错误直接显示 `err.Error()`（[desk/kit/status.go](../../../desk/kit/status.go)）。`workspace`、`model` 等包里的错误有中文也有英文技术前缀，没包装的英文会原样进提示条。
- 不少不是界面、但跟语言绑定的东西都假定是中文：字数按非空白字符数（`workspace/reads.go`），token 估算按中文调（`prompt/prompt.go`），导出写死 zh-CN、宋体、全角标点和缩进（`export/`），默认分类名（`workspace.Categories`），AI 提示词（`discussion/prompts.go`、`writing/rules.go`、`prompt/`）。
- mygo 0.7.4 自带一整套 i18n（`docs/i18n.md`、`i18n/catalog.go`）：
  - ARB 格式的 JSON 翻译表，ICU 消息语法（plural、select、selectordinal、数字、日期），复数按 CLDR。
  - `mygo generate` 给每个 key 生成一个带类型的 Go 函数；不带参数的消息说过一次就缓存，每帧再说只是一次查表。
  - 回退顺序：父语言 → 应用的源语言。
  - 伪语言 en-XA（加重音、拉长约四成）、ar-XB（从右往左）。只用 en-XA：作者 2026-11-02 定不做从右往左的语言，ar-XB 不加。
  - `i18n.NewLibraryCatalog(fsys, source, namespace)` 给库开一块带命名空间的表，`Catalog.Add` 能在运行时追加语言，并发安全。
  - 生成的代码提交进仓库后，`go build`、`go test` 不需要 mygo 命令行。

## Proposal

### 用 mygo 的 i18n

- 加 `mygo.json`：`{"i18n": {"dir": "locales", "source": "zh-Hans"}}`。翻译表放仓库根的 `locales/`；mygo 规定这个目录里只放翻译表和 Go 文件。
- 源语言是 zh-Hans：中文表必须写全，其他语言缺的回退到中文。
- key 用语义 ID，小驼峰，带区域前缀，前缀以 `locales/` 里已有的为准（`cmd`、`menu`、`status`、`settings`、`chat` 这些）。生成的函数名就是 key，代码里读得懂；`@key` 里给译者写说明，带参数的消息 must 在 `@key` 里声明 `placeholders`，参数顺序就按它。不用中文原文当 key：改一个字 key 就跟着变，译文就失效了。
- 整句加占位符，never 拼字符串。中文用不上复数，带数量的消息照样写成 `{count, plural, other {…}}`，英文、俄文的表才有地方写。
- 底层包不出界面文案，也不 import `locales`：底层返回带类型的错误或固定的错误值，由 `desk` 翻成文案。
- 每个扩展模块带自己的表 `ext/<id>/locales/`，用 `NewLibraryCatalog`，命名空间是模块 ID。模块登记的命令、菜单、设置项，标题传 key，不传字符串（VS Code `package.nls.json` 的思路）。外部插件将来在清单里附带翻译表，经 `Catalog.Add` 加进来。见[扩展模块](2026-11-02-extension-modules.md)。
  - mygo 0.7.4 的命令行（`mygo generate`、`mygo i18n check`）只管 `mygo.json` 里那一个主表，给库开的表能在运行时用，但生不出带类型的函数。2026-11-04 问作者是请 mygo 加还是自己写，作者说「我们自己补吧」：仓库里自己写一个生成器，读 `ext/*/locales/`，生成和主表一样写法的函数，检查也进 `npm run verify-ui`。
  - 2026-11-04 做完：表在 `ext/<id>/<id>text/`，`npm run ext-locales`（`internal/extlocales`）生成库的表（`i18n.NewLibraryCatalog`，不登记）。它检查的和总表一样严或更严：各语言的 key 一样、参数和声明一致、每句解析得通、和总表及别的扩展不重名（原型把它们平铺在一起用）；说明和总表一样可写可不写。一个 key 只有某个扩展的代码用到就搬进去（宿主的测试改调扩展的文字包），宿主的代码也用的留在总表。

### 原型的表是基准线

原型已经落地，作者 2026-11-03 定：应用迁移时以它为准。

- 应用的一处文案，原型里已经有说同一件事的 key，就用那个 key 和那句字，不另起 key。原型的字和应用现在的字不一样时，换成原型的，每批迁完把改了字的地方列给作者看（截图里看得出来）。
- 2026-11-03 粗算：`desk` 里不重复的中文字面量约 1060 个，约 670 个和 `zh-Hans.json` 里某条一字不差。没对上的有的是同一句话说法不同，有的是 `Sprintf` 拼出来的、表里是 ICU 占位符，按字面量比不出来，所以这个数只说明多数能直接对上。`desk` 以外（提示词、`model`、`workspace` 的错误、`cmd`）几乎对不上，本来也不该进表或者要先改成带类型的错误。
- 原型里没有的字：
  - 界面上看得见的新东西（一个新按钮、一页新的设置），先在原型里做出来，key 跟着进 `locales/`（AGENTS.md 第 2 条）。比如 `desk/serviceform.go` 一个也没对上，要先看原型里对应的界面是不是缺了。
  - 错误和提示条里的说明，直接在 `locales/` 加 key，原型用不上也留着。
- 原型专用、应用用不上的 key（舞台上的工具不在表里；macOS 系统菜单那几条见下一节）不删：生成的函数没人调也不报错。

### mygo 自己的字

mygo 的控件、对话框、macOS 菜单的角色项说 mygo 自带的 zh-Hans 表里的字。2026-11-03 拿 mygo 0.7.4 的英文表和 `locales/en.json` 对过，对得上的里面中文不一样的、应用里会看见的：

| 哪里 | mygo 的字 | 原型的字 |
|---|---|---|
| macOS「Inkgo」菜单的关于、隐藏、退出（`menuAbout`、`menuHide`、`menuQuitApp`） | 关于Inkgo、隐藏Inkgo、退出Inkgo | 关于 Inkgo、隐藏 Inkgo、退出 Inkgo（中文和字母之间有空格，表里 188 条都这样） |
| 系统菜单栏的「视图」（`menuView`） | 显示 | 视图 |
| mygo 的提示对话框按钮（`ok`） | 好 | 确定 |
| mygo 的查找条没有结果（`noResults`） | 没有结果 | 未找到 |
| 角色为重命名的菜单项、mygo 的重命名对话框（`menuRename`、`rename`） | 重新命名 | 重命名 |

应用的「视图」本来就要自己建（`RoleViewMenu` 带的是网页用的项），查找、重命名也是自己画的，后三行眼下碰不到。真会露出来的是 macOS 菜单的角色项，作者 2026-11-03 定照原型带空格：

- `zh-Hans.json` 里写 `mygo.menuAbout`、`mygo.menuHide`、`mygo.menuQuitApp`（`"关于 {app}"` 这样）改 mygo 的字。这是 mygo 给应用改它的字的办法：`mygo i18n check` 按 mygo 自己的表查这类 key，占位符写错、key 不存在都报错；`@` 说明可写可不写，表里给第一条写了为什么要改。英文不写，mygo 的英文本来就是 About Inkgo。
- 原型画系统菜单用自己的 key（`appAbout`、`winMinimize` 这些），应用里这几项由 mygo 画，两边说的字 must 一样。`scripts/prototype/locales.ts` 跳过 `mygo.` 开头的 key，不给原型生成函数，另外按 mygo 的查找顺序（每种语言先查表里的 `mygo.<key>` 再查 mygo 自己的翻译，依次是显示的语言、源语言、英文）算出应用会显示的字，和原型那几个 key 对不上就报错。要改这几项的字，`mygo.*` 和原型的 key 一起改。
- 以后 mygo 的字和原型不一样、又会露出来的，照这样办：在表里写 `mygo.<key>`，原型画它的那个 key 加进脚本的对照表。

### 英文的术语

同一个词在英文表里只用一种说法（作者 2026-11-02 看过英文界面，先照这样；以后要改再改）：

| 中文 | 英文 | 不用 |
|---|---|---|
| 作品 | Book | Work、Novel |
| 作品库 / 书架 | Library / Shelf | |
| 正文（页） / 正文（文字） | Write / Text | Body、Prose |
| 大纲（页） / 章纲 / 卷纲 | Outline / Chapter Outline / Volume Outline | Plan、Synopsis |
| 卷 | Volume | Part |
| 设定 | Lore | Setting（和「设置 Settings」撞） |
| 讨论 | Chat | Talk、Discussion |
| 伏笔 / 埋下 / 回收 | Foreshadowing / Plant / Pay Off（名词 Payoff） | Hook、Setup、Resolve |
| 批注 | Notes | Annotation、Comment |
| 检查 | Check | Review |
| 快照 / 回收站 / 备份 | Snapshot / Trash / Backup | |
| 专注写作 | Focus Mode | |

「第几章」是书里的字，跟书的语言，不翻（见下一节）。

### 数字

mygo 的格式化器，Go（`i18n/format.go` 的 `formatNumber`）和原型用的 TS 一样，数字默认按语言分组（1,820）。数量参数一律声明成 `int`（带小数的写 `double` 加 `::.0` 这类精度），英文的单复数才认得出；某处中文要写成不分组的 1820，就在中文那条消息里写 `{n, number, ::group-off}`，不要把参数改成 `String`。

- 原型里的字数、目标、上限现在都分组（3,000、5,000），原先有的分组有的不分，是各处自己拼的。目前没有一处用 `::group-off`。
- token 数按 DESIGN.md 写成「9.6K」，那几个参数仍是 `String`。
- 「万字」只有中文有：消息带两个参数，中文写以万计的 `value`，英文写完整的 `full`。源语言的消息必须提到译文用到的每个参数，否则 `mygo i18n check` 报错，所以中文写成 `{full, plural, other {{value, number, ::.0} 万字}}`，只拿 `full` 选复数的样子。
- 英文里「字」写成 characters（这本假书是中文的）；底栏那一行挤，写成 chars（`Chapter 2,846 chars`）。字数的单位以后跟书的语言走，见下一节。
- 应用还没有 `mygo.json` 时，可以在一个临时目录放 `locales/` 的副本加 `mygo.json`（`{"i18n": {"dir": "locales", "source": "zh-Hans"}}`）和照抄仓库的 `go.mod`（模块名随便改），用 `mygo i18n check`、`mygo generate` 试。本机没装 mygo 命令行，在仓库里 `go build -o <临时目录>/mygo.exe github.com/egoist/mygo/cmd/mygo` 用 go.mod 里那个版本现编一个，约 8 秒。2026-11-03 试过：`check` 只有上面那条「英文没用 value」的警告；`generate` 写出约 430KB 的 `catalog_gen.go`，约 2210 个函数，自己 import 了 mygo 的 `locales/zh-Hans`，`go vet` 通过。

### 书的语言和界面语言分开

`work.yaml` 加 `language`，默认 `zh-Hans`。字数口径、token 估算、导出的语言标记和字体、全角标点、默认分类名、AI 写作的输出语言，都跟书的语言走，不跟界面走。字段现在就加，以后再加就要迁移已有的书。

进度（2026-11-04，书的语言做完；2026-11-05 新建作品时能选语言）：

- `workspace.Language`（`Chinese` 即 `zh-Hans`、`English` 即 `en`）是 `Work.Language` 的类型。读 `work.yaml` 时空的或没写的一次补成 `zh-Hans`，以后代码里见不到空值；别的值打开时报错（`bookLanguageUnsupported`）。
- 跟着语言走的都是 `Language` 的方法：`Count`（中文数非空白的字；英文数字母、数字连成的词，词中间的 `'`、`-` 不断词，夹在里面的汉字、假名、谚文一个算一个）、`Unit`（给翻译表的 `unit` 选择：`word` 或 `character`）、`OtherCategory`、`ASCIICharsPerToken`。用到语言的函数都把它当必填参数，没有「不传就当中文」：第一版用可变参数省掉了改调用处，审查时改掉，漏传一处就编译不过。
- 字数的单位：带数字的 28 条消息加了 `unit` 选择，中文书照旧写「字」，英文书写「词」，和界面语言无关（中文界面看英文书是「本章 7 词」）。讨论「参考了什么」里的几行是存下来的 Go 字符串，按书的语言选「字」或「词」。
- token 估算：英文书的 ASCII 按 4 个字符一个 token（中文书仍按 3 个），非 ASCII 仍按 1.5 个，见[按字数估 token](../../implemented/architecture/2026-10-08-token-estimate-by-character.md)。讨论旁带的光标前正文，英文书按 2000 词截。
- 导出：英文书正文 Times New Roman、标题 Georgia，语言标记 `en`，首行不缩进，纯文本不加全角空格；生成的标签和标点（大纲、设定、设定后来的变化）用英文。中文书和改之前一样。
- 新建的英文书默认分类是英文名，「其他」是 `Other`，名字补全、设定、提示词都认它。
- AI：续写、起草、改写、改稿建议的规则里加一句英文书的正文用英文写；讨论的回复不限语言，跟作者说什么话走。规则本身仍是中文。中文书发出去的请求和改之前一字不差（请求字节测试守着）。英文续写也认 `.` 作句末。
- 备份记的字数、检查的最低字数、历史版本和改稿建议里的字数都按书的语言数。
- `go run ./cmd/sample` 多写一本英文书 The Last Harbor（5 章，带设定和章纲）。
- 选语言的界面先做在原型里（新建、导入的对话框各加一栏「正文语言」，默认界面语言）。2026-11-05 作者看了截图说「三件都照做」（另两件见[扩展模块](2026-11-02-extension-modules.md)「顺序」第 8 条）：
  - 新建作品的对话框在「体裁」下面加了「正文语言」，选项是 简体中文、English（各用自己的语言写），默认跟界面语言，界面不是这两种时用简体中文；下面一行「按它数字数、排版导出，AI 也用它写。」选的语言建书时就写进 `work.yaml`，英文书一建好分类就是 `Other`。
  - `workspace.Create` 不再把空语言当中文：建书必须给 `Chinese` 或 `English`，只有读旧书时才补 `zh-Hans`。
  - 导入：应用里还没有导入书籍这个功能（原型里有整套导入表单和预览，Go 里没有对应的入口），所以这一栏只在新建里。问作者要不要现在照原型做导入，作者说「先不做」。导入做的时候照原型带上这一栏。

### AI 提示词先不翻译

规则继续用一种语言写，输出语言按书的语言注入。这方面能找到的研究很少，只当作以后要验证的取舍，不当规则。

### 迁移顺序

1. 加 `mygo.json`，`mygo generate` 写出 `locales/catalog_gen.go` 一起提交，应用 import `writer/locales`。先迁 `desk/kit` 和 [desk/commands.go](../../../desk/commands.go)，用表里已有的 key（`commands.go` 的 67 个中文字面量有 57 个和表里一字不差）。同一次把 `mygo i18n check` 接进 `npm run verify`。
2. 底层包的错误改成带类型的，文案挪到 `desk`。
3. `desk` 的字先全部迁进主表，以后可能拆成扩展的（备份、伏笔、检查、批注、手机预览、导出）也一样（作者 2026-11-03 定）。功能拆到 `ext/` 时，它的 key 随代码搬进它自己的表，见[扩展模块](2026-11-02-extension-modules.md)的「翻译表」。
4. 迁完加检查：`desk`、`ext` 里除 `locales` 外不许再出现中文字面量。现成的 gosmopolitan 对中文源码误报太多，自己写一个范围小的。
5. 原型的语言切换见[原型按语言和平台预览](../process/2026-11-02-prototype-language-and-platform.md)，和应用共用 `locales/`。

进度（2026-11-03，第 1 步做完）：

- `mygo.json` 写了 `"main": "./cmd/inkgo"`：mygo 从 app 的 main 包看它 import 了没有 `locales`，默认看仓库根，根上不是 main 包，会一直警告「没 import」。
- `desk/commands.go`、`desk/keys.go`、`desk/titlebar.go`、`desk/kit/` 迁完，除了给测试找控件的 `.Label(...)` 和 `c.Key(...)` 里的固定前缀，没有中文字面量。顺带把 `shell.go`、`write.go`、`chatcompose.go` 里写快捷键的几句换成表里带 `{key}` 的消息。应用原来的中文和表里的一字不差，界面上的中文没变；只有满一万的字数照表里的写法变成一位小数（「1.0 万字」「120.0 万字」，原来是「1 万字」「120 万字」）。新加 10 个 key（下一章、换标签页、删一个词、采纳续写这类只在快捷键表里出现的名字，和「复制代码」）。
- 命令名、快捷键表的组名和说明存的是函数（`label: locales.CmdNewChapter`，不带括号），显示时才取。命令表是包级变量，初始化在 `main()` 之前，那时取的字会定死在系统语言，切语言也不变。
- 菜单的身份不跟语言变：标题栏菜单的 `c.Key` 用固定的 id（`title-menu-file`），给测试找的 `.Label("菜单栏-" + 名字)` 仍用显示的字。
- `kit.DayOf` 仍返回显示的「今天」「昨天」；拿日期比较的地方改用 `kit.SameDay`，不拿翻译后的字比较。
- **迁完之前界面默认中文，不跟系统走**：`cmd/inkgo` 启动时 `MYGO_LOCALE` 没设就设成 `zh-Hans`。英文表应用这边还不全，跟系统的话英文系统会半中半英。`MYGO_LOCALE=en` 能看英文，mygo 不会把它存下来；不调会存盘的 `App.SetLocale`。迁完删掉这几行，到时再定语言设置放哪。
- 测试固定说中文（`TestMain` 里 `i18n.SetLocaleFunc`），不看本机的系统语言；`MYGO_LOCALE=en SHOT=<目录> go test ./desk -run Shot` 能截英文的图（比较中文字的测试这时会失败）。

进度（2026-11-03，第 3 步的 `desk` 部分做完）：

## Alternatives considered

- **go-i18n v2** — 最强的理由是 Go 社区最常用，有 `goi18n extract/merge` 流程，CLDR 复数齐全。没选：mygo 自己的控件已经走 mygo 的 i18n，再起一套就有两个「当前语言」和两套回退；go-i18n 缺 key 在运行时才报错，mygo 生成的函数在编译时就报；go-i18n 的文档说运行时改 bundle 和读取并发不安全，插件带表进来不方便。
- **x/text/message + gotext** — 最强的理由是官方扩展库。没选：gotext 只从 Go 代码抽字符串，功能一直没做完，相关提案从 2022 年开着。
- **Fluent（hakastein/gofluent、lus/fluent.go）** — 最强的理由是消息模型最完整（terms、attributes）。没选：Go 实现都还没到 1.0，一个缺数字、日期函数，一个是借助 LLM 从 fluent.js 移植的。
- **中文原文当 key（gettext 式）** — 最强的理由是代码里直接看得到文案，缺译时自然回退。没选：改一个字就得改 key，AI 改文案时会顺手让一批译文失效。
- **迁移时以应用现在的字为准，原型跟着改** — 最强的理由是应用的字在真窗口里用过，迁移只抽不改，不会顺手改掉意思。没选：原型是界面的标准（AGENTS.md），英文表和术语也是照原型的字定的；以应用为准要把 1104 条里对不上的重写一遍，英文跟着重译。
- **提示词随界面语言翻译** — 最强的理由是模型看到的和作者用的是同一种语言。没选：每种语言都要单独调、单独测；输出语言要跟的是书，不是界面。

## Acceptance criteria

- 加了 zh-Hans 表以后，mygo 自带的控件、macOS 的默认菜单栏在中文系统上显示中文。
- 用 `MYGO_LOCALE=en-XA` 打开应用，界面上没有漏掉的中文字面量，文字被拉长后没有截断或重叠（`SHOT` 截图核对）。
- `go build`、`go test` 不装 mygo 命令行也能过；`mygo generate` 的翻译表检查进 `npm run verify`。
- 一个扩展模块带自己的表，切语言后它的文案跟着变，缺的回退到中文。
- 已有作品打开时 `language` 视为 `zh-Hans`，字数、导出和改前一致。

## Risks

- 1700 行的迁移是机械活，但抽错了会改掉文案的意思。要按包分批，每批截图对照。
- 原型在浏览器里用 `Intl` 算复数和数字，Go 这边用 CLDR 表，浏览器的 ICU 版本不同可能有细微差别。
- key 一旦定下就是生成的函数名，改名要全仓替换，原型和应用两边都要改。前缀已经由原型的 1104 条定下来了，应用加 key 时照着用，不另起一套。
- 原型的字是照原型的界面写的，应用有些地方的界面和原型还不一样，硬套原型的字可能说的不是同一件事。对不上的那四成要一条条看，不要按英文或字面相近就套。
- 英文比中文长，按钮、菜单、侧栏会被撑开，DESIGN.md 里有些固定宽度要重新看。
