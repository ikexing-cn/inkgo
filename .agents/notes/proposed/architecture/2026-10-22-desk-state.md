# Agent Note: `desk` 的内部状态：书模型、打开的章节、页面和命令

Status: proposed

## Problem

这是[理一遍代码](2026-10-21-code-reorganization.md)的第 6 批。那篇说过，这一批动手前要单独写成提案。现在的样子：

**书的内容没有主人。**
- 章节树有两份：写作页的 `a.write.tree`，检查页的 `a.ck.tree`。`loadTree()` 在 7 个文件里被调用 13 次，`nodeTitle` 还会再读一次盘。
- 写作页靠手设的 `write.entered` 判断树读过没有。
  - 写作页自己和 `findInChapter`、`replaceName`、`showProp` 设上它，`View` 离开写作页时清掉。
  - `liveText`、`checkItems`、`showPref` 读它。
- 读的时机各管各的：
  - 字数在 `enterWriting` 和回收站里读；
  - 标记在每次换章、改完伏笔、打开「提醒与检查」时整本读一遍（`scanMarks`）；
  - 大纲在大纲页和起草对话框里各读一次。
- 派生数据每次调用都重算，一帧要调好几次：
  - `foreshadows()` 有 5 处调；
  - `checkItems` 和 `listedChecks` 有 8 处调，其中有侧栏角标；
  - `feedNames` 每帧重建人名链接；
  - `total()` 每次都把字数加一遍。

**打开的章节散在 `writeView` 里。**
- 编辑器、存到哪一版、时间戳、上次快照、外面改过、盘上找不到这些状态，是 `writeView` 的十来个字段。
- 不显示的标签页靠 `sheet` 收着其中 9 个，切标签时由 `park`/`unpark` 来回拷。
- 章纲有两种存法：
  - 写作页停笔片刻就存（`watch`）；
  - 大纲页只在离开时存（`finishPlanOutline`）。

**页面没有统一的进出。**
- `View` 用一个 `switch` 画页面。换页时要做的事也写在 `View` 里：存盘、离开检查、清 `entered`、收大纲页的编辑、重读检查、存偏好。
- 侧栏的页、右栏的标签（`paneTab`）、设置的分页（`prefTabs`）是三种写法。AI 关着时，各处自己跳过属于 AI 的那几项。
- 待办项按来源分派「去那里」：`pendItem` 带着 `node`、`fore`、`check`、`retry`。
- `turnAI` 一条条记着关 AI 时要停的东西：讨论、提议、检查、起草和改写对话框、设定的待确认、提示。

**同一批命令写了三遍。**
- 快捷键是 5 个文件里的 16 处 `c.Shortcut`。
- 菜单在 `titlebar.go` 和正文的右键菜单里，每项自己写快捷键提示。
- 帮助是 `keys.go` 的 `keyGroups`。
- 三处靠手对齐。

**状态和后台任务各有一套。**
- 错误、连错几次、再试一次、完成提示、操作提示，是 `App` 上 6 个字段，`toasts` 每帧同步它们。
- 后台任务的写法：
  - 讨论走 `work`/`results`；
  - 导出和书架选文件夹各起 goroutine，往 `picks` 送；
  - 备份有自己的 goroutine 和 `done`；
  - 讨论记下设定走 `changes`。

**还有两处小的。**
- 右栏设定面板靠 7 个字段（`history`、`editing`、`asking`、`change`、`shown`、`todo`、`dropped`）决定画哪一屏。几个字段可以同时有值，`settingPanel` 按 `switch` 的先后取一个，每帧还要先清掉指向已删条目的那几个。
- AI 记录把每一条都建成元素，记录越多越慢。

## Proposal

分 8 段做，每段一个委派任务，规矩和前几批一样：
- 每段先挪后改，提交分开；
- 每段都 `npm run verify` 全过，截图前后逐张对比；
- 不改作者看得到的行为，下面「会改行为的」表里列出的除外。

### 书模型：`desk/book`

- 新包 `desk/book`，类型 `Book`，不引用 `mygo`、`editor` 和 `desk`。
  - 第 7 批拆出去的页面要用它，`desk` 的子包不能引用 `desk`。
  - 不建窗口也能测。
- `Book` 持有作品的 `*workspace.Store`，和 `desk` 要读的书的内容：
  - 章节树、字数、标记；
  - 设定；
  - 大纲（卡片、情节线）和各章的章纲；
  - 存着的检查结果。
- **一棵树**：`a.write.tree` 和 `a.ck.tree` 都是它的。写作页进页面和每 2 秒看盘时读，检查页进页面时读。原来检查页的条目在进过写作页后拿写作页的树，算哪些章该检查和数失败的章名又拿检查页的树；现在都拿进检查页时读的那一份。作者能看到的差别只在树被软件外改过时：停在检查页的条目也跟着新树（以前可能还拿旧的），回到写作页也可能先看到检查页读的那份。
- **版本号**：`Version()` 在它读进或写出任何一样时加一。同一次读树没读出变化时不动；打字后的字数没变时也不动。
- **读**：作品打开时读一遍。磁盘可能被外面改的那几样，重读的时机和现在一样：
  - 每 2 秒看盘时读树；
  - 讨论记下设定后读设定；
  - 换章时读标记；
  - 进检查页时读检查结果。
  看盘的频率和做法这次不动（[少看几次磁盘](2026-10-13-fewer-looks-at-the-disk.md)）。
  - `nodeTitle` 不再读盘，用这一份树。
  - 打开时不挡坏的 outline：`PlanErr` 留着，大纲页照现在的样子说读不出来，别的页照常开。
  - 写作页进入时读树和字数（`enterWriting`，见下面「`write.entered` 去掉」）。`showPref` 不再为「提醒与检查」读树和标记。
- **写**：`desk` 改书的内容都经过 `Book`。它写 `Store`，再更新自己那份：
  - 正文保存（伏笔的改动也走这里）写完后改这一章的字数，并重读这一章的标记：`Store` 会把标记的位置夹到正文里、按正文重写 `quote`，照传进去的抄会和重读不一样；
  - 一章检查写完只改这一章的结果；
  - 章纲写完只改这一条；
  - 新建、改名、移动、删到回收站、恢复、彻底删除：写后重读树；删到回收站和恢复还重读字数；
  - 卡片和情节线：写后重读 plan（现在也是每次写完读一遍）；
  - 设定的修订和删分类：写后重读设定（现在的 `refresh` 本来也读）。
  检查做完一章、改一个伏笔，不再整本重读。
- **页面自己的**不算进 `Book`：大纲页正在改还没存的字（`outlineText`、`outlineID`、`loaded`、`loadErr`、`checked`），检查队列的 `Pending`、`Running`、`Failed`、`Tried`，还有展开、选中、滚动这些看的状态。检查队列不再存一份检查结果（原来的 `CheckQueue.All`）：要看结果的几处由 `desk` 把 `Book` 那份递进去（`Keep`、`EnqueueStale`、`AfterPause`，和改成函数的 `DueChapters`、`PrunableChapters`），检查结果只有 `Book` 一个主人。
- **派生数据**按 key 缓存：
  - 用一个小的泛型 `cached[K, V]`（`get(key, build)`），只记住上一个 key 的值；`builds` 给帧测试数。
  - key 是这个 build 读到的全部：`Book` 指针和版本号；看正在写的这一章时再加编辑器指针、`Doc` 版本和章 ID；还要看 `aiOn`、`shelf.NoNames`、`lateAfter`、`ignored` 的版本、备份失败的样子和分钟、调色板、页面。
  - 缓存的有：伏笔、检查项、列出来的检查、灵感、待办分组、人名链接、侧栏文件夹字数、检查标注、分类计数、全书字数、右栏标签的角标。
  - 缓存放在用它的功能旁边：待办分组带颜色，人名链接是 `editor` 的类型，`Book` 不引用它们。
  - build 返回的东西调用方不改；要排序、过滤或 append 的地方先 `slices.Clone`（`checkDetail` 的 `also`、`markDoubts` 的 `items`；待处理列表本来就这么做）。
- **`write.entered` 去掉**：换页要做的事收进 `turnPage`：离开的页面放下手里的（存盘、离开检查、收大纲页的编辑），进入的页面读它要显示的（写作页 `enterWriting` 读树和字数，大纲页重读，检查页 `loadChecks`），再存偏好。`View` 在建任何东西以前调一次，`pageTurn` 在建页面时再调一次，接住同一帧里标题栏或侧栏换的页；两处都只在 `a.shown != a.page` 时做事，做完把 `shown` 设成这一页，所以一次换页只做一次，第一帧仍在编辑器建出来以前。作品打开在写作页也走这里。存偏好放在进入之后，记下的是进入时打开的章和读到的字数。`findInChapter`、`replaceName`、`showProp` 自己打开要跳的章，不再调 `enterWriting`；`liveText` 看打开的章是不是在写作页上（`liveChapter`）。
- `App.Store` 留给不是书的内容的那些读写：
  - 讨论（会话、事件、追加）；
  - AI 记录、快照、回收站列表；
  - `work.yaml`、偏好的路径。
  它们各只有一处显示，没有跨页面的派生数据。包一层只是给每个多一个转手的方法，不带缓存。
- **守着**：一个测试解析 `desk` 的源码（`_test.go` 和 `desk/book` 除外）。它调了 `Store` 读写书的内容的方法，测试就失败。名单里是树、字数、标记、设定、plan、章纲和检查的那几个读写；不在名单里的：
  - `ReadChapter`、`Texts`、`Pieces`、`ChapterStamp`：正文 `Book` 不存；
  - `Work`、`SaveWork`：作品名、分类、笔名这些；
  - 讨论、记录、快照、回收站列表、偏好和关闭。
- `Book` 只在界面线程用。讨论和检查的后台任务照旧拿 `Store` 本身。讨论写下的设定，界面收到交回的刷新时由 `Book` 重读。

### 打开的章节：`openChapter`

- 一个类型管一章打开以后的事：
  - 编辑器；
  - 存到哪一版、盘上的时间戳、上次快照的时间；
  - 外面改过还没选（`external`）、盘上找不到了（`lost`、`lostTitle`）；
  - 这一章的章纲草稿；
  - 看盘、存盘、采用磁盘版本、保留编辑器版本、存为新章节；
  - 标记在编辑器和存盘格式之间的转换。
- 标签页各持有一个 `*openChapter`，显示的那个只是其中一个。`sheet`、`park`、`unpark` 去掉。
- 字号、续写方式、AI 开关改了，就设给每个打开的编辑器，不再在切回标签时补设。
- 不变的：
  - 只看显示的那一章的盘；
  - 切回一个标签时和盘上比一次（现在的 `same`、`unsettled`）。
- **章纲草稿** `outlineDraft`：写作页的那一章和大纲页正在编辑的格子各持有一个。
  - 两处都是停顿 `saveAfter` 后存；
  - 换章、离开页面、关作品时立刻存；
  - 存都经过 `Book`，另一页读到的就是新的。

### 页面

- 每个页面有 `enter`、`leave`、`view`、`count`：

  ```go
  type pageView interface {
      enter()
      leave()
      view(c *ui.Context)
      count() int // 侧栏上的数，0 不显示
  }
  ```

- `View` 换页时调旧页的 `leave` 和新页的 `enter`。现在写在 `View` 里的换页收尾，搬进各页的这两个方法。
- 侧栏的页、右栏的标签、设置的分页，用同一种表项：名字、图标、是否属于 AI、角标数。
  - 画哪几项、AI 关着时跳过哪几项、显示的那项没了换到哪项，都按表来。
  - 不再各处自己判断。
- 待办项各带一个 `open func()`，点了就调它，不再按来源分派。
- **AI 开关**：停得下来的 AI 部分在 `New` 里向开关登记一个 `off func()`。
  - 登记的有：讨论、提议、检查、起草和改写对话框、设定的待确认、状态。
  - `turnAI` 按登记的先后调它们，不再一条条记着。
  - 先后要保住现在的：先取消讨论，再放下提议。

### 一张命令表

- 每条命令有：
  - 菜单里的字；
  - 快捷键；
  - 帮助里的一行：键怎么写、做什么、在哪一组（正文、讨论、全局）；一行可以合并几条命令（「Ctrl+PgDn / PgUp」）；
  - 属不属于 AI；
  - 现在能不能用、做什么。
- 标题栏的菜单、正文的右键菜单和标签页的菜单按命令取字、快捷键提示和能不能用。点这一行要做的事是那一行自己的（标签页的「关闭」关点的那一个），只取字和提示。
- `View` 里一处按表分派快捷键，只分派显示着的页面的命令，AI 的只在开着时分派；页面自己的准备（写作页读树、暂停存盘等）先做，所以键还是在编辑器建出来以前处理。帮助对话框按表列出。`keyGroups` 去掉。
- 编辑器自己处理的键也是表里的命令，只是 `desk` 不替它分派：撤销重做、按词删除、采纳或放弃续写、剪切复制粘贴全选、滚轮调字号。剪贴那四个只给正文菜单取提示，帮助不列，帮助的字不动。
- Ctrl+Enter 留在讨论输入框里（讨论页和正文旁共用同一个框），帮助那一行从表里来。
- 菜单、输入框、查找栏、各个小面板自己的 Esc 不是命令，留在原处，帮助不列。

### 状态和后台任务

- **`status`**：管错误（连错几次、再试一次）、完成提示、操作提示。
  - 方法按发生了什么命名：`fail`、`succeed`、`retry`、`did`、`hint`、`setError`、`clear`；toast 关上时用 `closeError`、`closeNotice`、`closeHint`。
  - `toasts` 只读它。
  - `SetError` 留着并转到它，`cmd/inkgo` 在用；`warn` 也留在 `App`。
- **`jobs`**：界面线程之外的工作，做完返回一个函数；函数放进一把锁护着的队列，下一帧在界面线程上按交回的先后全部跑一遍。
  - 交回只拿锁，不阻塞，所以界面线程等一个任务（如关作品等备份）时也不会卡住。
  - 换掉 `picks`，以及导出、书架选文件夹、备份各自的 goroutine 和通道。
  - 讨论那种带名字、能取消、占着窗口的任务，也由 `jobs` 起。「再试一次」和「一次只跑一个」照旧。
  - 讨论记下设定后的刷新也交回 `jobs`；`changes` 去掉。一轮里记下几处就刷新几次，界面看不出分别。
  - 备份的 `done` 留着：它在交回结果之前关上，关作品时仍从界面线程等它。
- 检查的 `checkRunner` 不动，它在第 4 批刚理好，取消和交回结果都是它自己的事。

### 右栏设定面板：`settingRoute`

- 一个值说右栏设定那一格现在是哪一屏，分层：
  - 底下是列表、待确认、已删除之一，三者只居其一；
  - 其上某条的页面；
  - 再上某条的表单（新建条目带着它回答的问题），或某条变化的表单；
  - 最上是修改记录。
- 7 个字段合成它。
- 每帧开头一次检查它指向的条目还在不在：条目没了收起它的表单和页面，问题没了收起新建条目的表单，变化没了或不在正文里收起变化的表单。

### AI 记录

- `recordsView` 改用 `ui.List`，只建看得见的行；行的键是记录在 `a.bk.records` 里的下标。
- 头部「‹ 本作品用量」和筛选留在列表上方，记录单独滚动。
- 按功能筛过的下标放在 `bk` 里：`showPref` 重读记录时清掉它，筛选变了时重算。

### 各功能的结构体

- 手机预览、导出、大纲页各有自己的结构体，状态和方法挂在它上面。
- 别的东西走一个十来个方法的小接口 `host`：
  - 配色、`Book`、AI 开关、`status`、`jobs`、存偏好；
  - 显示的那一章、换页。
- 第 7 批把这三个整个挪进子包，不用再改。
- 写作页、讨论、右栏、伏笔、待办、提议这一团留在 `App` 上。

### 会改行为的

| 改动 | 作者看得到的 |
| --- | --- |
| 大纲页的章纲停顿后保存 | 和写作页一样：停笔片刻就存，离开大纲页时立刻存 |
| 字号、续写方式、AI 开关设给每个打开的编辑器 | 看不出区别：现在是切回标签时补设 |
| 从人名链接或讨论跳到设定条目时，一并关掉变化的表单 | 正在给某条新增变化时点人名跳到别的条目，显示那条的页面，不再显示它的「新增变化」表单 |
| AI 记录改用只建看得见的行的列表 | 「‹ 本作品用量」和筛选那一行留在上方，记录在下面滚动，不再跟着记录滚走 |

## Alternatives considered

- **书模型放在 `desk` 包里**：
  - 最强的理由：少一个包，也不用为它导出名字。
  - 不选：第 7 批拆出去的手机预览、导出、大纲页都要读书，子包不能引用 `desk`。到时候再挪，就是同一批代码搬两次。
- **缓存放进 `workspace.Store`**：
  - 最强的理由：读盘和缓存在一处，谁调 `Store` 谁就有缓存。
  - 不选：
    - `Store` 也给讨论和检查的后台任务用，带着锁；版本号和派生数据是界面线程的事。
    - 放进去，后台任务会读到不该由它管的缓存，`Store` 也就不只是磁盘了。
- **派生数据缓存在 `Book` 上**：
  - 最强的理由：那篇原来就这么写，所有缓存在一处。
  - 不选：待办分组、人名链接是 `desk` 和 `editor` 的类型，放进 `Book` 它就要引用界面。那篇要的是「失效只在一处」：只认书的版本号，就做到了。
- **`Store` 的所有读都经过 `Book`，包括讨论、AI 记录、快照**：
  - 最强的理由：那篇的验收写的是「只有书模型调用 `Store` 的读接口」，一句话就能检查。
  - 不选：这几样各只有一处显示，包一层每个多一个转手的方法，什么都不缓存。守住的是书的内容，测试就守书的内容。
- **每个功能都改成自己的结构体**：
  - 最强的理由：那篇这么写，所有方法都有了明确的主人。
  - 不选：写作页那一团共用打开的章节、讨论状态和右栏，拆开要一个四十多个方法的接口，那篇自己否掉过。只给要拆出去的三个页面做，其余的结构体只是换了接收者。
- **一次做完，不分段**：
  - 最强的理由：中间状态少，不用一段段对齐。
  - 不选：这一批改的是 `desk` 一半以上的代码，一次的 diff 没人审得动。

## Acceptance criteria

- 每段：
  - `npm run verify` 全过；
  - 截图前后逐张对比没变；
  - 只挪的提交里没有逻辑改动。
- 第 5 段以后：
  - `desk` 里 `desk/book` 以外的源码，不调 `Store` 读写书的内容的方法，有测试守着；

  - 不变的帧不重建派生数据，有测试守着：写作页（待办列表开着）、大纲页、检查页各画 10 帧，派生数据的重建次数是 0。

## Risks

- **测试 diff 会很大**：测试里直接读字段的有几百处。第 1 段先加 helper，后面几段只改 helper。
- **绕过 `Book` 写书的内容，缓存就旧了**：源码测试守着 `desk`。测试代码里直接用 `Store` 搭场景的，要在搭完以后让 `Book` 重读一次。
- **打开的章节有好几种状态**：外面改过、盘上找不到、等着问存不存。现有的标签页和保存测试都要原样通过。
- **关 AI 的先后**：登记的顺序要保住「先取消讨论，再放下提议」，`TestTurnTheAIOffAndOn` 守着。
- **后台任务和 `Book`**：讨论在后台写设定。`Book` 只在界面线程用，收到交回的刷新才重读，不能让后台任务碰它。
