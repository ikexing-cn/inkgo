# Agent Note: Ctrl+= / Ctrl+- 缩放整个界面，等 mygo 稳定后再做

Status: proposed

## Problem

作者习惯 VSCode：Ctrl+= / Ctrl+- 放大缩小整个界面（侧栏、按钮、间距等比变），Ctrl+滚轮只调正文字号。现在 Ctrl+滚轮已经调正文字号（见[走查修正](../../implemented/feature/2026-10-09-walkthrough-fixes.md)的"正文字号"一条），Ctrl+= / Ctrl+- 也暂时调正文字号，因为界面缩放做不了。

mygo v0.2.15 的原生界面没有缩放：`ui/window.go` 里 `windowHost.size()` 直接取系统给的尺寸和 DPI 缩放比，没有留给应用的系数；它的 `SetZoom` 和 Zoom 菜单角色只对网页窗口有效（`menu.go` 里原生窗口直接返回）。界面里也没有能把整棵元素树放大、同时换算输入坐标的变换。

2026-10-09 作者决定：mygo 还在快速迭代，先不做，记下方案以后再说。

2026-10-13 mygo 升到了 v0.4.8（见[依赖升到最新](../../implemented/process/2026-10-13-mygo-0.4.md)），上游仍然没有界面缩放，这一篇照旧。

## Proposal

给 mygo 的窗口宿主加一个界面缩放系数 z（默认 1）：

- `size()` 返回 `w/z, h/z, scale*z`：界面按更少的 DIP 排版，每个 DIP 占更多像素，所有尺寸、字号等比放大，画面仍然清晰（不是位图拉伸）。
- 进来的指针、滚轮坐标除以 z；交给系统的坐标乘以 z：输入法光标位置（`SetTextInput`）、右键菜单弹出位置（`popupMenu`）、无障碍树的矩形、自绘标题栏的拖动区。
- 对外给一个类似 `Window.SetUIZoom(z)` 的接口。应用里 Ctrl+= / Ctrl+- / Ctrl+0 按 mygo `zoomSteps` 那样的档位调，存进偏好；那时 Ctrl+= 不再调正文字号，正文字号只剩 Ctrl+滚轮。

落地方式按当时的 mygo 状态选：最好是上游接受这个改动（给 egoist/mygo 提 PR）；不行就把 mygo 复制进仓库（如 `third_party/mygo`），go.mod 用 `replace` 指过去，不必建远程 fork。

## Alternatives considered

- **不改 mygo，在应用里自己缩放**：主题字号和 `desk/` 里写死的字号、间距、宽度都乘一个系数。好处是不碰依赖、升级 mygo 不受影响。但要改遍整个 `desk/`，以后每处新写的尺寸都得记得乘；mygo 自带控件（按钮、输入框、菜单、弹层）的内部间距改不到，放大后显得挤，不是真正的界面缩放。
- **现在就 fork mygo**：几十行就能做出 VSCode 的效果。不做，是因为 mygo 正在快速迭代，自己维护一份分叉要不停地合上游，代价大于这个功能现在的价值。

## Acceptance criteria

- Ctrl+= / Ctrl+- 后，侧栏宽度、按钮、字号、间距一起等比变化，文字清晰；点击、拖选、右键菜单、输入法候选框的位置都对。
- 缩放档位重开软件后还在；Ctrl+0 复原。
- Ctrl+滚轮仍只调正文字号。

## Risks

- 系统 DPI 变化（窗口拖到另一块屏）时，要和 z 一起正确重算。
- 如果做成本地复制的 mygo，升级 mygo 要手动合并。
