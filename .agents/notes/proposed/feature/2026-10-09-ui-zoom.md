# Agent Note: Ctrl+= / Ctrl+- 缩放整个界面

Status: proposed

## Problem

作者习惯 VSCode：Ctrl+= / Ctrl+- 放大缩小整个界面（侧栏、按钮、间距等比变），Ctrl+滚轮只调正文字号。现在 Ctrl+滚轮已经调正文字号（见[走查修正](../../implemented/feature/2026-10-09-walkthrough-fixes.md)的"正文字号"一条），Ctrl+= / Ctrl+- 也暂时调正文字号，因为界面缩放做不了。

mygo v0.2.15 的原生界面没有缩放：`ui/window.go` 里 `windowHost.size()` 直接取系统给的尺寸和 DPI 缩放比，没有留给应用的系数；它的 `SetZoom` 和 Zoom 菜单角色只对网页窗口有效（`menu.go` 里原生窗口直接返回）。界面里也没有能把整棵元素树放大、同时换算输入坐标的变换。

2026-10-09 作者决定：mygo 还在快速迭代，先不做，记下方案以后再说。

2026-10-13 mygo 升到了 v0.4.8（见[依赖升到最新](../../implemented/process/2026-10-13-mygo-0.4.md)），上游仍然没有界面缩放，这一篇照旧。

2026-10-27 mygo 升到 v0.7.1（见同一篇）。v0.7.0 加了 `Context.SetZoom(z)`：窗口里的内容按 1/z 的大小排版、放大 z 倍、按屏幕分辨率乘 z 画，字和图标是清楚的；指针、输入法、无障碍、右键菜单、拖放都跟着换算，z 限在 0.25 到 5。这就是下面「Proposal」要给 mygo 加的那个系数，不用改 mygo 了，还没有接到 Ctrl+= / Ctrl+-。

## Proposal

用 mygo 的 `Context.SetZoom(z)` 缩放整个窗口。原型里已经做出来（`prototype/base.js` 的 `ZOOMS`、`zoomBy`、`winSize`，`prototype/app.js` 的「视图」菜单和按键），等作者看过再写代码。

- 档位照 mygo `menu.go` 的 `zoomSteps`，只用 50%–200% 那一段：50、67、75、80、90、100、110、125、150、175、200。
- Ctrl+= / Ctrl+- / Ctrl+0 是界面放大、缩小、实际大小，哪一页都管用，不再调正文字号；正文字号只剩 Ctrl+滚轮。快捷键表里拆成两条：「正文」组的「Ctrl+滚轮 正文字号增大 / 减小」，「全局」组的「Ctrl+= / Ctrl+- / Ctrl+0 界面放大 / 缩小 / 实际大小」。
- 「视图」菜单在「手机预览」下面加一段：小标签「缩放 125%」，下面「放大」「缩小」「实际大小」三行带快捷键；到头的那一行灰，100% 时「实际大小」灰。
- 缩放存进本机偏好（和外观一样，所有作品共用），重开软件还在。
- 窗口在缩放前至少 1000×680（`cmd/inkgo` 的 `MinWidth`、`MinHeight`），缩放后按 1/z 排版，所以最小尺寸跟着乘 z：放大时用 `Window.SetMinimumSize` 把它调成 1000z×680z，窗口不够大就撑大；屏幕放不下 1000z×680z 的那一档不给，「放大」灰。缩小时最小尺寸跟着变小，窗口不自己缩。界面里的「窄窗口」（窄过 1180）按排出来的宽度算，放大后常常是窄窗口。

## Alternatives considered

- **不管最小尺寸，让排版窄过 1000（VSCode 就这样）**：最简单，屏幕多小都能放大。不用，是因为窄窗口的排版只做到 1000：侧栏、右栏、纸边已经是窄的那一套，再窄正文一行放不下三十来个字，标题栏的工具会挤；要支持就得再做一套更窄的排版。
- **Ctrl+= 仍调正文字号，界面缩放只放在菜单里**：不改作者的手感。不用，是因为作者要的就是 VSCode 那样 Ctrl+= 缩放界面、Ctrl+滚轮调字号，两样都在键盘上。
- **不改 mygo，在应用里自己缩放**：主题字号和 `desk/` 里写死的字号、间距、宽度都乘一个系数。好处是不碰依赖。但要改遍整个 `desk/`，以后每处新写的尺寸都得记得乘；mygo 自带控件的内部间距改不到，放大后显得挤。mygo v0.7.0 有了 `SetZoom`，这条不再需要。
- **fork mygo 自己加缩放**：几十行就能做出来。2026-10-09 没做，是因为要不停地合上游；现在上游有了，也就不用了。

## Acceptance criteria

- Ctrl+= / Ctrl+- 后，侧栏宽度、按钮、字号、间距一起等比变化，文字清晰；点击、拖选、右键菜单、输入法候选框的位置都对。
- 缩放档位重开软件后还在；Ctrl+0 复原。
- Ctrl+滚轮仍只调正文字号。
- 放大后窗口不小于 1000z×680z，屏幕放不下的档位灰。

## Risks

- 系统 DPI 变化（窗口拖到另一块屏）时，要和 z 一起正确重算；屏幕放得下几档也跟着变。
- `SetMinimumSize` 在 Windows 上会不会把已经比它小的窗口撑大，要试；不会就自己 `SetSize`。
