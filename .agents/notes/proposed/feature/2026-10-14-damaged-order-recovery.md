# Agent Note: 章节目录文件（`.order`）坏了以后，让作者自己能恢复

Status: proposed

## Problem

2026-10-13 审查代码时发现 `chapters/.order` 坏了会让程序每次启动都崩。[审查后的一批修正](../../implemented/bug-fix/2026-10-14-review-fixes.md)改成了不崩、报错，但没有做恢复。作者 2026-10-14：「这个暂时不急，记个笔记，后续仔细讨论设计优化」。这一篇先把事实摆清楚，方案都还没有定。

**`.order` 是什么**（见[正文页和章节](../../implemented/feature/2026-10-08-writing-page-and-chapters.md)）

- `chapters/` 下每个文件夹（根和每一卷）各有一个 `.order`，是一个 JSON 列表，每个节点一项：`id`、`title`、`file`、是不是文件夹。
- 它记的是文件名记不下的三样东西：先后顺序、节点的 ID、带有文件名不能用的字符的标题。
- 软件自己写它时先写临时文件再改名（`atomicWrite`），所以它坏掉多半是外面的原因：同步软件只同步了一半或留下冲突副本、手改、磁盘出错。
- 读它时不认识的字段也算读不出来（`decodeStrict`）。以后哪个版本给它加了字段，旧版本读新版本写的作品也会落到这里。

**现在坏了会怎样**

- 任何一个文件夹的 `.order` 读不出来，整棵章节树都读不出来：页面顶上一条错误，写的是文件路径加一句 JSON 的英文报错；正文页没有章节。磁盘上什么都不动，正文一个字不丢。（`desk` 的 `TestATreeThatCannotBeRead`）
- 一卷的 `.order` 坏了，别的卷也一起看不了。
- 作者不知道 `.order` 是什么，也没有按钮可点。

**`.order` 不在时又是另一回事**

- 文件夹里没有 `.order` 不算错：每个 `.txt`、每个子文件夹都当成新节点，标题用文件名，文件夹在前、文稿在后各按名字排，发新的 ID，然后写一份新的 `.order`。这是给「手动拷进来的文件」留的路。
- 所以作者现在唯一的自救办法是手动删掉坏的那个 `.order`，等于让软件按文件名重建这一个文件夹。

**按文件名重建会丢什么**

- 跟着文件名走、不会丢的：正文、章纲、标记（伏笔）、摘要、检查结果，它们都是章节旁边同名的文件。
- 靠 ID 认、会对不上的：
  - 快照（`history/<ID>/`）：文件还在磁盘上，但新的 ID 找不到它们，快照对话框里是空的；
  - 开着的标签页、上次看的那一章、每章的光标位置（`.writer/desk.json`）；
  - 讨论里引用的正文、设定条目的出处，点「查看原文」跳不到那一章了。
- 记在 `.order` 里、会丢的：这个文件夹里的先后顺序，和文件名不一样的标题。

**丢掉的东西还能从哪里找回来**

- 备份：zip 里有作品文件夹里除 `.writer/` 以外的所有文件，包括每个 `.order` 和 `history/`。
- 坏的那个文件自己：只坏了一半时，前面的若干项还读得出来。
- 快照：每个 `history/<ID>/` 里有那一章以前的全文，可以拿来和现在的各章比，认出哪个 ID 是哪一章。

## Proposal

还没有定。下面几步可以分开做，也可以只做其中几步，等讨论：

1. **一卷坏了只影响这一卷**：别的文件夹照常读、照常显示；坏的那个文件夹在树上还在，标出它的目录读不出来。
2. **把话说明白**：不放在顶上的错误条里，放在看得见这一卷的地方。说清三件事：是哪一卷、正文没有丢、接下来可以怎么办。不出现 `.order`、JSON 这些词。
3. **给两条路，各自写明会失去什么**：
   - 从最近一份备份里取回这一卷的目录：备份里有的章节，顺序、标题、ID 都回来，快照也对得上；备份之后新建的章节排在后面，当新节点。
   - 按文件名重建：顺序按名字、标题用文件名，快照等对不上（见上面的清单）。
   - 哪一条都先把坏的那份改名留下，不删。
4. **重建时把 ID 认回来**：没有备份时，用快照的全文和现在各章的正文比，认得出的沿用原来的 ID；认不出的才发新的。
5. **读得宽一些**：`.order` 里不认识的字段跳过而不是报错，免得新旧版本之间互相读不了。
6. **预防**：每次改写 `.order` 之前把上一版留一份（放在 `.writer/` 里），坏了先拿它。

界面上的每一步都要先在原型里做出来（「少见的情况」菜单里加一种），作者看过再写代码。

要和作者定的：

- 入口放在哪：正文页中间的一块说明加按钮，还是对话框，还是树上那一卷的右键菜单。
- 文案。
- 有没有哪一步可以不问就做（比如只坏了末尾、前面每一项都读得出来时）。
- 第 5 步：`.order` 是不是唯一要放宽的文件。检查和摘要的文件现在也是不认识的字段就报错（那一批修正给它们加了 `read` 字段）。

## Alternatives considered

- **坏了就自动按文件名重建，和文件不在时一样** — 最省事，作者什么都不用懂，作品马上能打开；代码里这条路是现成的。暂时不选：顺序、标题、快照的对应会不声不响地丢掉；而且坏的原因多半是同步冲突，这时自动写一份新的 `.order`，同步软件可能把另一台机器上好的那一份也换掉。
- **保持现在这样：报错，让作者自己处理** — 软件不会替作者做错任何事，磁盘上一个文件都不动。不够：错误是一句英文的 JSON 报错，作者看不懂；一卷坏了整本书都看不了；唯一的办法（手动删文件）恰好就是上面那条会丢东西的路，而且没人告诉作者会丢什么。
- **不要 `.order`，把顺序和 ID 写进文件名或每章自己的文件里** — 就没有「一个文件坏了，一卷都读不出来」这回事。暂时不选：文件名是作者在文件夹里直接看到、可以手改的名字，塞进编号和 ID 就不好看也不好改；这是落盘格式的大改，旧作品都要迁移。可以作为更远的一步讨论。

## Acceptance criteria

等方案定了再细化，先记下不管选哪几步都该成立的：

- 一个文件夹的 `.order` 坏了，别的文件夹里的章节照常能看、能写。
- 作者不离开软件、不用知道 `.order` 是什么，就能让这一卷重新显示出来。
- 每一条恢复的路在动手之前写明会失去什么；坏的那份留着，不删。
- 从备份取回以后，备份里有的章节，快照对话框里还看得到原来的快照。
- 有测试守着这几种坏法：空文件、写了一半、多了不认识的字段、旁边有同步软件的冲突副本。
- 原型的「少见的情况」里有这一种，走查脚本里有它的步骤。

## Risks

- 用快照认 ID 可能认错：两章内容相近（比如从同一章拆出来的）时，快照会挂到另一章名下。认不准的宁可发新 ID。
- 备份比现在旧：取回的目录里没有后来新建的章，改过名的章对不上文件，都会变成新节点排在后面，顺序要作者自己再调。
- 恢复时写的新 `.order` 可能又和同步软件冲突，回到原地。
- 做成自动的（不问就重建）最容易出上面这些错，而且作者事后不知道发生过什么。
