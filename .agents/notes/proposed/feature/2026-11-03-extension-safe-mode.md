# Agent Note: 扩展的安全模式

Status: proposed

## Problem

扩展能注入核心的点，也能换掉别的扩展的东西（见[扩展模块](../architecture/2026-11-02-extension-modules.md)）。所以一个出了错的扩展可能让软件打不开，或者打开以后没法操作，作者连「扩展」页都进不去，也就没法把它关掉。

宿主出错时只停那一个扩展，但有两种情况它兜不住：

- 进程直接退出：死循环、内存耗尽、注入了启动时就跑的点。
- 扩展没报错，行为却坏了：按键被吞掉、正文画不出来。

作者 2026-11-03 定：安全模式单独写一篇，以后再做。

## Proposal

- **怎么进**，两条路：
  - 命令行 `inkgo -safe`；
  - 上次启动没走到「界面画出第一帧」就退出了，下次启动先问作者要不要进安全模式。宿主在启动时写一个标记，画出第一帧时清掉。
- **进去以后**：
  - 所有可以关的扩展都不 Setup、不 Start，只剩核心：编辑器、目录、存储、宿主；
  - 开关的设置不改，退出安全模式就回到原样；
  - 标题栏一直写着「安全模式」；
  - 「扩展」页照常能打开，能拨开关。拨的是正常模式下的开关，下次正常启动生效。
- **找出是哪个**：照 VS Code 的 Extension Bisect，先全部关掉，再一半一半地开，每轮问作者「问题还在吗」，几轮后指出是哪一个。依赖照连带规矩一起开、关，所以每次开的那一半要按依赖分组。
- **出错的记录**：上次是哪个扩展在什么回调里出的错，从宿主的账里读出来，安全模式的提示里写出来。

随软件带的扩展都开着时，设定、大纲、AI 也都没了。安全模式下能写正文、能保存，别的功能都暂时没有，提示里要写清楚。

## Alternatives considered

- **不做安全模式，靠「出错只停那一个」** — 最强的理由是宿主已经 recover，大多数错误不会让软件打不开。没选：进程直接退出、行为坏了却没报错，这两种宿主都兜不住（Fabric 生态靠崩溃报告补救，Obsidian 默认开着受限模式）。
- **出错一次就自动把那个扩展关掉** — 最强的理由是作者什么都不用做。没选：作者 2026-11-03 定开关要看得见、不偷偷改；而且有时是别的扩展注入它才出错，自动关掉会关错。
- **安全模式下也加载前置扩展** — 最强的理由是设定、大纲还能看。没选：前置扩展也可能就是出错的那个；Bisect 一样能把它们开回来。

## Acceptance criteria

- `inkgo -safe` 启动后，没有一个可以关的扩展跑过 Setup，正文能写、能保存。
- 用一个启动就退出的假扩展，第二次启动会问要不要进安全模式。
- 在安全模式下拨开关，退出后正常启动按新开关加载。
- Bisect 用假扩展测：十个里有一个坏的，最多四轮找出来。

## Risks

- 「画出第一帧」这个标记对「打开以后没法操作」的情况没用，那种只能靠作者自己用 `-safe` 启动。
- Bisect 要作者回答好几轮，扩展少的时候不如直接一个个关。所以扩展少于一定数量时，只给开关，不给 Bisect。
