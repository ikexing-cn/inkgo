# Agent Note: 真机走查里看到、还没改的几处

Status: proposed

## Problem

2026-10-16 在真窗口里走了一遍（改了的见[又一次真机走查的修正](../../implemented/feature/2026-10-16-hands-on-pass.md)），下面几处看到了没改：有的要先和作者定说法，有的要先在原型里做出来。作者说晚点一起过，先记在这里。

1. **没选文字时「记为回收」「更换原句」照样能按**：右栏伏笔详情里，未回收的写着"请先在正文中选中回收的段落"，下面的「记为回收」是黑的；按下去弹一条提示"请先在正文中选中回收伏笔的段落"，把右栏那句又说一遍。失去锚点的「更换原句」同样（"请先在正文中选中要关联的句子"）。右键菜单里的「记为回收…」没选文字时是灰的，两处不一样。`DESIGN.md` Components 的「表单」说"不等作者按了才弹提示条说不行"，可同一节的「提示条」正拿"请先在正文中选中回收伏笔的段落"当不带图标的例子，原型走查的「pay off with nothing picked」也查它。
2. **「回答」把问题原有的名字丢掉**：右栏待确认里，AI 问的一条（以问号结尾）点「回答」，表单的名字、别名两栏是空的（`desk/setting.go` 的 `idea` 里 `d.name, d.names = "", ""`）。`workspace` 的 `OpAnswer` 把条目的 `Names` 换成表单填的，所以问题条目原来带着名字、作者没再填一遍时，存下的答案没有名字，原来的名字也没了。没有名字的条目在列表和发给 AI 的设定里只能用第一句的开头指它。
3. **有章检查失败时，检查页上面仍写「已检查至「某章」」**：标题已是"检查未完成"、带警告（c614831），工具条那一行还按查到最后的一章写"已检查至"，读着像那一章以前都查过了。
4. **新建作品的位置框只露出路径的开头**：路径长时文件夹名在后面被截掉，正是作者要核对的那段。常见长度放得下。
5. **作品分类点「编辑」以后没有「取消」**：表单一直在页面底下，填进去的只能自己清掉两栏。留着不会出事，按保存也只是原样再存一遍。服务表单新加了「取消」（09d7864），这里没有。
6. **别的就地展开的表单会不会也开在视野外**：服务表单原来开在列表最下面看不见的地方，现在打开时滚进视野。右栏新增设定、回答、伏笔备注这些就地表单没有逐个查过。

## Proposal

每一条都先和作者过一遍，定了再照 `AGENTS.md` 的顺序做：界面变化先在原型里做出来，跨处的规则先写进 `DESIGN.md`。

1. 没选文字时两个按钮变灰，和右键菜单一致；右栏那句说明不随选区变，免得作者拖选时右栏跳动。提示条那条规则换一个例子（还剩"各章均已检查，正文无新改动"）；`openPay`、`rehang` 里的提示留着兜底。原型的 `pane.js` 和走查那一步跟着改。
2. 点「回答」时把问题条目的名字带进表单（第一个进名字栏，其余进别名栏）；作者删掉了才算不要名字。
3. 有章失败时，那一行改说失败的事，或说已检查几章、几章失败。具体说法和作者定。
4. 让文件夹名露出来：框里截前面留后面，或者在框下那句说明里写出文件夹名（"将新建该文件夹：雾港"）。先在原型里比一比。
5. 表单里是已有分类时加「取消」，清空两栏；或者不加，维持现状。
6. 逐个点开就地表单，开在视野外的照服务表单的做法（`ScrollIntoView`，只在刚打开的那一帧滚）。

## Alternatives considered

- **写进走查那篇 implemented 笔记** — 一次走查的事都在一处，找起来方便。没有用：那篇的 Decision 是现在时、写的是已经做了的事；这几条还没定，混进去读的人分不清哪些落地了。那篇的 Consequences 链到这里。
- **当场就改掉** — 第 2、3、5 条都不大，改起来快。没有改：作者说晚点一起过；第 1 条和 `DESIGN.md` 里现成的例子冲突，要作者拍板；第 3、4 条的说法也该作者定。

## Acceptance criteria

- 每一条都有作者的结论：改，或者不改（不改的写明为什么）。
- 改了的：先写一个在改之前会失败的测试；原型、`scripts/prototype/walk.ts`、`DESIGN.md` 跟着改；`npm run verify` 全过；这篇转 implemented，或把落地的部分并进对应的笔记。

## Risks

- 第 1 条：按钮跟着正文选区变灰变亮，右栏每帧要读编辑器的选区；正文页以外右栏也在，那时没有编辑器，按钮一直灰。
- 第 2 条：问题条目的名字可能是 AI 猜的，带进表单后作者不留意就存下了；不过它本来就在那条上，比丢掉好。
