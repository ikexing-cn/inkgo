# Agent Note: 语音输入先靠系统自带的

Status: proposed

## Problem

2026-10-19 受访的作者提了「语音输入优化」：手机上写小说的软件有语音输入，用惯了。

Inkgo 是纯 Go（`CGO_ENABLED=0`）的桌面软件，自己没有语音识别。

## Proposal

这一期不做自己的语音输入：

- Windows 自带语音输入（Win+H），macOS 有听写，都是往有光标的输入框里打字，用的是系统输入法的那一套接口。
- 要确认的事实：mygo 的编辑器接了系统输入法（中文输入法已经能用），Win+H 的字能不能进正文、进讨论的输入框。在 Windows 上试一下：
  - 能用：帮助里写一句怎么开。
  - 不能用：看 mygo 少接了哪一部分，给上游提。
- 以后真要自己做，再开一篇：要接一个语音识别模型（本地的或服务商的），和 AI 一样要能整个关掉，也要算进 AI 记录。

## Alternatives considered

- **接服务商的语音识别** — 最强的理由：识别得准，标点也能加，和 AI 用同一套服务商设置。没有用（这一期）：要录音、要发送声音，是新的一类会发出去的内容，「关闭 AI」那一套规则得重新想一遍；作者这一轮要的是大纲和时间线，先做那个。
- **本地模型（whisper 一类）** — 最强的理由：不联网，不花钱。没有用：要 CGO 或者带一个几百兆的可执行文件，和纯 Go、单个可执行文件的做法冲突。

## Acceptance criteria

- 在 Windows 上试过 Win+H，结果写进这一篇：能用就写怎么用，不能用就写差在哪。

## Risks

- 系统语音输入的质量不归我们管，作者觉得不好用时，我们能做的只有接别的识别。
