# Agent Note: 原型按语言和平台预览

Status: proposed

## Problem

2026-11-02 作者提出两点：原型也要能切语言，因为不同语言下界面的宽高比例要先在原型里看过；原型漏了 macOS 的预览，这次要补上。

现状（[本地原型](../../implemented/process/2026-10-12-local-prototype.md)）：

- 原型只有中文、只有 Windows 的样子。标题栏右端是 Windows 的三个窗口按钮（`prototype/app.js` 的 `WINDOW_BUTTONS`）；快捷键全写成 `Ctrl+X`，约 15 处；路径全是 `D:\写作` 这类 Windows 路径。
- 文案写在模板字符串里，没有表。`base.js` 的 `t()` 只做 HTML 转义，不是翻译。
- 有 54 处拿中文字面量当状态值来比较（`look: '跟随系统'`、`tab: '批注'`），切语言不能只换显示的字。
- 走查 `scripts/prototype/walk.ts` 的约 774 次点击里，约 741 次是按中文文字找按钮。
- 讨论框的发送键（`pane.js` 的 `sendKey`）只认 `ctrlKey`，⌘Enter 发不出去；别处已经是 `ctrlKey || metaKey`。
- 应用这边在 macOS 上：标题栏用 `TitleBarHidden`，红黄绿按钮由系统画在左边，标题栏从它们右边排起（`c.TitleBar().Left`）；应用没调 `SetMenu`，所以 mygo 会装上默认的系统菜单栏（App、File、Edit、View、Window），同时窗口里还有自己画的「文件、编辑、视图、帮助」。[标题栏一行](../../implemented/feature/2026-10-13-title-bar-row.md)否决系统菜单栏的理由是「在标题栏下面另占一行」，这是 Windows 的情况；macOS 的菜单栏在屏幕顶上，不占窗口。

## Proposal

分两步，各自走查全绿、截图给作者看过再走下一步。

### 第一步：平台切换

2026-11-02 已做进原型，走查里是「macOS」那一条。

- 舞台条加「Windows / macOS」切换，默认 Windows；地址栏 `?os=mac` 直接打开 macOS 的样子（`file://` 也能带查询串）。切平台就像换了一台电脑，从头开始，外观和缩放保留。
- macOS 上：
  - 左上角红黄绿三个点，标题栏从它们右边排起；右端没有窗口按钮。专注写作时也一样。
  - 快捷键经一个 `keyLabel()` 换成 macOS 的写法：`⌘N`、`⇧⌘Z`，Enter、PgDn、PgUp 换成 `↩`、`⇟`、`⇞`。重做在 macOS 上标 `⇧⌘Z`。
  - 路径换成 `~/写作` 这样的写法，备份位置的例子换成 iCloud 云盘。
  - 「要不要保存」三个按钮照 macOS 的顺序：「不保存」单独在最左，「取消」「保存」靠右，主按钮在最右。这是 [DESIGN.md](../../../DESIGN.md)「照系统的顺序」那一条在 macOS 上的样子，DESIGN.md 的这一句跟着写明两个平台。
  - 窗口上方画出 macOS 的系统菜单栏，照应用现在的样子画：英文的 Inkgo、File、Edit、View、Window。这样重复的菜单在图上看得见，要不要改由作者定（见「待定」）。
- 按键不随平台变：哪儿都认 `ctrlKey || metaKey`，在 Windows 键盘上也能试 macOS 的样子。顺手修 `sendKey`。
- 走查加一小段：切到 macOS，看红黄绿在、窗口按钮不在、菜单里是 `⌘N`、存不存的按钮顺序对，截图；再切回来。

### 第二步：语言切换

1. 先把 54 处中文状态值拆成 ID 和显示文字，这一步界面上什么都不变，走查照旧全绿。
2. 翻译表和应用共用仓库根的 `locales/`（[多语言方案](../architecture/2026-11-02-i18n-on-mygo.md)）。双击打开的页面从 `file://` 读不了 JSON，也加载不了 ES 模块，所以由脚本把翻译表生成到 `prototype/` 里一个普通的 JS 文件，提交进仓库；`verify-prototype` 检查它有没有过期。打开原型仍然不用构建。
3. 消息的格式化用 mygo 的 `packages/runtime/src/i18n.ts`（738 行，没有依赖，只用 `Intl`），用 Node 去掉类型后放进原型。这样 ICU 语法和 en-XA、ar-XB 的算法和 Go 那边是同一套。
4. 两类字不进翻译表：
   - `book.js` 里假书的正文、设定、讨论，界面换成哪种语言都还是中文。这正好演示「书的语言和界面语言分开」。
   - 舞台上的工具（重新开始、少见的情况、两个切换）只写中文。
5. 语言先有 zh-Hans、en、en-XA。英文表由 haiku 按中文表和 `@key` 说明起草，作者看过前标成草稿。
6. 走查默认用 zh-Hans，原有的按文字点击不用改；另加一小段，把语言和平台各组合打开几个主要的界面，截图，并跑现有的按钮位置、溢出检查。

### 待定（要作者拍板）

- macOS 上窗口里的菜单和系统菜单栏重复了。选项：把窗口里的菜单挪进系统菜单栏；或保留窗口里的，系统菜单栏只留 App 那一项；或维持现状。
- 应用这边和 macOS 不一致的几处，原型照 macOS 的规矩画，应用以后再改：
  - `Ctrl+Tab` 在 `desk/commands.go` 里是写死的字面量。
  - 重做是 `⌘Y`，macOS 上通常是 `⇧⌘Z`。
  - 专注写作是 F11，重命名是 F2，在 macOS 上都不是常见的键。
  - 红黄绿按钮在 40 高的标题栏里是否垂直居中，没在真机上看过；可能要设 `TrafficLightPosition`。

## Alternatives considered

- **原型自己一张文案表，不和应用共用** — 最强的理由是不用生成文件，原型想怎么写都行。没选：原型就是界面文案的标准，两张表迟早不一样，key 也会各起一套。
- **自己手写一个小的 ICU 格式化器** — 最强的理由是几十行就够用，不用搬 mygo 的代码。没选：复数、选择、伪语言的规则要和 Go 那边一模一样，搬现成的最稳。
- **走查在每种语言下全跑一遍** — 最强的理由是覆盖最全。没选：741 次点击按中文文字找按钮，全改成按 ID 找工作量很大，每多一种语言走查也多跑一分多钟；布局问题用一小段截图加现有检查就能看出来。
- **平台切换只换外框，不重开** — 最强的理由是切过去时点到一半的地方还在。没选：路径、备份位置这些在打开时就写进了状态，切到一半会出现两种写法混在一起。

## Acceptance criteria

- `?os=mac` 打开是 macOS 的样子；舞台条上能来回切；`npm run verify-prototype` 全绿，截图里两个平台的标题栏、菜单、存不存的对话框都对。
- 在 Windows 键盘上，⌘ 和 Ctrl 的快捷键在两个平台的样子下都能用；⌘Enter 能发送讨论。
- 语言切到 en 和 en-XA 时，界面文案都换了，假书的内容还是中文；走查的那一小段截图里没有截断和重叠。
- `prototype/` 里生成的翻译文件和 `locales/` 不一致时，`verify-prototype` 报错。

## Risks

- 作者用的是 Windows，浏览器和走查都画不出 PingFang、SF。macOS 的预览只说明外框、按钮、符号和排布，不代表 macOS 上真实的字宽。
- mygo 的 `i18n.ts` 升级后要重新搬一次；生成脚本应记下搬的是哪个版本。
- en-XA 按中文源文拉长，比英文实际的长度短得多，宽度要以 en 的截图为准。
