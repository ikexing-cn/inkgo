# Agent Note: 审查全部代码后的一批修正：打不开和会崩的、会盖掉外面改动的、会卡住的、说错了的

Status: implemented

## Problem

作者 2026-10-13：「审查一份当前全部项目代码，寻找架构，优化，逻辑性等问题。」审查报告分六节交给作者；作者 2026-10-14：「同意，第四节的我们先待定；其他的先修正。」第四节（`Store` 不留缓存、侧栏章节树每帧全画、重活在界面线上）不在这一篇里，量出来的数字留在[少看几次磁盘](../../proposed/architecture/2026-10-13-fewer-looks-at-the-disk.md)那篇提案里。

这一篇修的是其余五节。都是读代码找到、再用测试或计时复现过的：

**会崩、会丢、打不开**

1. 没进过正文页就打开设置的「提醒与检查」，程序崩。那一页要数伏笔，章节树原来要进正文页才读，还是空的。2026-10-22 起 `Book` 在打开作品时就读树，写作页进入时 `enterWriting` 再读，这一条不再发生。
2. `chapters/.order` 坏了（比如同步软件写了一半），每次启动第一帧就崩，进正文页也崩。
3. 外面改了正开着的这一章，在下一次看磁盘（每 2 秒一次）之前作者又打了字，自动保存直接盖掉外面的内容，不留快照，也不提示。
4. 把一章移进回收站时文件被别的程序占着（Windows 上常见），移到一半失败：回收站里多出一条恢复不了的记录，原来那一章换了 ID，快照对不上了；把那条记录「彻底删除」会删掉还在的那一章的快照。
5. `sessions/` 里多一个不是讨论的文件（`desktop.ini`、`.DS_Store`、同步软件的冲突副本），整部作品打不开。

**会卡住**

6. 快照对话框：一章 2.4 万字时鼠标每动一下 0.9 秒，6 万字 9.6 秒，30 万字 50 秒。整份快照放在一个文本控件里，超过了 mygo 留排版结果的上限（8 MB），每帧重排；对比和「是否相同」也每帧算。
7. 「起草本章」对话框：每帧给前面每一个没有摘要的章读一次盘。300 章都没有摘要时一帧 7.9 秒。
8. 第一次全书查找逐章读盘，每读一章都重读一遍章节树：300 章 3 秒，1000 章 28 秒。
9. 备份失败以后，每帧都去看一眼备份文件夹所在的盘在不在。盘拔掉时这一眼可能很慢。

**说错了的、对不上的**

10. 一章太长、超出上下文预算时，检查和摘要只读了开头一段（默认预算下检查约前 5000 字，摘要约前 9000 字）。模型被告知了，作者没有：页面上写的是「检查完成，未发现不一致」。
11. 改了某个服务的地址或 key 以后，行内续写还在用旧的那一个，要重开作品才换。
12. 标签页那一行滚不动：每帧都把当前标签页滚回视野里。
13. 文件夹页上每章的摘要超过两行不出省略号。那一句被前一次改动并进了行尾的注释里。
14. AI 改写还在进行时点了「使用磁盘版本」，改写回来以后按旧位置落在新换上的正文里。
15. `.writer/desk.json` 直接覆盖着写。写到一半断电，标签页、忽略过的提醒、每天的字数都没了。
16. 解包备份时，条目名里带 `..\` 的会写到目标文件夹外面（Windows 上反斜杠也是分隔符）。现在没有界面会解包别人给的备份，但代码在。

**没用的代码**：七个函数没有任何地方调用，一个只有测试在用，一句注释对不上下面的函数。

**`mygo vet` 报的 11 处**：十处是后台任务做完以后，用起任务那一帧的 `*ui.Context` 叫界面重画；一处是自绘菜单的构建器里存着 `*ui.Context`。

## Decision

**章节树读不出来时**（1、2）

- `Tree.Walk` 遇到没读过的树（`Root == nil`）直接返回，不崩。
- 设置里切到「提醒与检查」时，如果还没进过正文页，当时会重读一遍章节树和各章的标记（`showPref`）。2026-10-22 起 `Book` 在打开作品时已经读过，这一处重读去掉。
- `.order` 坏了仍然报错，不自己重建。打开作品时 `Book` 读树，写作页进入时 `enterWriting` 和 `loadChecks` 处再读，都把错误显示出来（`loadChecks` 以前把这个错误吞了），页面上没有章节。

**存盘前先比一次**（3）

- `Store.WriteChapterOver(id, text, marks, over)`：在 `Store` 的锁里先看磁盘上这一章的大小和修改时间是不是 `over`，不是就什么都不写，返回 `ErrChangedOutside`。
- `saveText` 用它，`over` 是上一次读或写时记下的。不一致时马上读一遍磁盘（`lookAtText`，就是原来每 2 秒那一次的后半段）：
  - 字不一样：照原来的提示条让作者选「保留当前版本」或「使用磁盘版本」，这一次不写；
  - 字一样、只是时间变了（同步软件碰过）：记下新的时间，再写一次。
- 作者一直没选就换了作品、关了作品或关了窗口：编辑器里的字存成一份「外部改动」快照（`keepUnsettled`），磁盘上留外面的内容。以前提示条已经出来而没选的，编辑器里的字哪里都不存；还没轮到看磁盘的，是直接盖掉外面的。关标签页不走这里，它照原来那样先问。
- 全书替换和改不在眼前那一章的伏笔，也是先读后写，改成写回刚读到的那一版（`WriteChapterOver(…, ch.Stamp)`）。

**回收站移到一半**（4）

- 移文件用 `moveAll`：按顺序移，哪一个失败，就把已经移过去的移回来。
- `TrashChapter` 失败时把刚建的回收站目录整个删掉，章节原样留在原处，ID 不变。
- `RestoreChapter` 先写 `.order` 再移文件，移失败就把 `.order` 改回去。
- 列回收站时，一条记录对应的正文不在它的目录里，就不算一项：以前留下的坏记录不再显示，也不再占着那一章的 ID。

**`sessions/` 里别人的文件**（5）：只认 `<合法 ID>.jsonl`，其余的（文件夹、系统文件、冲突副本）跳过，不碰。

**快照对话框**（6）

- 快照按段落拆开，一段一个文本控件，装在一个可选中的容器里：跨段选中、复制和原来一样，复制出来每段一行，空行还是空行。
- 对比结果和「是否与当前相同」只在换快照、切换「与当前对比」、正文变了的时候算一次（`snapView`），不每帧算。
- 超过 9 万字节（约 3 万字）或 1000 段的快照，只建看得见的那几段（`ui.List`）。这时选中只在看得见的段落之间，滚出去的不在选区里。
- 量出来（每段都有一个字不同，最坏的情况）：

  | 一章的字数 | 以前一帧 | 现在一帧 | 现在打开 |
  |---|---|---|---|
  | 3000 | 9 ms | 7 ms | 0.17 s |
  | 2.4 万 | 0.9 s | 17 ms | 1.1 s |
  | 2.9 万 | — | 22 ms | 1.4 s |
  | 6 万 | 9.6 s | 9 ms | 0.18 s |
  | 30 万 | 50 s | 19 ms | 2.0 s |

**起草对话框、全书查找、备份失败**（7、8、9）

- 哪些章没有摘要，在打开起草对话框时算一次，补齐摘要做完以后再算一次，不每帧读盘。300 章都没有摘要：一帧 7.9 秒 → 14 毫秒。
- `Store.Texts()` 一遍读出全书各章的正文，章节树只读一次。全书查找和「检查全书」用它。第一次全书查找：300 章 3 秒 → 88 毫秒，1000 章 28 秒 → 0.3 秒。仍然在界面线上（挪出去属于待定的第四节）。
- 备份失败时看一次盘在不在，记在 `bk.gone` 里；说明原因的文字每帧只读这个结果。

**只读了前面一段，要说出来**（10）

- 检查和摘要各多记一个数 `read`（`.check.json`、`.summary.json`，读全了就不写这个字段）：超出预算时模型实际拿到了前多少字。
- 页脚：「第 N 章仅检查前 5000 字，未发现不一致」（2026-10-15 起是「本章…」，见[指某一章写它的标题](../feature/2026-10-15-chapter-titles-not-numbers.md)）（有待处理时是「…，有 M 处待处理」），不再说「检查完成」。
- 摘要：标题「本章摘要 · 不完整」，下面一行「AI 生成 · 模型 · 时间 · 仅依据前 9000 字」，琥珀色。
- 两处悬停都说：「后文超出上下文预算，可在设置中提高预算」。2026-10-15 起是「后文超出模型的上下文上限，可在设置中「AI」配置里调整」（见[上下文上限配在模型上](../architecture/2026-10-15-model-limits-and-usage.md)）。
- 原型里先做了这一种情况（「少见的情况」→「本章过长，仅读取前文」），走查脚本跟着加了一步。这几句文案是 agent 起的，原型和软件一起做了、没有先等确认；作者 2026-10-14 看过：「可以」。

**其余**（11–16）

- 保存服务、清除 key、重新加载配置以后，把续写用的那一个重建（`modelsChanged`）。
- 标签页只在「变成当前标签页」的那一帧滚进视野，之后作者可以随便滚。
- 文件夹页的省略号放回链式调用里。
- 「使用磁盘版本」先停掉正在进行的 AI（`stopAI`）。
- `desk.json` 先写到 `desk.json.tmp` 再改名。
- 解包备份时按本机的路径规则看条目名：`filepath.IsLocal` 不过的、落在 `.writer` 里的（不分大小写、不分哪种分隔符）都拒绝。

**没用的代码**

- 删掉没人调用的七个：`App.browse`、`chapterName`、`App.paneShown`、`pill`、`Editor.Drafting`、`Doc.Runes`、`Editor.SetText`；`Engine.Send` 只是 `Say` 外面包的一层，只有测试在用，测试改成直接调 `Say`。
- `App.foreshadowOf` 只有测试用，挪进测试文件。
- 留着的：`backup.Unpack`（测试靠它证明备份解得开；「恢复备份」怎么做还待定）；`Editor.Proposal`、`Editor.Completions`、`Editor.FontSize`（`desk` 的测试要隔着包看编辑器的状态，只能走导出的方法）。

**`mygo vet`**

- 后台任务在起头的那一帧取一份 `sv := c.Services()`，做完以后叫 `sv.Invalidate()`。`Services` 是 mygo 说明里可以留到帧外的东西。连带改了两处把 `c` 留到以后再用的地方：重试（`status` 的 `retry`）和选完备份文件夹以后的那一次备份。
- 菜单构建器位于 `desk/kit/menu.go`，清单不保管帧对象。`scripts/verify-ui.ts` 把 `mygo vet` 接进 `npm run verify`，检查所有绘制包，不放行报告。详见 [mygo 升级那篇](../process/2026-10-13-mygo-0.4.md)。
- 同一天后来这一处也改掉了，用的不是下面放弃的那个办法：构建器改成只记下各行，不存 `Context`，画由一个拿着 `c` 的函数做，每行把点了要做的事交给它（`m.Item(…).Do(…)`）（见[自己画菜单那篇](../feature/2026-10-12-own-menus.md)）。`verify-ui` 不再放行任何一处。

## Alternatives considered

- **`.order` 坏了就按文件夹里的文件重建一份** — 作品马上能打开，作者不用懂什么是 `.order`。没有选：重建出来的每一章都是新 ID，靠 ID 认的东西会对不上：快照、开着的标签页和光标位置、讨论和设定里「查看原文」的出处；章节的先后只能按文件名排，和文件名不一样的标题也没了。这等于悄悄丢东西。（摘要、检查、章纲、标记是章节旁边同名的文件，不受影响；这一句原来把摘要和检查也算了进去，是错的，2026-10-14 改正。）现在是报错、不崩；怎么让作者自己恢复，作者说「暂时不急」，事实和几条路记在[提案](../../proposed/feature/2026-10-14-damaged-order-recovery.md)里，以后讨论。
- **回收站先移文件，都成功了再写记录** — 失败时不会留下记录。没有选：移到一半断电，回收站里就有一堆没有记录的文件，不知道是哪一章、从哪来的。先写记录、失败时删掉，两头都有交代。
- **存盘不比，只把每 2 秒看一次改成更勤** — 不用改 `Store`。没有选：再勤也有空当，而且作者说过 2 秒一次已经「有点太暴力了」。比一次是一次 `stat`，在本来就要拿的锁里。
- **快照整份用只读的正文编辑器显示** — 编辑器本来就只排看得见的行，多长都不卡，选中复制也是全的；「摘取原文」对话框就是这么做的。没有选：对比视图要显示当前正文里没有的字（红色删除线），编辑器只会画文档里有的字，得给它加新的标记种类和画法；外观也会跟着变成稿纸的样子。
- **快照不分长短，一律只建看得见的段落** — 一条路，打开也最快（6 万字 0.18 秒，比 2.4 万字走全建的 1.1 秒还快）。没有选：这样选中就出不了看得见的那几段，平常三五千字的一章想拖着选一大段也不行了。所以只有以前本来就卡住的长度才走这条路。
- **太长的一章分几次检查、分段摘要** — 这才是真的把后文读了。没有选：一章要调几次 AI、结果怎么合并、摘要怎么拼，是新功能，不是修正。这一次只做到不说错话。
- **菜单构建器里不存 `*ui.Context`，每个方法都把它传进来** — `mygo vet` 就一处都不报了。没有选：菜单的写法是照 mygo 自己的 `ui.Menu` 来的（`m.Item("…").Hint("…").Chosen()`），这样一改，七十多处调用每一行都要多写两遍 `c`。构建器是画菜单时当场造、画完就丢的，不跨帧，`mygo vet` 要防的那种事在这里不会发生。留着的代价：`mygo vet` 只认工具包自己的那几个类型，放行以后，`menu` 或它的一行（`menuItem`）要是被存起来、交给后台任务，它看不出来，只能靠读代码。  - 2026-10-14 后来：例外还是消掉了，办法是让构建器不画（只记行），所以不需要 `c`，也就不用每行传它。

## Consequences

**收益**

- 报告里第一、二、三、五、六节的每一条都有了交代：16 条改了，死代码删了，`mygo vet` 11 处剩 1 处并写明了为什么留（同一天后来这 1 处也没有了）。
- 外面的改动不会再被自动保存悄悄盖掉；提案里「看得稀一些之前要先补上比对」这个前提满足了。
- 新写的后台任务如果又用 `*ui.Context` 叫重画，`npm run verify` 会拦住（试过：把一处改回 `c.Invalidate()`，`verify-ui` 报出那一行并失败）。

**代价与已知上限**

- `.check.json`、`.summary.json` 多了 `read` 字段。这两个文件读的时候不认识的字段会报错，所以旧版本的程序读不了新版本写下的、带 `read` 的文件。只有一章超出预算时才会写这个字段。
- `.order` 坏了以后作品能开、但没有章节可看，作者得自己修或者从备份里取回；没有恢复的界面（[提案](../../proposed/feature/2026-10-14-damaged-order-recovery.md)）。
- 很长的快照（约 3 万字以上）选中只在看得见的段落之间。没有在真的窗口里试过拖选时的手感。作者 2026-10-14：「长字数的情况下，我们应该是动态渲染的，即只渲染目前的窗口，这个下轮对话再讨论。」现在的做法（3 万字以内全建、以上才只建看得见的）还没有照这句话改，等讨论。
- 2.4 万到 3 万字的快照打开要 1 秒多（一次排完所有段落），以后每帧 20 毫秒上下。以前这个长度是每帧 0.9 秒。
- 全书查找、起草对话框的那一次读盘还在界面线上，1000 章时分别是 0.3 秒和 0.4 秒。
- 「仅检查前 N 字」只说了没读全，没有去读后文。
- 存盘失败以后每帧重试、不退避，这一条审查时记下了，没有列进报告，这次也没有动。
- `npm run verify` 多了一项，全套慢几秒（测试都重跑时没有它 35 到 39 秒，有它 41 到 48 秒；机器忙闲带来的差别比这一项大）；`go test ./desk` 现在 25 秒上下，是全套里最慢的一项。
- 都没有在真的窗口里跑过：作者在用电脑，没有让 agent 操作桌面。

## Verification

- `npm run verify` 全绿（`go vet`、`mygo vet`、`go test`、笔记、原型；`DESIGN.md` 没改，它的那一项没跑）。
- 新加的测试，每一条对着上面的一条：
  - `workspace`：`TestATreeNeverReadHoldsNothing`、`TestTrashThatCannotMoveLeavesTheNodeWhole`（正文被占、章纲被占各一次）、`TestTrashNoteWithoutItsFilesIsNotListed`、`TestRestoreThatCannotMoveLeavesTheNodeInTheTrash`、`TestWriteChapterOverTheVersionLastSeen`、`TestTextsAreWhatReadingEachGives`、`TestFilesThatAreNotSessionsArePassedOver`。
  - `desk`：`TestSavingDoesNotWriteOverAnOutsideChange`、`TestSavingOverAFileOnlyTouched`、`TestLeavingWithAnOutsideChangeKeepsTheEditorsWords`、`TestRemindersBeforeTheWritingPage`、`TestATreeThatCannotBeRead`、`TestTheRowOfTabsScrollsFreely`、`TestSavingAServiceRemakesThePredictingWriter`、`TestTroubleSaysWhatWasFoundAsItFailed`、`TestPrefsAreWrittenWhole`、`TestParagraphsOfADiff`、`TestASnapshotSelectsAcrossItsParagraphs`（拖选三段再复制，剪贴板里和快照逐字相同）、`TestALongSnapshot`、`TestAChapterReadInPartIsToldSo`、`TestTakingTheDisksTextEndsTheRewrite`。
  - `writing`：`TestAChapterReadInPartSaysSo`。`backup`：`TestUnpackKeepsToItsFolder`。
- 其中两条拿旧代码跑过，确认会失败：解包（旧条件下 `.writer\desk.json`、`C:evil.txt` 等被解开）和改写途中换磁盘版本（去掉 `stopAI` 以后改写落在新正文上）。
- 上面表里的时间是临时测试量的（同一台机器，量完删了）；「以前」那一列是审查时量的。
- 渲染的截图看过：快照对话框（对比）、很长的快照滚动以后、读了一部分的一章（页脚和摘要）；原型里新加的那一种情况（走查存的 `86-read-in-part`）。
- 文件夹页的省略号只是把那一句放回去：渲染了一张章纲很长的文件夹页，第二行末尾是「…」；没有单独的测试。
