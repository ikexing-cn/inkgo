# Agent Note: DESIGN.md 只写每一处界面都要守的规则

Status: implemented

后续的[阅读入口整理](../architecture/2026-10-27-reading-entry-and-owned-state.md)沿用本篇分工，根 README 只提供模块地图与链接，不复述视觉规范。

## Problem

作者 2026-10-26 说 `DESIGN.md`「太多了」，「现在喂给模型就占了一堆」，「何况我们还有笔记，那里面有详细记录」。`AGENTS.md` 要求动界面之前先读 `DESIGN.md`，它有 793 行、63 KB，读一次约 2.7 万 token。多出来的主要是两样：

- 每条规则下面「检查：」列的测试和走查步骤，一共点了 138 个测试，约占正文四分之一。这是[界面规范写在 DESIGN.md](2026-10-13-design-md.md) 定的「在规则下面写明谁在查」。名单已经有一个过时：`TestDeskImportsNothingThatSends` 10-24 并进了 `desk/imports_test.go` 的 `TestImports`，这里没跟着改。
- 只管一个功能的细节：「设定随章节变化」「大纲」「页边批注」「底栏」「手机预览」整节，「标题栏」「侧栏」「标签页和保存」「就地输入」和 AI 那几节里的各种情况、文案原话。这些在原型里看得到，在各自的笔记里写得更全（「手机预览」一节的每一句，[手机预览](../feature/2026-10-21-phone-preview.md)里都有），做别的界面时用不上。

## Decision

`DESIGN.md` 只写做哪一处界面都要守的规则；一个功能自己的细节在原型和它的笔记里；查规则的测试不在 `DESIGN.md` 里点名。

- 「怎么维护」：
  - 开头一句：每次动界面都要把这份文件整个读一遍，所以只写非写不可的。
  - 第 1 条加一句：只管一个功能的（某一页怎么排、各种情况怎么办、文案的原话），写进那个功能的笔记和原型，不写进来。
  - 第 2 条改成：能自动查的就加检查，这里不列测试和走查步骤的名字，不守规则检查自己会报。
  - 第 3 至 6 条的号不变，[每条界面规则只写在一处](2026-10-15-each-rule-said-once.md)里说的「第 4 条」照旧对得上。第 6 条只留「警告照实留着」：`DESIGN.md` 改了，`npm run verify` 自己会带上 `verify-design`。
- Overview 的分工：样子看原型，一个功能自己的细节和来龙去脉看它的笔记。
- 删掉的：
  - 所有「检查：」段和句中点名的测试、走查步骤。
  - 「设定随章节变化」「大纲：写的先后和故事的先后」「页边批注」「底栏」「手机预览」整节；Colors 里手机预览只留 `phone-eye` 是什么。
  - AI 那四节只留原则：关掉以后整个不见、不删、不发；发的东西作者看得到；AI 的字作者采纳才进正文；回复时别处照常用。各种情况和提示的原话删掉。
  - 「标题栏」「侧栏」「菜单」「就地输入」只留做新功能时会碰到的约束：开关每页都在、做不了的灰着不拿掉、不设「更多」、侧栏只列东西、输入框的默认值和怎么算确定。各页的排法、四个菜单的名字、专注写作、F2 这些删掉。
  - 「标签页和保存」改名「保存」，只留保存的规则；标签页的样子只写在「标题栏」。
- 合并的：「点错了在提示条上撤销」原来在批注、待处理、设定的待确认三处各写一遍，并成「提示条」里一条。
- 加的一句：「按钮」的保存例外写上代码里那一行行尾要写 `// system order`。原来只写在它的检查里，检查段删了会丢，而 `TestButtonsAtTheRight` 认这个记号。
- `AGENTS.md` 同一次改：笔记那一节的第 2 至 4 条是笔记技能的缩写，其中「取代时归档旧篇」和技能的「能删则删，删不了再归档」不一致，并成一句，细则以技能为准；「Node 直接运行 TypeScript」管的是 `scripts/` 的全部脚本，从笔记那一节挪到「提交前」；界面那一节开头不再复述节标题。
- 开头的数值一字没动。结果是 793 行、63 KB 变成 604 行、29 KB，其中开头的数值约 12 KB。

## Alternatives considered

- **测试名单换成反指：每个测试在注释里写它守 `DESIGN.md` 的哪一节，`TestDesignMD` 查这些节名都在** — 最强的理由：改规则时 grep 节名就知道要改哪些测试，`DESIGN.md` 不占篇幅，测试改名也不会让哪里过时。没有用：要给一百四十来个测试加注释，再多一道检查；改了规则，没跟上的测试跑 `npm run verify` 本来就会报。
- **只删测试名单，功能细节留着** — 最强的理由：`DESIGN.md` 是一处能读完所有定下来的行为的地方，想知道某个功能定了什么不用翻笔记；笔记按时间写，同一个功能可能前后几篇。没有用：作者说笔记里有详细记录；每次动界面都要为别的功能的细节付上下文，而动那个功能时本来就要先读它的笔记。
- **不删，动界面时只读 `DESIGN.md` 相关的几节** — 最强的理由：一句都不丢。没有用：模型读文件多半整份读进来；规则散在各节，哪几节「相关」说不清。

## Consequences

- **收益**：
  - 每次动界面读进来的 `DESIGN.md` 少了一半多。
  - 测试改名、加减不用改 `DESIGN.md`，不会再有过时的名字。
  - 新功能不再往 `DESIGN.md` 加一节，文件不跟着功能的数目长。
- **代价与已知上限**：
  - 光看 `DESIGN.md` 看不出哪条规则有检查，要到测试和 `scripts/prototype/walk.ts` 里找。
  - 一个功能的细节分在原型和它的几篇笔记里；后来的改动常写在旧篇开头的引注里（如[正文多标签页](../feature/2026-10-13-chapter-tabs.md)），要顺着读。哪天模型因为找不到某个功能的细节做错了，再考虑给每个功能留一份现行说明。
  - 删掉的原话有几句笔记里没有，只在原型和软件里：举例（「关于 周祥 · 第87章起」「第88章：第九十一章 雪」）、窄窗口时侧栏「不收成一列图标」、AI 关着时标题栏正中只有「正文」「大纲」。

## Verification

- `go test ./desk/kit -run TestDesignMD`：八节的名字和先后、开头的数值照旧对得上。
- `npm run verify-design`：0 个错误。
- `rg "Test[A-Z]" DESIGN.md`：没有结果。
