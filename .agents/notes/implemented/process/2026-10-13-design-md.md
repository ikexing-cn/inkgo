# Agent Note: 界面规范写在 DESIGN.md

Status: implemented

> 2026-10-26 起 `DESIGN.md` 不再在规则下面写谁在查，只管一个功能的细节也不写进去，见 [DESIGN.md 只写每一处界面都要守的规则](2026-10-26-design-md-only-shared-rules.md)。

## Problem

界面要守的规则散在几处，有的只在对话里：

- 数值只写名字、按钮靠右这两条在 `AGENTS.md` 界面那节；
- 「功能操作放右上角」「搜索和新增分开」「文案不口语化」「没用的不要留」是作者前几轮说的，没有写在仓库里，新做的界面守不守看当时记不记得；
- 就地改名字该怎么表现（默认值、失焦就确定）没有人定过，原型和软件各做各的，两边都做错了。

作者 2026-10-13：「按钮应该统一右对齐，这个作为基线写到设计文档，不能每次都漂移提醒一次」，随后：「维护一个DESIGN.md作为规范基准」。第一版是自己起的中文小节，作者看过后给了格式：「https://github.com/google-labs-code/design.md 按照这个规范来」。

## Decision

- 仓库根目录的 `DESIGN.md` 是界面规范的基准，按 [DESIGN.md 格式](https://github.com/google-labs-code/design.md)（`version: alpha`）写：
  - 开头的 YAML 是数值：`colors`、`typography`、`rounded`、`spacing`、`components`。
  - 正文八节，名字和先后是格式定的：Overview、Colors、Typography、Layout、Elevation & Depth、Shapes、Components、Do's and Don'ts。节名用英文（格式的检查工具按名字认），节里写中文。
  - 原来的小节各归其位：「怎么维护」「数值只写名字」在 Overview，「位置」在 Layout，「按钮」「菜单」「就地输入」「标签页和保存」在 Components，「文案」「不留没用的」在 Do's and Don'ts。
- 数值在三处，同名同值：`DESIGN.md` 开头、`desk/kit/tokens.css`（原型直接用）、`desk/kit/theme.go`（代码用）。
  - 名字照 `desk/kit/tokens.css` 的，不改成格式推荐的那一套（`surface`、`on-surface`……）：`colors.ink` 是 `--ink`，`typography.body` 的字号是 `--fs-body`，`rounded.control` 是 `--r-control`，`spacing` 是 `--space` 那一排数。
  - 格式只有一套颜色，深色那一套写成 `<名字>-dark`；控件也一样，有颜色的控件各有一份 `-dark`。
  - `primary` 是格式要有的名字，写成 `{colors.ink}`。
  - 控件高度、图标大小在格式里没有自己的组，写在 `components` 的 `height`、`size` 里。
  - 阴影、遮罩、半透明的几级、行距的几级、禁用透明度没有位置放，值仍只在 `desk/kit/tokens.css`，`DESIGN.md` 里写名字和用处。
- 两个检查：
  - `go test ./desk/kit` 的 `TestDesignMD`：开头的数值和 `desk/kit/tokens.css` 一致（两套颜色、字号、圆角、间距），`components` 里的高度和尺寸都在 `--h-*`、`--icon-*` 上并且每一级都有控件在用，内边距在间距刻度上，有颜色的控件都有 `-dark` 那一份，八节的名字和先后对。
  - `npm run verify-design`：格式自带的检查工具（`@google/design.md@0.4.0`，经 `npx` 取，不进依赖），查引用断没断、有没有没被用到的颜色、对比度。没有错误才算过。
    - 2026-10-13 起 `npm run verify` 在 `DESIGN.md` 改了还没提交时带上它，见[全套检查从四分半到半分钟](2026-10-13-fast-checks.md)。
- 分工不变：
  - `DESIGN.md` 写每一处界面都要守的规则；
  - `prototype/` 是每个界面具体的样子；
  - `AGENTS.md` 写做界面的流程（先改原型再写代码、怎么验证），界面那节开头指向 `DESIGN.md`。`DESIGN.md` 自己怎么改只写在它的「怎么维护」，`AGENTS.md` 不复述，见[每条界面规则只写在一处](2026-10-15-each-rule-said-once.md)。
- 原型和 `DESIGN.md` 对不上，以 `DESIGN.md` 为准，改原型。
- 只写作者定下来的；还在原型里等作者看的方案留在 `.agents/notes/proposed/`。我定的而作者没说过的例外标「待作者确认」。
- 作者提了一条不只管一处的要求，先写进 `DESIGN.md`，再改原型和代码，同一次提交；能自动查的加检查，并在规则下面写明谁在查。

## Alternatives considered

- **留着自己起的中文小节，不用外面的格式** — 小节跟着作者说过的话分（按钮、就地输入、文案），找起来顺；数值只在 `desk/kit/tokens.css` 一处，不会对不上。没有用：作者点名要这个格式；它有现成的检查工具，别的工具和别的 AI 也按它读。
- **`DESIGN.md` 开头的数值当唯一的一份，`desk/kit/tokens.css` 由它生成** — 少一处要对的。没有用：阴影、半透明、行距这些格式里放不下，`desk/kit/tokens.css` 还得手写一半；原型和代码都已经直接读它，核对一下比加一步生成简单。
- **颜色改用格式推荐的名字（`surface`、`on-surface`、`error`）** — 别的工具一看就懂。没有用：原型和代码里几百处都写着现在的名字，改名只换来叫法，两边还多一张对照表。
- **深色那一套不写进去** — 格式只有一套颜色，写一套最干净。没有用：深色的值就没有地方核对了，检查工具也不会去量深色的对比度。
- **`components` 不写，只写前四组** — 开头短一半，检查工具也不会报「没被用到的颜色」。没有用：控件高度和图标大小就没有位置放；对比度是按控件的底色和字来量的，不写就量不了。
- **把 `verify-design` 列进每次提交前必过的三条** — 不会忘。没有用：它要联网取工具，离线就提交不了；数值对不对已经由 `go test ./desk` 每次都查，它只在改了 `DESIGN.md` 时才有新东西可查。
- **接着写在 `AGENTS.md` 里** — 少一份文件，进仓库干活的都会读到它。没有用：`AGENTS.md` 是流程，规则一多就把流程埋了；作者点名要单独一份。
- **不写文件，只靠原型当基准** — 原型点得出来，比文字准。没有用：原型只能说「这个界面是这样」，说不了「以后每个界面都要这样」；按钮靠右在原型里就漂过。

## Consequences

- **收益**：
  - 作者说过的通用要求有一个固定的地方，下次不用再说。
  - 规则旁边写着谁在查，哪条只靠人看一目了然。
  - 数值和控件的搭配第一次写在一处，检查工具量出了五对不到 4.5:1 的对比度（提示的字浅色、深色各一对，警告条的字和主按钮，成功的字），记在 Colors 一节，改不改待作者定。
- **代价与已知上限**：
  - 数值多了一处要一起改；漏了由 `TestDesignMD` 报。
  - `DESIGN.md` 开头有三百多行：深色那一套和每个控件的 `-dark` 占了一半。
  - `components` 里的搭配（哪个底色配哪个字）是照原型的样式抄的，没有检查核对它和原型一致。
  - 字体没有写进数值：原型用系统的中文黑体，软件用工具包默认的字体，规范只定字号、字重和行距；行距只有 `read`、`paper` 两级和字号是固定搭配，写进了数值。
  - 格式还是 alpha，检查工具钉在 0.4.0；格式变了要跟着改。
  - 「位置」「文案」「不留没用的」几条没有检查，靠写的时候照着做、审查时对着看。

## Verification

- `go test ./desk -run TestDesignMD`：通过；改坏一处（一个颜色、一个深色的颜色、字号、行距、圆角、少一级间距、不在刻度上的高度和内边距、对不上的 `-dark`、节的先后、少一节）各试过一遍，十一种都报。
- `npm run verify-design`：0 个错误，5 个对比度的警告，没有「没被用到的颜色」。
