# Agent Note: 一排按钮靠右，写成规则并且两边都查

Status: implemented

## Problem

按钮在一排里靠哪边，没有写下来的规则，各处是各处写的时候定的：

- 对话框底下的按钮靠右；备份浮层里的「重试」「更换位置」「今日不再提醒」、提示条里的「复制详情」、设置里的「打开配置文件」「重新加载配置」靠左。
- 作者 2026-10-13 截了备份浮层和两条提示：「按钮应该统一右对齐，这个作为基线写到设计文档，不能每次都漂移提醒一次」。之前已经说过一次主按钮放右边。

说过的事没有落成规则和检查，下一次新写的一排按钮还是会靠左。

## Decision

- 规则写进 `DESIGN.md` 的「按钮」一节（当天先是 `AGENTS.md` 界面那节的一条，同一天搬进新立的 `DESIGN.md`，见[界面规范](2026-10-13-design-md.md)）：一排按钮靠右，主按钮在最右，次要的在它左边，文字样式的操作在更左。三种不这样：
  - 空页正中那一段的按钮跟着那段话居中，主按钮仍在右；
  - 跟在一句话后面的行内链接（「查看原文」「更改」）跟着那句话；
  - 不做决定的那一个（「稍后再说」）可以单独留在最左，和其余的分开（现有两处：检查页一条结果的底下、第一次备份的对话框）。
- 原型的检查在走查里（`scripts/prototype/walk.ts` 的 `LOOSE`）：每点一下，窗口里凡是装着按钮的一行（`.btn`、`.solid`、`.ghost`，或者整行都是能点的字）都量一遍，最后一个离这一行右边不能有空，从第一个按钮起后面的要一个挨一个（按钮右边不能隔着一段空），主按钮后面不能再有按钮。找到的攒起来，走完一起报，一次看全。
- 代码的检查是 `desk/theme_test.go` 的 `TestButtonsAtTheRight`，读界面代码：一个 `ui.Row(c)` 里第一个画出来的是按钮（`a.pal.primary`、`a.pal.secondary`、`a.textLink`），这一行就要写 `Justify(ui.End)`；按钮不能在 `ui.Spacer(c)` 的左边，只有单独一个 `a.textLink`（「稍后再说」）可以；`primary` 后面不能再有 `secondary`、`textLink`。
- 这次改过来的：
  - 备份浮层：出错时是「今日不再提醒」「更换位置」「重试」，平时是「备份设置…」「立即备份」，都靠右（原型 `backupPop`，代码 `desk/backup.go`）。
  - 提示条里能点的几个靠右，最要紧的那个（「重试」「取消」）在最右，「复制详情」在它左边（原型 `toasts`，代码 `toastActions`）。
  - 设置里「打开配置文件」「重新加载配置」靠右。
  - 设置里一个服务的表单：原来「获取可用模型」「清除已保存 key」在左、「保存提供商」在右，现在三个都靠右，依次是「清除已保存 key」「获取可用模型」「保存提供商」。
  - 没有章节的空页：「新建文件夹」「新建第一章」，主按钮换到右边。

## Alternatives considered

- **只写规则，不加检查** — 最省事，规则一句话就说清了。没有用：这条之前就口头说过，还是漂了；作者要的正是「不能每次都提醒一次」。
- **给代码加一个专门画按钮行的函数，所有地方都用它** — 靠右是函数管的，不用查。没有用：按钮行有带输入框的、带一句说明的、带「稍后再说」的，一个函数装不下，装不下的地方照样自己写一排，还是要查。
- **代码也像原型那样，画出来以后量位置** — 量的是真的位置，比读代码准。没有用：要把每个对话框、浮层、提示都在测试里摆出来一遍才量得全，现在的测试没有这样一张清单；读代码的检查不用摆，新加的一排自动在里面。备份浮层和提示条这两处另有量位置的测试（`TestBackupFails`、`TestToastOverTheSettings`）。
- **「稍后再说」也一律挪到右边** — 规则没有例外，最好记。没有用：它不是这一排里的一个选择，而是「先不选」；和「无需修改」「修改设定」「修改正文」排在一起会被当成第四种处理办法。这一条如果作者要，去掉例外和代码里的两个 `ui.Spacer(c)` 就是。

## Consequences

- **收益**：
  - 新写的一排按钮靠左，原型这边走查报、代码这边 `go test ./desk` 报，不用等作者看见。
  - 试过：把提示条那一行改回靠左，走查报出「toast-acts is not at the right: 复制详情」；把 `desk/backup.go`、`desk/write.go` 换回改之前的，`TestButtonsAtTheRight` 报出备份浮层两行和空页那一行；服务表单那一行是收紧检查以后两边各自报出来的。
- **代价与已知上限**：
  - 代码的检查读的是写法，不是画出来的样子：
    - 不用 `a.pal.primary`、`a.pal.secondary`、`a.textLink` 画的按钮它看不见：提示条里的是 `ui.ButtonBase`；`ghost` 既画行内链接也画按钮，没有算进去。
    - 一行里先画了一句话、按钮跟在后面，它不管；这一行如果没有写 `FillWidth` 之类把按钮推到右边，它发现不了。
    - 空页那两行写了 `Justify(ui.End)` 只是为了过检查：那一行和按钮一样宽，靠哪边看不出来。
  - 原型的检查只看走查走到的地方；没有走到的浮层不查。

## Verification

- `go test ./desk`：`TestButtonsAtTheRight`、`TestToastOverTheSettings`（「复制详情」「打开设置」在提示的字下面靠右，后者在右）、`TestBackupFails`（「今日不再提醒」在「重试」左边，都不贴着浮层左边）。
- `npm run verify-prototype`：按钮行没有不靠右的。
