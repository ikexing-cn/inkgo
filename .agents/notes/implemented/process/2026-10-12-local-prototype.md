# Agent Note: 界面以仓库里能点的原型为准，纯 HTML/JS，不靠 Claude Design

Status: implemented

## Problem

设计稿（Design artifact）的画板是静止的，点不了。能点的原型做过两版（第 47、48 版），放在 artifact 里的 `Prototype.dc.html`：它要 Design 类型的运行库和同目录的组件文件才能开，只能在画布上点「播放」；改一处要先把最新版拉到本地、改、再发布。作者 2026-10-12 的要求是「不用 claude design，放在本地维护，随时修改」。

本地那版做出来以后，作者同一天定下：「以后以本地的为主，先把本地和原型的内容同步」「artifact 的不再理会了，留着就行」。这样界面的基准从 artifact 换成了仓库里的原型，原型也要先补到和软件一样全。

## Decision

- 界面设计以 `prototype/` 为准（`AGENTS.md` 界面那节）：
  - 新的界面功能照原型来；原型里没有的，先在原型里做出来给作者看，确认后再写代码。
  - artifact 只作存档，不更新，也不拿它对照。它里面画过、软件还没做的几页（全书规划、导入稿件、恢复备份、「写到相关人物时提醒」）没有搬进原型，要做的时候再在原型里做。
- 原型没有库，不用构建，双击 `index.html` 就开。一份样式，七份脚本：
  - `index.html`：样式。链的是 `../desk/tokens.css`，颜色、字号、间距只有那一份。
  - `book.js`：那本假书（卷、章、设定、修改记录、伏笔、讨论、AI 的固定回复）。
  - `base.js`：状态、重画、各处都用的小零件。
  - `write.js`：侧栏、工具栏、正文。
  - `pane.js`：右栏的设定、讨论、伏笔。
  - `pages.js`：讨论、检查、作品分类、书架四页。
  - `dialogs.js`：对话框和备份。
  - `app.js`：把窗口拼起来，和全局的按键、拖动。
- 脚本都是普通 `<script>`，按上面的顺序加载，不用 ES module：从磁盘直接打开（`file://`）时浏览器会拦模块。各文件最外层的名字是共用的，所以不起和浏览器自带的同名的（`top`、`open`、`name`）。
- 画法：只有一份状态 `S`。`set()` 改完状态，把整个窗口重新拼成一段 HTML，再由 `children()`、`patch()`（四十来行）对着页面上现有的节点，只改不一样的属性和字。这样输入框不会被重建（光标和拼音选字不断），正文里选中的字也不受打扰。有 `id` 或 `data-k` 的元素按名字认，别的按顺序对。
- 事件都挂在根上：点、打字、按键、右键、松开鼠标，另有拖章节的几个和拖右栏宽度的一个。元素上只留 `data-click="号码"`，号码对着这一遍画的时候登记的函数。
- 样式都写成类。只有跟着选中的字走的浮层（右键菜单、记伏笔、选回收哪条）和拖出来的右栏宽度在行内写位置和尺寸。原型和代码一样守 `AGENTS.md` 界面那节的第 4 条。
- 软件里有的界面，原型都照着做一遍，文案一字不差地用软件的。范围是软件现在的全部页面：正文（卷当一页开、章纲、摘要、查找替换、专注、快照、起草、改写、续写、导出）、右栏三个标签、讨论、检查、作品分类、书架、设置、备份、回收站、提示。
- 平时碰不到的情况（稿子在软件外面被改了或找不到了、检查或摘要没成功、备份文件夹找不到或不让写、设定没整理成功）放在窗口上面的「少见的情况」菜单里，点一下就摆出来。这个菜单和旁边的「重新开始」只属于原型，不是软件的界面。
- `npm run verify-prototype` 做两件事，改了 `prototype/` 就跑：
  - 设计规则（`scripts/design/check.ts`、`rules.ts`）：`index.html` 和每份脚本对着 `desk/tokens.css` 查，样式表里的每条规则也按控件高度查。
  - 走查。`scripts/prototype/browser.ts` 用本机的 Edge 或 Chrome 无头打开 `index.html`（走 `file://`，和双击一样），经 DevTools 协议真的按鼠标、敲键盘；`walk.ts` 把 76 条流程点一遍，每条结束时还要查窗口里没有东西伸出去、页面没有报错。只用 Node 自带的 `WebSocket` 和 `fetch`。`SHOT=<目录>` 会存下每一步的截图。
- 它不进提交前的三道检查：要本机有浏览器，而且只有原型变了才有意义。
- 窗口固定 1266×780；浮层的位置从页面上量窗口、侧栏、右栏的宽，不另记数字。

## Alternatives considered

- **留在 Claude Design 里** — 原型和静止的画板共用同一套组件文件（侧栏、工具栏、正文、右栏标签），组件改了原型自动跟着变，不会两边对不上；作者在一张画布上看得到全部。不用：作者要的就是本地、随时改；那边每改一次都要拉取再发布，断网打不开，逻辑只能写成它的模板。
- **artifact 仍是基准，原型只是它能点的一份副本** — 画板把一个页面的各种状态并排摆着，一眼看全；原型一次只看得到一个状态，要点过去。不用：两份都要跟着改，对不上时还得先问以哪边为准；作者已经定了以本地为主。看不全的那部分由「少见的情况」菜单和走查的截图补上。
- **把 Design 的运行库和页面打成一个 HTML** — 几乎不用重写，和 artifact 那版一字不差。不用：运行库是 188 KB 的压缩代码，放进仓库看不懂也改不了；页面仍是 Design 的模板格式，「不用 Claude Design」只做到一半。
- **引一个小框架（Preact、Alpine 之类）** — 省掉自己写的对比更新，写法很多人认识。不用：从 CDN 引，断网就打不开；把副本放进仓库，又是一份别人的代码。这一页要的只是「整个重画，只改不一样的地方」，四十行够了。
- **每次直接整页重写，不做对比** — 最简单，一行 `innerHTML`。不用：输入框每敲一个字就被换掉，光标和拼音选字会断；正文里选中的字每次都丢，而右键菜单靠的就是它。
- **脚本留在一个文件里** — 不用管加载顺序，也不会有两个文件起了同一个名字。不用：补全以后有两千多行，找一处要翻很久；按窗口的几块分开，改哪一块就开哪一份。

## Consequences

- **收益**：
  - 双击就开，改文件就是改原型；基准只有一份，和代码在同一个仓库、同一次提交里改。
  - 每次改完一条命令验证，不用人盯着点。试过：把「记下」改成不存伏笔，走查停在那一步；把标题字号写成数字、把留白改成刻度外的数，规则检查都报出来。
  - 出错和少见的状态以前只在 artifact 的画板上看得到，现在点一下就在真的窗口里摆出来。
- **代价与已知上限**：
  - 软件改了界面，原型不会自己跟着变：没有检查能发现两边的文案或布局对不上，靠先改原型、再改代码这个顺序管着。
  - 动作变了，`scripts/prototype/walk.ts` 里的步骤要跟着改；走查按字找东西点，改了文案也要改它。走一遍要三分钟左右。
  - 各脚本最外层的名字共用：两个文件起了同名的 `const` 会报错，同名的 `function` 不报错，后加载的悄悄顶掉前面的。
  - 样式链的是 `../desk/tokens.css`，单把 `prototype/` 文件夹拷给别人打不开样子，要连 `desk/tokens.css` 一起。
  - 正文不能打字（`Ctrl+J` 当作写了一句），AI 只回固定的几句，内容是编的；作者 2026-10-12 同意这三条。
  - 做不出来或没有做的：
    - 系统的窗口（选文件夹、存文件）不会打开，只提示一句；「添加已有作品」当作每次选的都是同一个文件夹。
    - `Ctrl+N`、`Ctrl+PgUp/PgDn` 被浏览器占着。
    - 卷里不能再套卷；书架上只有第一本书有内容。
    - 出错提示上的「×N」（同一条连着出了几次）、切换作品时找不到文件夹、作品清单读不了这几种没有做。
  - 原型和软件眼下有几处样子不同，等作者定以哪边为准：原型侧栏顶上多一个收起侧栏的图标；第一次备份的对话框里「什么时候备份」原型是三个勾选框，软件是下拉；章节树里软件的卷有箭头和文件夹图标，原型只有箭头。
