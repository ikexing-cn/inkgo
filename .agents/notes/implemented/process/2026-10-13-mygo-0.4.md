# Agent Note: 依赖升到最新：mygo v0.4.8、goai v0.10.8；控件的 key 写在 `c.Key` 上

Status: implemented

## Problem

作者 2026-10-13：「更新下依赖吧，看看有什么更新的」。查下来（`go list -m -u all`）`go.mod` 里有三个落后：

- `github.com/egoist/mygo` v0.3.7 → v0.4.8。界面工具包，跨了一个小版本。
- `github.com/zendev-sh/goai` v0.10.7 → v0.10.8。模型那一层。
- `github.com/godbus/dbus/v5` v5.2.2 → v5.2.3。间接依赖，只在 Linux 上存密钥时用到。

其余的都已经是最新：`goldmark`、`go-keyring`、`go.yaml.in/yaml/v3`、`golang.org/x/*`、`go-text/typesetting`、`purego`，还有检查 `DESIGN.md` 用的 `@google/design.md@0.4.0`。`go list` 另外列出的 `cloud.google.com/go/compute/metadata`、`stretchr/objx`、`golang.org/x/oauth2` 不在我们的 `go.mod` 里，也不会编进软件，不用管。

mygo v0.4 自带一份迁移说明（模块里的 `docs/ui/migration.md`）和一个改源码的工具（`mygo migrate-ui`）。我们的代码不改也能编译、测试全过，但说明里有一条现在的写法不符合：有状态的控件（按钮、滚动区、输入框）的 key 要在造它之前给，写成 `ui.ButtonBase(c.Key(k))`；`ui.ButtonBase(c).Key(k)` 是造完了才给，状态已经按位置读过了。

## Decision

- 三个都升到最新，`go mod tidy`。
- 跑了 `go run github.com/egoist/mygo/cmd/mygo migrate-ui -write desk`（只对 `desk`；`editor`、`cmd` 它没有要改的），35 处 `X(c).Key(k)` 改成 `X(c.Key(k))`，分在 15 个文件里。只在这几个目录上跑，没有对整个仓库跑：仓库里有作者自己的文件夹，工具会把里面的 `.go` 也改掉。
- 工具改不了的 4 处手改：`a.paneRow(c, …).Key(id)` 是在辅助函数造完一整行以后才给 key，改成 `a.paneRow(c.Key(id), …)`，`paneRow` 里第一个造的就是那个按钮，key 归它。
- 以后的写法：
  - 按钮、滚动区、输入框这类自己记着状态的控件：`ui.Scroll(c.Key("名字"))`、`ui.ButtonBase(c.Key(id))`。
  - 只是装东西的 `ui.Row`、`ui.Column`：`.Key(k)` 写在 `.Children(…)` 前面仍然可以（`settings.go` 里服务的卡片是这样）。
  - 自己写的、返回一个控件的辅助函数：调用的地方用 `c.Key(k)` 把 key 递进去，不在返回值上 `.Key`。
- 编辑器不再留着一帧的 `*ui.Context`（工具提示的那一条）：原来留着只为了量出新尺寸后叫界面重画，改用已经在用的 `ui.Services`（`e.sv.Invalidate()`），`Editor` 里的 `c` 去掉了。
- `desk/theme_test.go` 的 `TestButtonsAnswerThePointer` 原来只认 `ui.ButtonBase(c)` 这几个字，迁移以后带 key 的 10 个按钮它就不看了，而且不会报错。改成两种写法都认，并且加了一条：读到的按钮少于 40 个就失败（现在是 56 个），写法再变的时候它会叫出来。

## Alternatives considered

- **只升版本，不跑迁移工具** — 不改也能编译，测试全过，截图也一样，动的文件最少。没有选：迁移说明里写明了带状态的控件 key 要先给；现在看不出差别，是因为这些控件的位置恰好没有在两帧之间换过，哪天列表里插了一行，滚动位置、悬停就会串到隔壁那个上，那时很难想到是这里。
- **mygo 先不动，只升另外两个** — 界面工具包变化大，留在 v0.3.7 最稳。没有选：差得越远越难升，[界面缩放](../../proposed/feature/2026-10-09-ui-zoom.md)那一篇等的就是上游；而且这一次实际要改的很少。
- **对整个仓库跑迁移工具（`migrate-ui -write .`）** — 一条命令，不会漏目录。没有选：它会走进作者自己的文件夹改里面的文件。

## Consequences

**收益**

- 依赖都在最新版本上。
- 带状态的控件按名字认，不按位置认：列表增删以后，滚到哪、悬停、按下不会串到别的控件上。
- goai v0.10.8 修的是 OpenAI「responses」协议下接着上一次回答往下说的情况：服务说了不存回答时，不再带着上一次的回答编号去问（带了会报错）。我们的 OpenAI 服务走的就是这个协议。

**代价与已知上限**

- 之前记下的几件工具包做不到的事，v0.4.8 里还是没有：鼠标中键、整个界面的缩放、「窗口到了前面」的通知、把输入框里的字全选。
- v0.4 新加的东西（过渡和弹簧动画、变形、内嵌网页、不看键盘布局的快捷键、`OnPaste`、`Dismissed`）这一次都没有用。
- 升级前后的截图逐个像素比过：标签页九张完全一样；其余的不同都是时间和临时目录的路径，除了一处——讨论页「思考过程」那一块高了 2 个像素，没有查是哪一条改动带来的。
- 没有在真的窗口里跑过，只跑了测试和渲染的截图。
- 升级时只跑了 `mygo migrate-ui`，没有跑 v0.4 另带的检查 `mygo vet`，这是漏掉的。2026-10-13 审查代码时补跑（`go run github.com/egoist/mygo/cmd/mygo vet desk`，一次一个目录）：`desk` 10 处、`editor` 1 处。10 处是后台任务做完以后用那一帧的 `*ui.Context` 叫界面重画（`c.Invalidate()`），其中一处在编辑器的预测里（`editor/view.go`）；1 处是 `desk/menu.go` 的 `menu` 里留着 `*ui.Context`。当时不出错：`Context.Invalidate` 的说明写的是可以在任何线上叫。但 `mygo vet` 要的写法是 `c.Services().Invalidate()`。
- 2026-10-14 改了那 10 处（见[审查后的一批修正](../bug-fix/2026-10-14-review-fixes.md)）：起头那一帧取 `sv := c.Services()`，后台做完叫 `sv.Invalidate()`。`desk/menu.go` 那 1 处留着，是知道的例外：菜单的构建器在一次调用里造出来、画完就丢，不跨帧；要消掉它得让七十多处 `m.Item(…)` 每行多传两遍 `c`。`mygo vet` 没有「这一行不查」的写法，所以由 `scripts/verify-ui.ts` 来跑它（`npm run verify-ui`，也在 `npm run verify` 里）：`desk`、`editor`、`cmd/poc` 三个包同时跑，只放行 `desk/menu.go` 的这一种报告，别的一处都不让过；这一处哪天不报了，脚本会要求把放行去掉。工具按 `go.mod` 里 mygo 的版本建一次，留在 `.tmp/mygo-<版本>` 里（不进仓库）：`go run` 每次都要重新链接，三个包 20 秒；建好以后一次约 3 秒。mygo 换了版本会重建，旧的那个删掉。
- mygo 还在 v0.x，下一个小版本可能再改写法。

## Verification

- `npm run verify` 五项全绿。
- `go run github.com/egoist/mygo/cmd/mygo migrate-ui desk`（不带 `-write`）不再列出要改的文件；对 `editor`、`cmd` 也是。它只剩一句提醒：`desk/menu.go` 的 `menu` 里留着 `*ui.Context`。那是画菜单时当场造、画完就不用的东西，不跨帧，不用改。
- 升级前（v0.3.7）和升级后渲染的截图用脚本逐像素比：`TestShotTabs` 九张、`TestShotCheck`、`TestShotBackup`、`cmd/poc` 的 `TestLayout`。
