# Agent Note: 依赖升到最新：mygo v0.4.8、goai v0.10.8；控件的 key 写在 `c.Key` 上

Status: implemented

## Problem

作者 2026-10-13：「更新下依赖吧，看看有什么更新的」。查下来（`go list -m -u all`）`go.mod` 里有三个落后：

- `github.com/egoist/mygo` v0.3.7 → v0.4.8。界面工具包，跨了一个小版本。
- `github.com/zendev-sh/goai` v0.10.7 → v0.10.8。模型那一层。
- `github.com/godbus/dbus/v5` v5.2.2 → v5.2.3。间接依赖，只在 Linux 上存密钥时用到。

其余的都已经是最新：`goldmark`、`go-keyring`、`go.yaml.in/yaml/v3`、`golang.org/x/*`、`go-text/typesetting`、`purego`，还有检查 `DESIGN.md` 用的 `@google/design.md@0.4.0`。`go list` 另外列出的 `cloud.google.com/go/compute/metadata`、`stretchr/objx`、`golang.org/x/oauth2` 不在我们的 `go.mod` 里，也不会编进软件，不用管。

mygo v0.4 自带一份迁移说明（模块里的 `docs/ui/migration.md`）和一个改源码的工具（`mygo migrate-ui`）。我们的代码不改也能编译、测试全过，但说明里有一条现在的写法不符合：有状态的控件（按钮、滚动区、输入框）的 key 要在造它之前给，写成 `ui.ButtonBase(c.Key(k))`；`ui.ButtonBase(c).Key(k)` 是造完了才给，状态已经按位置读过了。

## Decision

- 三个都升到最新，`go mod tidy`。
- 跑了 `go run github.com/egoist/mygo/cmd/mygo migrate-ui -write desk`（只对 `desk`；`editor`、`cmd` 它没有要改的），35 处 `X(c).Key(k)` 改成 `X(c.Key(k))`，分在 15 个文件里。只在这几个目录上跑，没有对整个仓库跑：仓库里有作者自己的文件夹，工具会把里面的 `.go` 也改掉。
- 工具改不了的 4 处手改：`a.paneRow(c, …).Key(id)` 是在辅助函数造完一整行以后才给 key，改成 `a.paneRow(c.Key(id), …)`，`paneRow` 里第一个造的就是那个按钮，key 归它。
- 以后的写法：
  - 按钮、滚动区、输入框这类自己记着状态的控件：`ui.Scroll(c.Key("名字"))`、`ui.ButtonBase(c.Key(id))`。
  - 只是装东西的 `ui.Row`、`ui.Column`：`.Key(k)` 写在 `.Children(…)` 前面仍然可以（`settings.go` 里服务的卡片是这样）。
  - 自己写的、返回一个控件的辅助函数：调用的地方用 `c.Key(k)` 把 key 递进去，不在返回值上 `.Key`。
- 编辑器不再留着一帧的 `*ui.Context`（工具提示的那一条）：原来留着只为了量出新尺寸后叫界面重画，改用已经在用的 `ui.Services`（`e.sv.Invalidate()`），`Editor` 里的 `c` 去掉了。
- `desk/kit/theme_test.go` 的 `TestButtonsAnswerThePointer` 原来只认 `ui.ButtonBase(c)` 这几个字，迁移以后带 key 的 10 个按钮它就不看了，而且不会报错。改成两种写法都认，并且加了一条：读到的按钮少于 40 个就失败（现在是 56 个），写法再变的时候它会叫出来。

## Alternatives considered

- **只升版本，不跑迁移工具** — 不改也能编译，测试全过，截图也一样，动的文件最少。没有选：迁移说明里写明了带状态的控件 key 要先给；现在看不出差别，是因为这些控件的位置恰好没有在两帧之间换过，哪天列表里插了一行，滚动位置、悬停就会串到隔壁那个上，那时很难想到是这里。
- **mygo 先不动，只升另外两个** — 界面工具包变化大，留在 v0.3.7 最稳。没有选：差得越远越难升，[界面缩放](../feature/2026-10-09-ui-zoom.md)那一篇等的就是上游；而且这一次实际要改的很少。
- **对整个仓库跑迁移工具（`migrate-ui -write .`）** — 一条命令，不会漏目录。没有选：它会走进作者自己的文件夹改里面的文件。

## Consequences

**收益**

- 依赖都在最新版本上。
- 带状态的控件按名字认，不按位置认：列表增删以后，滚到哪、悬停、按下不会串到别的控件上。
- goai v0.10.8 修的是 OpenAI「responses」协议下接着上一次回答往下说的情况：服务说了不存回答时，不再带着上一次的回答编号去问（带了会报错）。我们的 OpenAI 服务走的就是这个协议。

**代价与已知上限**

- 之前记下的几件工具包做不到的事，v0.4.8 里还是没有：鼠标中键、整个界面的缩放、「窗口到了前面」的通知、把输入框里的字全选。
- v0.4 新加的东西（过渡和弹簧动画、变形、内嵌网页、不看键盘布局的快捷键、`OnPaste`、`Dismissed`）这一次都没有用。
- 升级前后的截图逐个像素比过：标签页九张完全一样；其余的不同都是时间和临时目录的路径，除了一处——讨论页「思考过程」那一块高了 2 个像素，没有查是哪一条改动带来的。
- 没有在真的窗口里跑过，只跑了测试和渲染的截图。
- `scripts/verify-ui.ts` 用 `mygo vet` 检查 `desk`、`desk/kit`、`editor`、`cmd/inkgo`，不放行任何报告。后台任务取起头那一帧的 `c.Services()`，完成后叫 `Services.Invalidate()`。
- `desk/kit/menu.go` 的 `Menu` 只存行数据和动作，不存 `*ui.Context` 或 `ui.Element`。界面工具按 `go.mod` 里的 mygo 版本建一次，留在 `.tmp/mygo-<版本>`；换版本时重建。
- 同一天后来，那 1 处也没有了：菜单的构建器改成只记下各行、不存 `Context`，由拿着 `c` 的一个函数来画（见[自己画菜单那篇](../feature/2026-10-12-own-menus.md)）。`mygo vet` 对三个包都没有报告，`scripts/verify-ui.ts` 里的放行表删掉了：现在一处都不放行。上面那一条里说的放行，只存在了半天。
- mygo 还在 v0.x，下一个小版本可能再改写法。
- 2026-10-19 升到 v0.5.5（purego、dbus 跟着升了小版本）。`mygo migrate-ui` 只给 `desk` 四个文件排了版（gofmt），没有要改的写法；编译、`npm run verify` 都过。有一处要知道：测试器（`ui.Tester`）现在有自己的钟，提示条的倒计时、展开收起的动画都按它走，真实时间过去它不动，要 `tt.Advance` 拨。`TestNoticesFade` 原来把时长改成 50 毫秒、再等真实时间，改成了拨钟；`cmd/inkgo` 的布局截图在每张之前拨一秒，不然「思考过程」停在刚点开、还没展开的那一帧。和升级前逐像素比过 `TestLayout` 和 `desk` 的 `TestShot*`：剩下的不同是时间、临时目录、转圈图标和光标闪到哪一帧、提示条底下计时线的长短。界面缩放、鼠标中键这次也还是没有。v0.5 新带的 `ui/markdown` 和 `ui/richtext` 另说。
- 2026-10-24 升到 v0.6.3（多了间接依赖 `golang.org/x/net`）。`mygo migrate-ui` 对 `desk`、`editor`、`cmd` 下的九个包都没有列出要改的文件；编译、`npm run verify` 都过。用 GPU 画的帧改成等交换链有空位再画，不在主线程上等交帧：作者机器上一帧在主线程上从 32 ms 降到 2–3 ms（见[看完重组那篇](../bug-fix/2026-10-24-after-reviewing-the-reorganization.md)）。和升级前逐像素比过 `TestLayout` 和 `desk` 的 `TestShot*`：118 张里 98 张一样，不同的 20 张是临时目录的路径、转圈图标转到哪里、测试里最后一下点击以后指针悬停在哪个控件上（滚动条悬停时才出现，所以有两张一张有滚动条一张没有），界面本身的样子没有变。不用 GPU 时窗口发白，这一版还是一样，见[白窗口那篇](../bug-fix/2026-10-24-no-gpu-white-window.md)。
- 2026-10-27 升到 v0.7.1（goai 到 v0.10.9，间接依赖 `golang.org/x/net` 到 v0.61.0）。
  - mygo 从 v0.6.4 起要 Go 1.27.3，`go.mod` 的 `go` 跟着从 1.27.1 升到 1.27.3。本机装的还是 1.27.1，`go` 命令自己下一份 1.27.3 来用（`GOTOOLCHAIN=auto`）；换了编译器，升完头一次编译、头一次 `npm run verify` 都要从头编，那一次 `go test` 用了 186 秒。
  - 代码一行没改：`ui` 的导出接口只加不减，迁移说明没变，`mygo migrate-ui` 对九个包都没有列出要改的文件。v0.7.0 写的四条不兼容（macOS 子窗口、中日韩应用名的 slug、安装包的文件名、`audio.Player.Position`）我们都没用到。
  - 修了我们报的两处：不用 GPU 时 Windows 窗口发白（[mygo#690](https://github.com/egoist/mygo/issues/690)，v0.6.4 修），平移过的裁剪区每帧在 CPU 上重画遮罩、收起侧栏一帧 40–55 ms（[mygo#794](https://github.com/egoist/mygo/issues/794)，v0.7.0 修）。作者当天在真窗口里看过：「确认可行了」。见[白窗口那篇](../bug-fix/2026-10-24-no-gpu-white-window.md)和[页边批注那篇](../feature/2026-10-24-margin-notes.md)。
  - goai 这一版把 OpenAI 报的写缓存单独记进 `CacheWriteTokens`，从 `InputTokens` 里扣掉。`model` 的 `usage` 本来就把三项加回 `Input`，价目表里 OpenAI 的写缓存和输入同价，算出来的输入和花费不变。
  - 和升级前逐像素比过 `TestLayout` 和 `desk` 的 `TestShot*`：137 张里 107 张一样。不同的 30 张里，26 张是时间、临时目录、转圈图标转到哪里；另 4 张差 1–3 级（满 255），是裁剪区的边改在着色器里切：挪到半途的批注卡片底边、收起右栏半途的几条短横线、右栏设定卡片的底色。眼睛看不出。
  - v0.7.0 新带的界面缩放（`Context.SetZoom`，见[界面缩放](../feature/2026-10-09-ui-zoom.md)）、`Element.Hidden`、`Element.Cache`、`Painter.AnimationFrameRate` 和 v0.7.1 的 `Font.LineHeight` 这次都没用。
