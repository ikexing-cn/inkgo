# Agent Note: 测试用的书写成文本，由 cmd/sample 生成作品文件夹

Status: implemented

## Problem

一致性检查、伏笔、摘要、起草这些功能要在一本有内容的书上才试得出来。之前每次都是测试里临时拼几句正文，或者手工在软件里敲，既不像真书，也没法让两个人在同一份内容上复现问题。

## Decision

- `cmd/sample/books/` 里一本书一个 `.txt`：书名、题材、设定（正文 / 等你决定 / 已删除三处）、卷和卷纲、章和章纲、正文，伏笔用 `{伏:备注|原文}`、`{收:备注|原文}`、`{弃:备注|原文}` 写在正文里。格式说明在 `cmd/sample/main.go` 开头。
- `go run ./cmd/sample <目录>` 用 `workspace` 的公开接口（`Create`、`Revise`、`NewChapter`、`WriteOutline`、`WriteChapter`）把每本书写成一个作品文件夹；目录里已有同名非空文件夹时报错，不覆盖。
- 现有两本，各 15 章、两卷：《雨城修灯人》（出版小说）、《青崖问剑》（网文，带力量体系）。正文里故意埋了和设定对不上的地方、写错的名字、设定里没有的新名字，清单写在各文件开头的注释里，作为人工核对检查结果的答案。
- 不写摘要、检查结果、讨论记录：这些留给真实模型跑出来。
- 大纲用 `workspace.SaveCard`、`SaveLine` 创建；两者在锁内避开已有卡片和情节线的 ID，随机候选相同也不会使样例生成失败。
- `cmd/sample` 的测试把两本书写到临时目录再读回来，核对章数、字数够检查的下限、伏笔位置和回收关系。

## Alternatives considered

- **直接把生成好的作品文件夹提交进仓库** — 打开即用，不用跑命令。但文件夹里有每次都不同的 ID 和时间，落盘格式一改就得整份重做；试过的人还会把检查结果、摘要写回去，弄脏仓库里的样本。
- **在 Go 代码里用字符串字面量写书** — 少一个解析器。但一万多字的小说夹在代码里没法读也没法改，伏笔的位置要手算；文本格式改一个字就是改一个字。
- **做成软件里的「示例作品」入口** — 作者也能用。但这是界面功能，设计稿里没有；现在只是开发时要用，先不进产品。

## Consequences

- **收益**：两条命令得到一本内容固定、问题已知的书；落盘格式变了，重新生成即可，测试会先发现接口对不上。
- **代价与已知上限**：书的内容和埋的问题靠文件开头的注释说明，改正文时要手动同步；伏笔的时间都是生成那一刻，试不出按日期算的东西；每本只有一万字上下，试不出长篇的性能和上下文预算。
