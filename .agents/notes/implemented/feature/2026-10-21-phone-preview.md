# Agent Note: 手机预览

Status: implemented

## Problem

网文读者大多在手机上看，作者在电脑上写。电脑上一段四五行，到了手机上就是十来行：段落太长、一屏全是字，作者在电脑上看不出来。作者现在的办法是把窗口拖成手机那么窄，或者发布以后用手机自己看。

2026-10-21 作者同意做「手机预览」，要求先调研橙瓜码字的做法。调研报告在 [`.agents/research/2026-10-21-phone-preview.md`](../../../research/2026-10-21-phone-preview.md)，要点如下：

- 橙瓜码字只查到手机 App 里的「阅读模式」，桌面版的手机预览查不到。
- 作家助手（阅文）有虚拟手机框，能选各平台的格式，晋江有作者专门发帖称赞。
- Noveler（VS Code 插件）的说明最细：仿 iPhone 外框、393×852、字号 14–24、四种背景、跟着正文实时更新。
- 起点、番茄、七猫现在默认的字号、行距查不到可靠数值。
- 作者用它主要是看手机上什么样、查段落太长、换个环境通读改错字、连着读几章。

作者同日也说过，以后可能要另做手机 App，所以这一项不急，先做原型给作者看。作者看过原型、改了几处细节后，同日要求交给 Codex 做进软件。

## Decision

右栏多一页「预览」，和设定、讨论、伏笔并排；「视图」菜单里也有「手机预览」。AI 关着时照样有：它不用 AI。

### 样子

- 右栏里画一部手机，按右栏的大小缩放。手机里按读者的手机排这一章：
  - 状态栏；
  - 章标题，冒号换成空格，像阅读 App 那样写「第87章 停电」；
  - 正文，首行缩进两个字；
  - 底下一行是章名和「3/8」。
- 上面一排是「翻页」「滚动」两种看法，右边「Aa」打开排版：
  - 屏幕：窄屏 360、标准 393、宽屏 430，单位是手机上的点；
  - 字号：16–24，默认 20；
  - 行距：紧凑、适中、宽松，借用正文的三级行高；
  - 背景：白天、夜间、护眼；
  - 显示手机外框；
  - 标出超过 5 行的段落；
  - 恢复默认。
  - 调研查不到各家的默认值，所以不写「起点默认」这类话。也不在弹层里写「读者那边屏数会有出入」之类的说明：作者看原型时说不要在页面上写注释（2026-10-21）。
- 手机下面一行是「‹ 上一屏」「第 3 屏，共 8 屏」「下一屏 ›」。翻页是真的按排版分屏，不按字数估。
  - 只在这一章里翻：第一屏的「‹ 上一屏」、最后一屏的「下一屏 ›」变灰。原型先做过翻过头接着读上一章、下一章，作者看了说不要（2026-10-21）：要读别的章，在侧栏打开那一章。
  - 滚动时只写「约 8 屏」。
- 再下面一行写「2 段超过 5 行，看下一处」，点了翻到那一屏。超过的段落底色深一级，鼠标停上去写「手机上 7 行」。
  - 5 行取的是番茄写作指导里「手机上一段 3–5 行」的上限。这只是提示，不算错，也不进「待处理」。

### 和正文一起动

- 正文打字，预览跟着变。
- 正文里选中的字，预览里同一处也选中；没选字时，预览在同一个字后面画一道光标。不再按段整段标底色：原型先这样做过，作者看了说要跟着选中走，不按分段（2026-10-21）。
- 翻页看时，光标到了另一屏，预览跟过去。作者在预览里往回翻着看时，只要光标还在同一屏里打字，就不把它拉回来（参照 Noveler 的做法）。
- 滚动看时，预览跟着正文滚：正文滚到几成，就取正文窗口里几成高的那一处，在预览里放到同样几成高的地方；正文到顶、到底，预览也到顶、到底。
- 点预览里的哪个字，正文的光标就放到那个字后面，不是那一段的开头。
- 预览只读，不能在里面改字。

### 存在哪

排版的几项记在本机，所有作品通用，和「外观」一样；看到第几屏不记。

### 不做的

- 不画具体机型的外壳和灵动岛，不模仿哪一家 App 的界面。
- 不自动判断哪里该断章，不统计对话比例。调研里没找到作者这样用的证据。

样子在原型：

- `prototype/pane.js` 的 `phoneView`、`fitPhone`；
- `prototype/index.html` 的「右栏：手机预览」；
- `prototype/base.js` 的 `PHONE`；
- `scripts/prototype/walk.ts` 的「the phone preview」。

护眼的背景加了一个颜色名 `phone-eye`，见 DESIGN.md 的 Colors。

## Alternatives considered

- **单独开一个窗口，或者放在正文旁边一栏**。
  - 最强的理由：手机可以画得大，右栏还能同时开着设定。
  - 没有用：右栏本来就是「正文旁边的东西」，再开一栏，正文就被挤得太窄；在右栏里切到预览就能看，看完切回设定。
- **按字数估屏数**，比如一屏按 270 字算。
  - 最强的理由：算得快，代码里不用真的排版，原型和软件也容易对上。
  - 没有用：对话多的章一屏放不了那么多字，估出来差得远；作者要看的正是「这一屏长什么样」。软件里本来就有排版，拿同一套排一遍。
- **照起点、番茄、七猫各做一套预设**。
  - 最强的理由：作者投哪家就看哪家，作家助手就是这么做的。
  - 没有用（这一期）：三家现在的默认数值都查不到，编出三套数字反而误导。等拿到可靠的样本再加。

## Consequences

- `desk/phone.go` 管预览面板、设置、坐标转换和绘制；`editor/pagination.go` 的 `PaginatedText` 管分行、分页、偏移所在页和文字命中：
  - 排版用 `editor.LayoutParagraph`（`editor/paragraph.go`），和正文共用 `layoutParagraph` 整形、断行（避头尾），用 `textAscent` 计算上升高度；每行字形从 rune 边界索引直接切片。按段缓存：同一段文字、同样的宽、字号、行距、缩进不重排。打一个字只重排那一段。
  - `desk` 把屏幕尺寸、字体、行距、缩进和段间距传给 `editor.PaginationOptions`；分页不依赖 `shelf.Phone` 或窗口。手机里的尺寸是开头那组 `phone…` 常量，单位是手机上的点或 em，数值照原型；不借用 `hTag` 这类桌面常量。
  - 滚动同步用 `Editor.ScrollAnchor`（`editor/view.go`），算法和原型的 `syncPhone` 一样。
- 右栏开着哪页从 `talk`、`fore` 两个布尔改成一个 `docView.tab`（设定、讨论、伏笔、预览）。
  - `desk.json` 只写 `pane_tab`；老文件没有它时照 `fore_tab`、`talk_tab` 推出来，`fore_tab` 优先。
  - AI 关着时 `tab` 留着「讨论」，右栏显示设定，和以前一样。
- 排版的几项记在 `works.json` 的 `phone`（`shelf.Phone`），各档用英文词（`flip`/`scroll`、`narrow`/`standard`/`wide` 等），nil 或不认识的值用默认；`NoFrame`、`NoLong` 省略即开着。
- 检查：
  - `desk` 的 `TestThePhonePreview`：照原型 walk 走一遍，包括光标跟屏、选中、点字定位、到头变灰、长段、Aa、滚动同步、关 AI、换章、卷的空状态。
  - `desk.TestPhonePreferencesAreLocal`、`editor.TestPaginatedParagraphCache`，以及 `desk.json` 的旧字段兼容测试。
  - `TestPhonePreviewTypingCost`：一万字以上的章，每打一个字的整帧中位数不超过 25ms。
  - `cmd/inkgo` 的 `TestLayoutPhonePreview` 存白天、夜间、滚动、长段四张截图。
  - `npm run verify-prototype` 的「the phone preview」。
- 2026-10-21 由 Codex 实现，Claude 审查：返工一轮，三处都是结构问题：右栏标签改成一个字段；偏好从单独的 `phone.json` 并进 `works.json`，用词不用编号；尺寸改成手机自己的常量。

## Risks

- 预览和读者实际看到的不会完全一样：各家 App 的字体、边距、行距都不同。界面上不写说明，靠「约」字和不标平台名来避免误会。
- 每次打字仍要把这一章的行重新分屏（只是不重新排字）。几万字的超长章若感到卡，再改成只排光标附近的几屏。
