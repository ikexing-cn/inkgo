# Agent Note: 标题栏并进各栏顶部，章节间前后跳转

Status: implemented

## Problem

系统标题栏单独占一行，下面侧栏、工具栏、右栏又各有一行顶栏，窗口顶部白白多出 30 来像素。设计稿"标题栏"页把它和各栏顶部合成一行（"不多占高度"）。侧栏顶部还画了后退、前进两个按钮，代码里原先没有导航历史。

作者 2026-10-09 定了：标题栏以设计为准；后退、前进在打开过的章节之间跳转。

## Decision

- 主窗口隐藏系统标题栏（`TitleBarHidden`）。窗口按钮由系统画，浮在页面上；`c.TitleBar()` 给出它们占的位置。
  - 按钮保持系统的高度（Windows 上 32），贴在 52 高的顶栏上沿。起初设成 52，和顶栏一样高，但系统按钮被拉高，比别的 Windows 程序高出一截，作者看着奇怪，就改了回来。
- 各栏顶部那一行就是标题栏，按住可以拖动窗口，双击最大化（`DragWindow`）：
  - 侧栏顶部新加 52 高的一行，下面一条分隔线，和工具栏的分隔线对齐。macOS 上先给红绿灯留出位置。
  - 正文页的工具栏、讨论页的顶栏：右边没有右栏时，给 Windows 的三个按钮留出位置；左边没有侧栏时（专注模式），给红绿灯留出位置（`chromeRoom`）。
  - 右栏的标签行改为 52 高，右边给 Windows 按钮留位置（`paneTop`）。标签的位置因此上移约 9 像素，和设计稿一致。
  - 设置页、作品分类页、书架没有自己的顶栏，在顶部垫一条 52 高的透明拖动区。设置页内侧栏的上边距从 20 加到 24，第一项不被压住。
- 出错、请求中、完成提示原先排在整页最上面，现在排在各页顶栏下面，不再占用标题栏那一行。没有顶栏的页面，提示排在拖动区下面。
- 后退、前进只在正文页显示：
  - 打开另一章时，当前这章记进"后退"，"前进"清空，和浏览器一样。最多记 50 章。
  - 跳到的章已被删掉时跳过它，接着找前一个。
  - 历史只在这次打开作品期间有效，不存盘；切换作品时随正文页状态一起清空。
- 设计稿侧栏顶部还有"收起侧栏"按钮。收起之后，展开按钮和前后箭头该放在哪里，设计稿里没有画，这次没有做，等作者在设计稿里定下来。

## Alternatives considered

- **保留系统标题栏，只加前后按钮** — 不碰窗口，各平台的拖动、贴边、双击行为都由系统负责，风险最小。但这和作者定的"以设计为准"相反，顶部也照旧多一行。mygo 的隐藏标题栏仍由系统画窗口按钮，拖动和双击也由它处理，要自己负责的只是留出位置。
- **完全无边框，自己画窗口按钮** — 可以完全照设计稿的样子画按钮。但最小化、最大化、贴边布局、按钮的悬停态都得自己做，各平台的习惯也不一样。系统的按钮外观和设计稿已经很接近。
- **提示条浮在顶栏下面** — 不用改各页面，在一处叠上去就行。但它会盖住正文上方"磁盘上被改过"这类提示的按钮，测试一跑就点不到；放回页面的布局里就没有这个问题。
- **前后跳转在页面之间跳，或者存盘** — 页面只有四个，左侧导航一下就到，用不着历史；章节多了才需要"刚才那章"。存盘后重开作品还能后退，但重开时本来就回到上次那章，用处不大。

## Consequences

- **收益**：窗口顶部少一行，和设计稿一致；在章节之间来回查看不用再去树里找。
- **代价**：
  - 侧栏内容下移约 50 像素，章节树能显示的行数少两行左右。
  - 设置、分类和书架三页的拖动区是透明的，看不出能拖，但和别的页同一高度，用起来是一样的。
  - 窄窗口下侧栏收成图标栏时只有 60 宽，macOS 的红绿灯放不下；目前只在 Windows 上用，暂不处理。
