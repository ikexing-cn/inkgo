# Agent Note: 导出成 Word，正文、大纲、设定勾几样导几样

Status: implemented

## Problem

导出原来只有一种：正文合并成一个 `.txt`，可以选全书、本卷或本章，段首可以加两个全角空格（[写作页和章节](2026-10-08-writing-page-and-chapters.md)、[走查修正](2026-10-09-walkthrough-fixes.md)）。2026-10-16 作者说「导出成 Word 是核心需求」，导出的东西要拿去投稿：交给出版社、杂志、征文，或者网站的编辑。投稿常要附大纲，有时要附设定，这些原来都导不出来。

同一天用一问一答把要做成什么样定了下来，下面「Decision」里的都出自作者的回答，原型审过两轮。

## Decision

- **照投稿稿件的样子做**：给编辑审稿、自己打印存档也都够用。
- **还是「文件 → 导出…」一个对话框**：纯文本留着，网文作者往网站后台粘贴还是它方便。
- **内容是三个勾选框「正文」「大纲」「设定」，勾几样导几样，各成一个文件**。作者审第一版原型（内容是三选一的分段）时说：「不能直接导出三个吗。或者选择导出正文和大纲。这个设计不好」。只勾一样时照常选文件名；勾了几样就选一个文件夹，几个文件都放进去。
- **对话框记住什么**：勾了哪几样、格式（Word / 纯文本）都记在本机，所有作品通用。第一次打开时只勾正文，格式是 Word。范围每次都从「全书」起。原来开着一章时先选「本章」（[标签页](2026-10-13-chapter-tabs.md)），这次作者改成一律「全书」：投稿多半要全书或前几章。
- **范围**：全书 / 本卷 / 本章 / 指定范围，作用于正文和大纲，设定不分范围。「本卷」是开着的这一章所在的那一层文件夹，开着的是文件夹时就是它；卷里套卷时也只指最里面那一层，不再像原来那样写出卷名。「本卷」「本章」只在正文页开着一章或一卷时有；指定范围要有两章以上。指定范围是「从」「到」两个下拉框，默认第一章到第三章，「到」只列「从」那一章及以后的章；两章同名时，后一章的名字后面加「 (2)」。跨卷时，每卷的卷名排在它在范围内第一章的上面。
- **笔名**：只在勾了正文、选了 Word 时出现，选填，写在首页。存在作品的 `work.yaml`（新加的可选字段 `pen`）。本机另记一份最后用过的，作品自己没有笔名时就带上它，新作品也一样。只在导出对话框里改，导出成功时存下。
- **导不出的那一样**：勾上的这一样导不出来时，在表单里用灰字说为什么，导出时跳过它：「还没有章节，不导出正文。」「所选范围内还没有写章纲，不导出大纲。」「还没有已定的设定，不导出设定。」勾上的几样都导不出时，「导出」按钮是灰的。
- **格式和范围用一排单选圆点**，和上面那排勾选框一个样子。作者看了分段的样子说「有点丑」：分段放在表单里会撑满一行，一长条灰底里只有左边几个字。看了圆点说「这个样子可以，我挺满意」。这一条写进了 `DESIGN.md` 的「表单」；起草对话框的「本章已有内容」也换成了圆点。

### 正文的 Word

- **首页**：书名、「作者：笔名」（没填就不写这一行）、「字数：12.3 万字」，字数按导出的那部分算，写法和书架上一样。首页是单独一节，不印页码；正文那一节的页码从 1 起，放在页脚居中。
- **一套固定的版式，不给选项**：A4，正文宋体小四、1.5 倍行距、首行缩进 2 字，卷名和章名用黑体、居中。
- **用 Word 自己的样式**：正文是「正文」（Normal），卷名是「标题 1」（Heading 1），章名是「标题 2」（Heading 2），首页的书名是「标题」（Title）。编辑要别的字体字号，在 Word 里改一处样式，全书就跟着变；导航窗格按卷、章列出来。卷里套卷时里面那层是「标题 2」、其中的章是「标题 3」，再深也是「标题 3」；不在卷里的章也是「标题 2」。
- **每章另起一页**；卷名不单占一页，排在它第一章的上面。不出目录：Word 的目录是个域，每次打开都要问要不要更新，导航窗格已经够用。
- **章里的空行照留**：作者常用空一行隔开两场戏。
- **纯文本的正文和原来一样**：只有导出全书时开头写书名，段首加不加全角空格可以选，打开时勾着。

### 大纲和设定

- **大纲**：第一行「书名 · 大纲」，卷名是「标题 1」，章名是「标题 2」，纲是「正文」，接着排不分页。没写纲的章只写章名，看得出哪几章还没写。不带 AI 写的摘要，也不附伏笔清单。
- **设定**：第一行「书名 · 设定」，按作品分类的顺序分节，分类名是「标题 1」，没有已定设定的分类不写；每条一段，名字加粗，后面括号里写别名，再接「：」和内容。只导已定的，不导待确认、已删除的，也不写出处。
- 都没有首页，也都能导成纯文本，结构和 Word 一样。

### 文件名

正文是「书名.docx」，大纲是「书名-大纲.docx」，设定是「书名-设定.docx」。范围不是全书时写进正文和大纲的文件名：「书名-第一卷.docx」「书名-第一章至第三章-大纲.docx」。名字里的「：」和 Windows 不许用的 `\ / : * ? " < > |` 都换成空格。纯文本是 `.txt`。

### 代码里怎么做

- `workspace`：`Store.Pieces` 按章节树的顺序读出每个节点：标题、在第几层、是不是文件夹、正文和纲。原来的 `Store.Export` 去掉，拼文本的事挪到 `export` 包。
- `export` 包：`Within` 从全书的节点里挑出一组章和装着它们的文件夹，每个文件夹只出一次；`Prose`、`Outline`、`Setting` 把它们排成一份 `Doc`（首页、一串带样式的段落），`Doc.Text` 出纯文本，`Doc.Docx` 出 `.docx`。`.docx` 用 Go 标准库的 `archive/zip` 自己写，不引入依赖，也不需要 cgo。
- `shelf`：`works.json` 多一项 `export`（`shelf.Export`）：嵌入 `export.Options` 记勾选内容和格式，另记最后用过的笔名。没有这一项就是第一次，只勾正文、Word。勾选框和格式一改就存。
- `desk/export.go`：对话框打开时先存下正在写的，再用 `Store.Pieces` 读一遍全书放在内存里；`export/plan.go` 的 `BuildPlan` 从这一份和设定、当前章节、`Options`、范围 `Selection` 计算 `Plan`，整体存在 `exportState`。打开弹窗，或内容、格式、范围、起止章节、当前章节变化及设定刷新时重算；普通绘制复用计划。笔名和缩进由界面保管。只勾一样时用 `SaveFile` 选文件名，几样时用 `PickFolder` 选文件夹；没有系统对话框时（测试）写进作品的 `导出` 文件夹。同名的文件直接覆盖：选文件名时系统对话框会先问，选文件夹时不问。
- `desk/theme.go` 的 `dots`：表单里一排单选圆点，导出和起草对话框都用它。

## Alternatives considered

- **内容三选一，一次导一样** — 第一版原型就是这样。对话框简单，每样东西的选项也不会混在一起。没有用：作者说「这个设计不好」，投稿常要正文和大纲一起交，一样一样导要开三次对话框。
- **勾了几样合成一个文件**（大纲在前、正文在后、设定在最后，中间分页） — 发给别人只有一个附件。没有用：三样的排法不同（正文有首页、每章分页，大纲和设定接着排），编辑收稿也多半要正文、大纲分开的附件。真有人要合成一个，再加一个「合并为一个文件」的勾选框。
- **对话框里给字体、字号、行距的选项** — 编辑的要求各不相同，在对话框里就能对上。没有用：每多一个选项，对话框就长一截。用 Word 的样式排，在 Word 里改一处样式全书都跟着变，比在对话框里选更方便。
- **出目录** — 稿子长时翻得快。没有用：Word 的目录是个域，打开文件时要问要不要更新；导航窗格按标题列出全部卷章，已经够用。
- **指定范围用一棵带勾选框的章节树** — 可以跳着挑章。没有用：投稿要的样章几乎都是连着的「前三章」，两个下拉框最直接。
- **格式、范围用分段** — 第一版原型就是这样，和软件里别处的分段一致。没有用：作者看了说「有点丑」。分段适合点了马上换样子的地方（检查的分类、待处理的全部和本章），它在那里只有内容那么宽。
- **用现成的 Go 库写 `.docx`** — 不用自己记 Office Open XML 的规矩。没有用：要的只是段落、样式、分页、分节、页脚的页码，这几样用标准库写一百多行就够；多一个依赖，就多一份要跟着升级、要审的代码。
- **笔名存在本机，不跟着作品** — 不用改 `work.yaml`。没有用：笔名是这部作品的，换台电脑打开同一部作品也该在。本机只记最后用过的那个，给没有笔名的作品当默认值。
- **`Store.Pieces` 收一组章，只读这几章** — 导出一章时不用读全书。没有用：对话框要在按「导出」以前说清楚大纲导不导得出、字数多少，每换一次范围都要知道范围里有没有纲；打开时读一遍全书，换范围时就只在内存里挑，比每次换范围都读盘简单。原来按「导出」时也要读全书。

## Consequences

- 投稿要的正文、大纲、设定一次导出，Word 里打开就是稿件的样子；版式要改，在 Word 里改样式。
- 打开导出对话框会读一遍全书的正文和纲。几百章的书在打开时多等一下；以后嫌慢，可以只读纲和字数，按「导出」时再读正文。
- `work.yaml` 多了可选的 `pen`，`works.json` 多了可选的 `export`；它们都按「不认识的字段就报错」读，旧版本打不开写过这两项的文件。软件还没发出去过，和之前加字段时一样，只记下。
- Word 和 WPS 对样式的理解不完全一样：首行缩进同时写 `firstLineChars` 和按小四算的 `firstLine`（480 缇），WPS 不认前者时还有后者。字体只写中文名「宋体」「黑体」，没装这两种字体的电脑上会换成别的。打开的效果作者自己在 Word、WPS 里看，agent 没有验收这一项。
- 几个文件里有一个写失败时，前面写好的留着，提示条报那个文件的错，对话框不关。
- 卷里套卷时，「本卷」只是最里面那一层；要导外面那一层，用「指定范围」。
- 检查：
  - `npm run verify-prototype` 的「export」点了单选、多选、指定范围、笔名记住、导不出的那一样；「a new work」点了没有已定设定时的说明和按钮变灰；「a draft」点了圆点。
  - `go test ./export`：`.docx` 是一个 zip，各部分 XML 解得开；首页单独一节、不印页码，正文页码从 1 起；章另起一页、卷名和第一章同页；样式名、宋体黑体、缩进、行距、页码域、加粗的名字都在；纯文本的正文和原来的输出逐字一样；`Within` 跨卷挑章时每卷只出一次。
  - `go test ./workspace` 的 `TestPiecesAndCount`，`go test ./shelf` 的 `TestShelfRoundTrip`。
  - `go test ./desk` 的 `TestExportTheWork`：先是全书、Word；笔名写进首页、`work.yaml` 和本机；只勾大纲又没写纲时说为什么、按钮不动；三样一起导成三个纯文本；勾选和格式记进 `works.json`；本章导出时文件名带章名。`TestDraftOverWhatIsThere` 查起草的圆点。
  - `go test ./cmd/inkgo` 的 `TestLayoutWriting` 截导出对话框两张：打开时，和纯文本、指定范围。
