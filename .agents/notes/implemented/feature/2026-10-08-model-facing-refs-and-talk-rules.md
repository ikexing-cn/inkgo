# Agent Note: 模型只看本次请求的短编号，讨论规则直接对作者说话

Status: implemented

## Problem

用真实 DeepSeek 试用 M1 时出现两类问题。第一，讨论请求把思路写成 `[保留 20261007-1659-6942] 文本`，模型就在回复里写“（保留条目 20261007-1659-6942）”；“AI 看到了什么”面板也原样显示这串内部 ID，而界面其他地方刻意不显示 ID。第二，讨论规则写的是“只回应作者本次明确提出的问题；不主动续写、发散、追问”。作者只说出一个念头（“主角有个说不出口的秘密”）时，模型没有问题可答，就回了“已记录……我这边不展开、不预设”；作者要建议时，模型又用第三人称说“作者要求给想法，我按维度列一批”，把规则里的说法带进了对话。

本篇沿用 [M1 实现笔记](2026-10-07-m1-discussion.md)中的上下文分层、预算与快照规则，只改模型看到的形式和讨论规则。

## Decision

- 讨论请求把思路池按“留下”“待定”“已定设定”“已放弃”分段列出，每条用本次请求内的 `[n]` 编号；冲突写成“与 [n] 矛盾，作者尚未解决”。编号每次请求重新分配。
- 记账请求中放弃清单的条目用 `r1`、`r2`……，冲突检查中其他保留思路用 `k1`、`k2`……。模型返回的 ref 在本地映射回思路 ID，未知 ref 视为无效输出。任何发给模型的内容里都没有思路 ID。
- 回复快照的 `ContextItem` 仍记录思路 ID，供审计；`Text` 改为“状态：内容”，界面不显示 ID。
- 讨论规则在 `discussion/prompts.go`。下面三条中关于语气和篇幅的部分（只回应念头、不追加点子、不反问、每个方向一两句）已被[讨论规则放开语气和篇幅](2026-10-08-talk-rules-as-collaborator.md)取代，其余仍有效：
  - 称作者为“你”；不复述规则，不说“已记录”这类描述自身做法的话，不提编号、状态或“思路池”，提到某个方向时用内容指代。
  - 作者只给出念头时，简短回应这个念头本身（它带来的张力、它和已有方向怎样衔接或冲突），不追加新点子，不反问。
  - 作者提问或要建议时，给出几个彼此不同的具体方向，每个一两句，方便拆成卡片逐条取舍；不替作者选定。

## Alternatives considered

- **继续发送真实 ID，只在规则里禁止复述** — 改动最小，冲突与相近检测可以直接返回真实 ID，不用映射。但模型照抄标识符是常见失败；审计面板照样显示 ID；18 位 ID 也容易抄错，抄错就让整轮记账因“未知 ID”失败。
- **回复落盘前用正则删掉 ID** — 结果确定，不依赖模型是否听话。但删完句子会残缺（“保留条目 ”），面板问题也没解决。
- **保留原来“只回应明确问题”的严格规则** — 最贴近提案中“AI 不主动出内容”的原则。但作者只说一个念头时，模型没有可回应的问题，只能说空话或解释自己的规则。新规则仍然不追加点子、不反问，只回应作者说出的内容。

## Consequences

- **收益**：模型请求、回复正文和审计面板里都不再出现内部 ID；记账与冲突检查的 ref 只有两三个字符，模型抄错的机会更少。
- **代价与已知上限**：规则的实际效果只能靠真实使用观察；单元测试只证明请求里没有 ID、ref 能正确映射。如果作者认为“回应念头本身”仍然算主动出内容，就收紧这一条。编号不跨请求稳定，所以规则要求用内容指代方向；模型若仍在回复里写“第 3 条”，就考虑去掉编号，冲突改为直接引用文本。

## Verification

`discussion/engine_test.go` 的 `TestTurnJournalAndReopen` 断言讨论与记账请求的系统规则和最后一条消息都不含思路 ID，快照文本不含 ID；`TestSimilarRefsMapToRejectedIdeas` 覆盖 `r1` 映射回放弃思路的 ID；`TestConflictsDoNotDecideForAuthor` 覆盖 `k1` 映射。
