# Agent Note: M1 总讨论与思路池落地

Status: implemented

## Problem

作者需要把讨论中的具体想法逐条留下、待定或放弃，并在新会话中继续使用这些决定。只保留聊天记录无法区分临时发散与作者认可的依据，网络失败或记账中断还可能造成重复卡片和丢失原文。

本篇落实[完整产品提案](../../proposed/feature/2026-10-07-idea-pool-discussion.md)中的 M1。原提案与本篇部分重叠，保留 proposed 状态供 M2、话题、设定整理和正文集成继续使用；其中 M1 的实现事实以本篇为准。[原生编辑器决策](../architecture/2026-10-07-pure-go-native-editor.md)继续有效，本次仅增加只读原文选区。[笔记门禁](../process/2026-10-07-agent-notes-gates.md)只约束过程，没有业务决定被替代或废弃。本篇的 SQLite 索引已由[存储去掉索引](../architecture/2026-10-08-m1-storage-without-index.md)取代；模型看到的思路形式与讨论规则见[短编号与讨论规则](2026-10-08-model-facing-refs-and-talk-rules.md)。下文"API 不流式"的决定已由[模型层用 GoAI](../architecture/2026-10-08-model-layer-on-goai.md)取代，推理等级与推理内容落盘也在该篇。

## Decision

### 模块与操作边界

`workspace` 管作品文件；`model` 管全局配置、凭据与协议；`discussion` 管上下文、严格记账和作者操作；`desk` 管 mygo 原生界面。入口默认打开讨论界面，`-work` 打开指定作品，`-editor` 保留原编辑器演示。所有包在 `CGO_ENABLED=0` 下构建。

讨论只由作者发送或重试触发。自动模型工作限于本轮拆分、分类、相近提示和作者保留后的冲突检查。模型输出不能决定卡片状态；人说的话也先成为未处理卡片。同轮卡片按人先、AI 后显示，分类只能来自作品列表。现实事实默认未核实，确认核实需要来源。作者可以编辑卡片或在只读原文中选择 rune 范围自行摘取；原文不能被输入、剪切、粘贴或输入法修改。

界面以分诊为中心：思路池默认显示“待处理”队列，作者决定后卡片离开队列，焦点移到下一张，8 秒内可撤销；被放弃的卡片撤销时只能回到待定，与状态机一致。放弃理由在卡片内就地填写。讨论区不再在每条回复下复制卡片，只显示本轮整理数量和“在思路池查看”，点击后思路池只看这一轮，避免同一张卡在两处各有一套按钮。对话以首句和日期命名，不显示内部 ID。

网络工作在后台执行，结果通过通道交回界面线程。在途期间禁止切换作品、发送另一请求和修改卡片，读界面使用缓存。取消保留已经落盘的数据。每个 Store 有互斥锁，但 M1 的写入协调边界是单个应用实例；不支持多个进程同时写同一作品。关闭应用时取消在途任务，尚未返回的回复不能承诺保存。

### 持久化与重试

作品使用 schema 1：严格 YAML 的作品配置、带 YAML 头信息的 Markdown 卡片、只追加的 JSONL 会话。字段拼写、版本、ID、引用、状态历史和原文位置均验证。未知版本明确报错；M1 没有旧版本迁移，因为这是首个落盘格式。文件写入采用临时文件加替换，新增 ID 不覆盖现有文件。只有 JSONL 最后一个未完成且未换行的事件可以修复；中间坏行、完整但非法的尾行必须报错。

讨论先保存用户发言，再请求模型；回复成功后保存实际上下文快照，再开始记账。失败发言可以重试回复，沿用原消息 ID；已有回复只能重试记账。记账先验证整个输出，精确匹配本轮原文片段并换算 rune 区间，再把含固定卡片 ID 的计划追加到会话。`bookkeeping` 事件的 `idea_ids` 可以预留尚未出现的文件；普通消息的引用必须已经存在。之后逐张落盘。重试优先重放已有计划，已有卡片保留作者修改，不重复调用模型；计划完整时即使没有模型配置也可恢复。

模型输出使用严格 JSON，不接受未知字段、无效分类、伪造来源、未知放弃条目 ID 或尾随输出。允许空的 `ideas` 数组；返回 `null` 不表示成功。保留操作先保存作者决定，再做冲突检查，失败必须明确表示“决定已保存，检查失败”。冲突只作双向提示，不替作者解决，计数仅包含双方仍处于保留状态的组合。多卡片冲突写入不是事务；中途磁盘错误可以留下单边标记，再次显式检查重建关联。

读写只走规范文件，不建索引，见[存储去掉索引](../architecture/2026-10-08-m1-storage-without-index.md)。分类删除先将条目归入“其他”，再改配置，因此中断后文件仍有效，再次删除即可完成。

### 上下文与模型

M1 只有总话题。上下文来自保留、待定、放弃避让清单和已有采用状态的约束，未处理与被取代条目不进入依据。按最近修改优先装入完整条目，最后加入最多四轮完整对话和当前发言。放弃摘要使用条目文本的单行形式与理由；卡片本身是短摘要，不额外调用总结模型。字节数加消息开销是保守预算估计，并非供应商精确 token 计数；讨论预留 2048 输出，记账预留 4096。系统规则与当前发言都放不下时拒绝请求。记账不能在悄悄漏掉放弃清单的情况下做相近检测，超预算直接报错并允许重试。

模型只看到本次请求内的短编号，不看到思路 ID，见[短编号与讨论规则](2026-10-08-model-facing-refs-and-talk-rules.md)。每条回复持久化实际发送和省略的思路 ID、当时文本及省略原因，“AI 看到了什么”读快照，不按后来修改的卡片重算。被放弃的方向以禁止推荐的形式发送，但模型仍可能不遵守；相近检测的语义质量也依赖模型，测试只证明协议和状态约束，不承诺百分之百不重复。

全局提供商预置 DeepSeek、Kimi、OpenAI、Anthropic，支持自定义 API 和三种协议：Chat Completions、Responses、Anthropic Messages。讨论和记账分别选模型，记账留空沿用讨论。模型目录可以手写或显式拉取，目录外 ID 可直接使用。凭据存系统钥匙串，缺失时读环境变量；作品里只保存提供商与模型 ID。空 key 输入保留已有凭据，专门的清除按钮删除后回到环境变量。配置界面及发送前显示本机或远程目的地址；本机代理是否继续转发由服务本身决定。

请求改为流式，时长、输出上限与凭据关卡见[模型层用 GoAI](../architecture/2026-10-08-model-layer-on-goai.md)。客户端拒绝重定向，支持上层取消；请求、响应和完整目录限制 8 MiB，目录分页上限 100。错误信息为中文，HTTP 失败附带可能原因（如 401 对应 key 无效）；不回显远程响应体或传输详情，避免凭据泄漏。系统钥匙串不可用且未设置环境变量时显示错误；该情形下 M1 界面不能直接使用无凭据端点，底层显式无 key 客户端可以。

### 验证

门禁为 `go vet ./...`、`go test ./...`、`npm run verify-notes`。本批测试涵盖文件校验、状态保护、原文 rune 区间、JSONL 尾部恢复、固定 ID 记账重放、不覆盖已修改卡片、上下文预算与快照、相近与冲突 ID、三种 API 请求响应、取消、超限、模型目录和凭据隔离。

原生无窗口测试验证数字输入不误触留弃、可选放弃理由、决定后离开待处理队列、撤销、对话命名与本轮筛选、捞回待定、无模型时仍保存保留决定、取消后恢复界面、错误后显示已落盘内容，以及原文只读选择。入口的 `TestLayoutDiscussion` 与既有 `TestLayout` 一同渲染截图，设置 `SHOT` 时另写 `-m1`、`-settings`、`-welcome` 图片。截图采用合成对话与临时作品，没有调用真实供应商或使用真实稿件。

## Alternatives considered

- **只写卡片，不写记账计划**：文件更少、实现直接。但崩溃在第 N 张卡片后，重试无法区分已写卡片与新提议；固定 ID 的预写计划使恢复不依赖再次调用模型。
- **整个会话同步执行**：状态模型最简单，不需要线程协调。但网络超时会冻结原生界面和取消按钮；采用单后台任务加界面缓存，保留单写入者约束。
- **索引使用修改时间与内容 hash 增量更新**：大作品重建更快。但 M1 的数十条思路不足以抵消失效与恢复逻辑，先全量重扫；真实数据出现瓶颈后再加缓存。索引本身后来也去掉了，见[存储去掉索引](../architecture/2026-10-08-m1-storage-without-index.md)。
- **供应商专用 tokenizer**：预算更精确、上下文利用率更高。但三个协议与自定义端点未必暴露 tokenizer，先使用明确标示为估计的保守字节预算。
- **回复下内联完整卡片**：作者在读回复时就能就地决定，少一次视线移动。但同一张卡在讨论区和思路池各有按钮，状态与焦点难以一致，长回复下卡片把对话挤散；改为一行摘要并联动筛选思路池。
- **直接用原生 TextArea 取得来源选区**：能少维护一套输入处理。但当前 mygo 没有公开文本区选区读取接口；复用现有 editor 的 rune 选区，并关闭所有修改路径。

## Consequences

M1 能从空文件夹开始，配置模型、总讨论、拆分、留弃、手工摘取、查看避让与冲突、切换会话及重新打开作品。文件可直接用 git 管理，key 不进入作品格式。

本批不实现话题树、embedding 调用、AI 合并/细化操作、整理设定、章节存取、联网核实或正文侧栏；这些仍由完整产品提案承载。大作品全量扫描、宽松语义摘要和非事务的跨卡片冲突更新是 M1 的已知限制。真实 API、系统钥匙串交互和硬件输入法没有通过合成测试得到验证，需实际使用时确认。
