# Agent Note: 第一次真机走查的修正：回到上次的页面、提示自动消失、服务按名称选、模型点开可选、窄窗口留住正文

Status: implemented

## Problem

2026-10-09 作者授权连夜推进时，agent 用 kimi-cu 在真实窗口里走了一遍新建作品、写章、配模型、起草。截图测试看不出以下五处别扭，只有真的用起来才会碰到：

- 关掉程序时正停在正文页，重开却总是先到"讨论"。要再点一次"正文"才回到刚才那章，而那一章其实已经记住了（`desk.json` 的 `chapter`）。
- 绿色的成功提示，比如"模型设置已保存"，会一直挂在页面顶上，切到别的页面也还在，把整页往下推一截，直到手动点掉。
- "模型设置"里的服务下拉显示的是 ID（`deepseek`），左边服务列表和其他地方显示的都是名称（DeepSeek）。
- 模型输入框点进去什么都不出。mygo 的 `Autocomplete` 只在打字时给候选，而且不列和当前值相同的那项；已经填着 `deepseek-flash` 的框，要先删掉几个字才看得到还有 `deepseek-v4-pro`。
- 窗口拖到最小宽度（1000）时，正文页顶栏的章节名被挤成"…"，字数成了"本章…"。左栏 232、右栏 392，中间只剩三百多像素，还要放七个图标。查找替换栏同样一行放不下，"替换""全部替换"被截掉，还把右栏挤窄了几像素。

## Decision

- **回到上次的页面**：`.writer/desk.json` 多一个 `writing` 字段。
  - 作者在"讨论"和"正文"之间切换时记下当前页，重开作品时停在正文页就回正文页，章节照旧用 `chapter`。
  - "作品分类"和"模型设置"不单独记，离开正文页去这两页时 `writing` 保持原值。这两页是偶尔去改一下的地方，不是写作停下的地方。
  - 记下的是"最后停在讨论还是正文"（`leftWriting`），不是存盘时的当前页。在设置页保存模型选择也会写 `desk.json`，按当前页算的话会把 `writing` 冲掉，第一版就是这样，真机重开时才发现。
- **提示自动消失**：成功提示（`notice`）出现 8 秒后自动清掉（`noticeFor`）。用 `ui.Context.After` 定时重绘，不靠鼠标移动触发。错误提示不受影响，仍要作者点掉。
- **模型点开可选**：三个模型输入框改用 `ComboboxBase` 自己搭（`modelField`）。点一下或按 Down 列出这个服务目录里的全部模型，当前那项垫底色；打字时只留包含所打内容的，开头相同的排前面；目录外的 ID 照样可以直接输入。样式照抄 mygo 的 `Autocomplete`。
- **窄窗口留住正文**：
  - 右栏宽度除了不超过窗口一半，还要给中间留出 480（`pageMin`），但不窄于 300。作者拖出来的宽度照样记着，窗口放大后恢复。
  - 顶栏上一帧宽度不足 600 时，"本章 N 字 · 全书 N 字"缩成"N 字"，不再参与收缩，章节名先保住。
  - 查找替换栏改成两行：第一行查找框、"1 / 4"、上一个、下一个、关闭；第二行替换框、替换、全部替换。输入框占满剩下的宽度。不按宽度切换一行或两行，窗口拖动时栏不跳。
- **和正文一样的快照**：快照对话框里选中的快照和当前正文逐字相同时（刚打开章节时最新那份总是这样），说明处写"这一份和现在的正文一样"，"恢复这个版本"不可点。以前照样能恢复，恢复了也什么都不变，只多存一份"恢复前"快照。
- **系统对话框跟着窗口**：导出全书和选文件夹用的系统对话框传入主窗口作 `Parent`（`cmd/poc`），出现在程序窗口上方。以前没有父窗口，对话框弹在屏幕左上角，窗口不在那里时像是没反应。
- **回收站说清楚恢复了什么**：恢复后的提示写"「新章节」已恢复"，不再只写"已恢复"。弹窗底部加"关闭"按钮，以前只能按 Esc 或点弹窗外面。说明文字不再提 trash 文件夹，作者不需要知道它放在哪个目录。
- **文件夹页显示本卷字数**：选中文件夹时，顶栏写"本卷 N 字 · 全书 N 字"，N 是文件夹里所有章节（含子文件夹）的字数和。以前只写全书字数，要知道这一卷写了多少只能自己加。窄窗口时同章节一样缩成"N 字"。
- **右栏讨论说的是正在写的东西**：
  - 正文页右栏的空讨论不再沿用讨论页的"从一个模糊的念头聊起"和"整理成右边的设定文档"（右栏里设定是旁边的标签，不在右边）。改成"聊聊正在写的这一章"，三个起头换成问这一章的："这一章的节奏怎么样""接下来可以怎么写""人物的动机说得通吗"。
  - 选中文件夹时，标题、起头、输入框提示和开关都说"卷"：开关写"附上本卷"，提示写"把卷纲一起发给 AI"。以前写"附上本章"，实际发的是卷纲（`openUnit`）。
  - 右栏讨论在回复时，进度（"正在思考…"和取消）只在右栏里显示，页面顶上不再多一条"AI 正在思考…"。以前发一句话整页正文就往下跳一截，回复完又跳回来。讨论页本来就是这样处理的；右栏收起时，顶上那条照旧出现，否则看不到在等什么（`talkShown`）。
  - 设定条数写在“设定”标签里面。以前写在两个标签后面，紧挨着“讨论”，看起来像讨论有一条未读。
  - 快捷键按系统写：Windows 上是 Ctrl+L、Ctrl+J、Ctrl+Enter，macOS 上是 ⌘（`modKey`）。以前输入框提示、续写按钮的提示和设置说明在 Windows 上也写 Cmd。
- **只导出本卷或本章**：导出对话框多了"全书 / 本卷「X」/ 本章「Y」"三选一（"本卷"是打开的这一章所在的文件夹，顶层章节没有这一项；打开的是文件夹时只有它自己）。每次打开对话框默认全书。部分导出不写作品名那一行，从所选节点的标题开始，文件名是"作品名-标题.txt"。`Store.Export` 多一个 `from` 参数，空串是全书。顶栏图标的名字改成"导出全书或章节"，弹窗标题改成"导出正文"。投稿或发给试读的人时，常常只要一章，以前只能导出全书再手剪。
  - 被放弃：**在章节树右键菜单里加"导出这一章"** — 能导出任何一章，不必先打开它。但导出要选缩进、选位置，最终还是弹同一个对话框；从对话框里选范围，入口只有一个。真要导出别的章，先点开它再导出，只多一步。
- **写作开关勾上就存**：模型设置里"停止输入后自动续写""离开改过的章节时更新摘要"两个勾选框，以前勾了立刻在本次生效，却要点"保存作品模型选择"才写进 `.writer/desk.json`；不点保存就重开，开关又回去了。现在勾选即存。模型选择和上下文预算仍要点保存：那几项要校验、要一起生效。
  - 被放弃：**把两个开关挪出这张卡片** — 位置本身就暗示"和下面的保存按钮一起"。但它们讲的是写作模型怎么用，和模型选择放在一起读得通；改成勾上即存，位置就不再误导。
- **引用卡用现在的章名**：讨论里引用卡上的《章名》以前是引用那一刻的名字，章节改名后还挂着旧名（真机上一章叫"新章节"时引用的，改名后仍是《新章节》）。现在章节树认得这一章就用它现在的名字，章已删除或树还没读时才用存下来的旧名。会话文件里的 `title` 不改写，那是当时的记录。
- **今天写了多少**：正文页顶栏的字数后面加"· 今天 +N"，N 是全书字数减去今天第一次看到时的全书字数；为 0 时不显示。顶栏不到 760 宽（右栏开着的常见窗口）时不占位，只在字数的悬停提示里写"全书 N 字，今天 +N 字"；专注写作或宽窗口里直接显示。基准存在作品的 `.writer/desk.json`（`day` 本地日期、`day_start` 当时全书字数），关掉重开仍从今天开头算；日期变了，下一次看顶栏时重新取基准。删章、移进回收站会让它变少甚至为负，这是"净增"，不另做区分。计数还没读进来时不取基准，否则会把整本书都算成今天写的。
  - 被放弃：**按天记一份写作日志（每天多少字），做成日历或曲线** — 能看出连续写作的天数和习惯，是写作软件常见的激励。但那要新落盘格式、要决定跨机器怎么合并，眼下作者要的只是"今天写够没有"；`.writer/` 本来就不随作品同步，一个基准数就够。真要日志时再从这个基准扩展。
  - 被放弃：**只记本次打开以来的增量，不落盘** — 最简单，没有格式。但写作者一天会开关好几次，每次清零就答不了"今天"的问题。
- **Ctrl+N 新建章节**：正文页按 Ctrl+N，和点章节树上的"＋"一样，在打开的章后面（打开的是文件夹就在里面）新建一章并进入改名，编号照"新章接着编号"预填；正在改名时不响应，免得连按建出一串空章。"＋"的悬停提示写上了快捷键。快照弹框的说明里补上"全书替换之前"。
  - 被放弃：**Ctrl+N 新建作品** — 很多软件里 Ctrl+N 是"新文档"，对这里来说文档是作品。但新建作品一部书只做一次，而新建章节几乎每天都做；常用的那个配快捷键。
- **最近 7 天写了多少**：每日目标的弹框下面画最近 7 天的小柱状图，每天一根，下面是几号，悬停看"10月8日：+2100 字"；达到目标的那天是主题色，其余是浅灰；最高的柱子按 7 天里最多的那天和目标中较大的那个定。数据来源：作品打开着、到了新的一天第一次算"今天"时，把上一个记录日的"写了多少"（那时的全书字数减去那天的起点）记进 `.writer/desk.json` 的 `days`（日期 → 字数，留最近 60 个），再开始新的一天；今天的那根是实时的。作品没打开的日子是 0。
  - 被放弃：**按每次存盘记录时间线，再按天汇总** — 精确到每一次写作，也能画按小时的图。但要一个会一直变大的新文件，和"今天写了多少"这个已有的基准重复；按天一个数就够回答"这周写得怎么样"。
  - 被放弃：**单独做一个统计页** — 地方大，能放月历、累计曲线。但现在只有一个数一天，一页里装不满；放在每日目标旁边，看目标时正好看到最近的表现。
- **新章接着编号**：新建章节（或文件夹）时，看树里它前面最近的同类节点：标题以"第N章/卷/回/节/部/篇/集"开头（N 是中文数字或阿拉伯数字，一万以内），新节点就叫下一个号，比如"第四章 名单"之后是"第五章"，"第九十九回"之后是"第一百回"，"第12章"之后是"第13章"。改名框里预先填好"第五章 "，光标在末尾，接着打章名就行；直接回车就叫"第五章"。前面那个没有编号（"楔子""新章节"）时照旧叫"新章节"、框里空着。作者如果不看预填、整个打了"第五章 归来"，结果会成"第五章 第五章 归来"——所以预填后面跟着的又是一个带编号的标题时，丢掉预填（`numbering.go` 的 `numbered`，`rename` 里判断）。
  - 被放弃：**只把编号放在占位提示里，框里空着** — 不会和作者打的字叠在一起，也不用上面那条去重。但网文作者几乎每章都是"第N章 章名"，号是要的，放在占位里就得自己再打一遍；mygo 的输入框没有"全选预填"的接口，预填 + 去重是现有条件下打字最少的。
  - 被放弃：**按整本书的章节数编号** — 不依赖上一章的标题。但有楔子、番外、分卷重新计数的书，总数和章号对不上；跟着上一章走，作者自己的编号习惯不会被打乱。
- **Ctrl+S 立即保存**：正文页按 Ctrl+S，把正文、章纲、摘要当场写盘，记下光标，顶上提示"已保存。停笔片刻也会自动保存"（8 秒后自己消失）。AI 正在起草或有改写等着采纳时不动它，提示"等它结束会自动保存"——不像其他离开动作那样先停掉 AI。原来按 Ctrl+S 什么都不发生，习惯按它的作者会不确定到底存没存。
  - 被放弃：**什么都不做，靠自动保存** — 自动保存本来就可靠，多一个键是多余的。但 Ctrl+S 是写作者几十年的手指习惯，按了没有反应正是让人不安的地方；它的价值在那句确认。
  - 被放弃：**在顶栏字数旁闪一下"已保存"，不占横幅** — 不推动正文。但顶栏已经挤，窄窗口时放不下；横幅是软件里所有提示的统一位置。
- **章节记住光标**：离开一章时（换章、换页、关窗口、切作品，凡是先存正文的时候）记下光标位置，再打开这一章就把光标放回去并滚到那里。位置按章节 ID 存在 `.writer/desk.json` 的 `carets`，重开软件也在；章节已不在树里的位置顺手删掉。正文在外面改短了，位置会被夹到结尾。
  - 被放弃：**只在本次运行里记** — 不碰落盘格式，简单。但最常见的场景正是"昨天写到哪儿，今天打开接着写"，跨重启才是要紧的那一半。
  - 被放弃：**记滚动位置而不是光标** — 读者式的"看到哪儿"。但作者回来是要接着打字，光标在哪儿比页面停在哪儿要紧；光标放回去时编辑器本来就会把它滚进视野。
- **Ctrl+PageDown / Ctrl+PageUp 换章**：在正文页按这两个键打开章节树顺序里的下一章、上一章，跳过文件夹，到头就停。打开的是文件夹时，往下到它的第一章，往上到它前面那一章。编辑器只处理不带修饰键的 PageUp/PageDown（翻页），带 Ctrl 的交给页面。写完一章接着写下一章、或回头看上一章，不必离开键盘去点树。
  - 被放弃：**Ctrl+↑ / Ctrl+↓** — 更好按。但很多编辑器里它们是"按段落移动光标"或滚动，作者手上已有这个习惯；Ctrl+PageUp/PageDown 在浏览器、Word 里本来就是"上一个/下一个标签或页"。
- **每日目标**：点顶栏的字数弹出一个小框，填每天想写多少字，回车或点外面收起；留空就是不设。设了目标，宽顶栏显示"今天 +N / 目标"，写到了整串字数变成主题色；窄顶栏只在悬停提示里写。目标按作品存在 `.writer/desk.json` 的 `day_goal`，和"今天"的基准放在一起。填的不是整数时目标不变。
  - 被放弃：**进度条或圆环** — 一眼能看出完成了多少，是写作软件常见的做法。但顶栏已经挤，进度条要再占一块地方；一个数字加变色足够回答"写够没有"。
  - 被放弃：**目标放进模型设置页** — 设置集中在一处。但那一页讲的是模型，目标和字数紧挨着放，看到数字时顺手就能改。
- **卷也显示字数**：章节树里文件夹那一行显示它下面所有章节的字数之和（含子文件夹），和章节行同样的灰色小字。以前卷那一行是空的，想知道一卷写了多少只能逐章加。
- **专注写作**：正文页顶栏最右加一个按钮，收起左边的导航和章节树、右边的设定和讨论，只留顶栏和正文；再点一次（"退出专注"）回来。选中正文按 Ctrl+L 引用时自动退出，因为讨论在右栏里。章纲、摘要那一块最宽和正文一样（`editor.MaxTextWidth`，760）并居中，宽窗口里和正文对齐。F11 同样进出专注（按钮提示里写着），在正文里打字时也能按；Esc 不用来退出，它已经用来放弃 AI 的灰字续写，两件事抢一个键，按一下可能同时发生。状态不存盘，重开程序总是正常布局：专注是写一阵子的事，下次打开时作者未必还记得两栏被收起来了。
  - 被放弃：**只收起左栏，右栏另有按钮** — 和右栏现有的收起按钮正交，组合更灵活。但想专心写的人要点两处、记两处状态，一个按钮一次收干净更直接；只要右栏的人照旧用右栏自己的收起按钮。
- **记住窗口大小和位置**：主窗口用 mygo 的 `WindowOptions.StateKey`（"main"），关窗时把位置、大小、是否最大化写进用户数据目录的 `window-state.json`（Windows 上是 `%APPDATA%\writer\`），下次打开照原样恢复；屏幕换了放不下时 mygo 退回默认的 1280×820。以前每次打开都是 1280×820，拉宽、最大化都得重来。没有放进作品的 `.writer/`：窗口跟着这台电脑的屏幕走，不跟着作品走。
- **服务按名称选**：三个服务下拉（讨论、整理、写作）都显示服务名称，存的仍是 ID（`providerSelect`）。作品配置里的服务已经不在本机配置里时，下拉里显示它的 ID，不会被悄悄改掉。

## Alternatives considered

- **提示改成浮在角落、不占位置的 toast** — 不推挤页面，也是常见做法。但 mygo 没有现成的浮层提示，要自己算位置和层级，还要处理和弹窗、侧栏的遮挡；提示条现有的样式和关闭按钮已经够用，问题只在它不走。
- **所有页面都记，包括"模型设置"** — 完全回到离开时的样子。但改完模型就关掉程序的情况很常见，下次打开还停在设置页反而要多点一次。
- **模型框换成 `ui.Combobox`** — 点开就列出全部选项，不用自己搭。但 `Combobox` 只能选目录里的项，失焦时会把没匹配上的输入改回原值，而目录外的模型 ID（新出的、自定义服务的）必须能直接输入。
- **下拉里同时显示名称和 ID** — 名称重复时也分得清。但内置服务的名称不会重复，自定义服务的名称是作者自己起的，同时显示只会让下拉变挤。

## Consequences

- `desk.json` 多一个可选字段 `writing`。旧文件没有它时照常打开在"讨论"。
- 成功提示在 8 秒后消失，作者没看到也不会再出现；重要的结果（错误）仍然常驻。
- 两个服务名称相同时，下拉选到的是靠后的那个。目前内置服务的名称都不同，自定义服务出现重名再处理。
