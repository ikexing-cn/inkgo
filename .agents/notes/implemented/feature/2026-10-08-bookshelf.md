# Agent Note: 书架：看得到、找得回、管得了的作品列表

Status: implemented

## Problem

程序不记得任何作品。每次启动都停在欢迎页，作者要手填或浏览作品文件夹的路径；侧栏"切换作品"只是关掉当前作品、回到欢迎页。作者不知道自己有哪些作品、建在了哪里，也没有地方改名或整理。

方案在 2026-10-08 与作者逐条确认。

## Decision

### 清单

- 新包 `shelf` 管作品清单，存在全局目录 `providers.yaml` 旁边的 `works.json`（`shelf.File`）。内容是：
  - 每本作品的路径、最近打开时间，以及上次打开或关闭时缓存的作品名、体裁、字数；
  - 作品库位置；
  - 书架用列表还是卡片。
- 书架只读这份缓存，不逐本打开作品。界面在打开作品、切换、关闭、退出、改名时更新缓存（`remember`）。
- `works.json` 按严格格式读：未知字段、未知版本、相对路径都报错。读不了时界面提示，并且这次运行不再写它，免得把清单清空。
- 作品库默认是 `主目录\Documents\写作`（`shelf.DefaultLibrary`）。可以在书架顶部更改；改了只影响新建的默认位置，已有作品不搬家。
- 没有 `works.json`（第一次启动）时扫一遍作品库的直接子文件夹，带 `work.yaml` 的都加进来，然后写下清单；不扫整块硬盘。
- 路径比较在 Windows 和 macOS 上不分大小写。

### 书架页

- 取代欢迎页。启动时（没有 `-work` 参数）打开上次的作品（`OpenLast`）；没有，或者它的文件夹找不到了，进书架。
- 顶部："我的作品"、作品数和作品库路径、"更改"；右边是列表和卡片切换、"添加已有作品…"、"新建作品"。
- 每本显示首字图标、作品名、体裁、字数、最近打开时间，列表里还有浅灰的路径。按最近打开排序，没打开过的排在后面。
- "⋯"菜单：
  - 重命名（只改 `work.yaml` 里的作品名，没打开的作品也可以改）；
  - 在资源管理器中显示（macOS 上叫"在访达中显示"）；
  - 从书架移除（不删文件）。
- 找不到文件夹的作品变灰，点不开，标"找不到文件夹"，给"重新定位…"和"从书架移除"。新位置必须有 `work.yaml`；新位置已经在书架上时，两条合成一条。
- 书架为空时显示原来的标题和三条说明，以及"新建作品"和"添加已有作品…"。
- 需要系统对话框的按钮（选文件夹），在没有对话框的环境里不显示，和原来的"浏览…"一样。

### 新建作品

- 弹窗：作品名、体裁、位置。位置默认是"作品库\作品名"，跟着名字变；作者改过位置后就不再跟。位置必须不存在或是空文件夹，否则在创建前就用中文说明。
- 弹窗挂在根视图上，所以书架页和侧栏菜单都能打开它。

### 侧栏"切换作品"

- 作品名右边加了下拉箭头，点开是菜单：最近 5 本（当前这本打勾，找不到的不能选）、"新建作品…"、"全部作品…"（关掉当前作品，回书架）。
- 请求进行中仍然不能切换作品。

## Alternatives considered

- **只用作品库文件夹，扫描它下面的作品** — 不用另存清单，作品库就是真相。但放在作品库以外的作品就看不到了，作者的作品已经散在各处。
- **书架打开时逐本读作品，显示实时字数** — 永远准确。但每本都要校验全部文件、读全部章节，作品一多书架就慢；作品只在本程序里改，打开和关闭时更新缓存已经够准。
- **书架只做列表，或只做卡片** — 少一套布局。作者要两种都能选：作品少时卡片直观，多时列表信息密。
- **删除作品（移到系统回收站）** — 管理更完整。但作品是作者最重要的数据，误删代价太大；"从书架移除"加上自己在资源管理器里删已经够用。
- **重命名时文件夹一起改名** — 名字和文件夹一致。但文件夹可能被同步软件或别的程序占用，清单路径也得跟着改；作者可以关掉作品后自己改名，再"重新定位"。
- **启动时先进书架** — 每次都看得到全部作品。但平时打开程序多是接着写，书架一键就到。

## Consequences

- 全局目录多一个 `works.json`（schema 1）。坏了只会报错，不会被覆盖。
- 书架上的字数和作品名是缓存，作品在别处被改过时，要打开一次才更新。
- Windows 的"文档"目录可能被 OneDrive 重定向，`主目录\Documents` 不一定是作者在资源管理器里看到的"文档"，作者可以更改作品库。
- 测试用的作品库由 `desk.Library` 指到临时目录，第一次启动的扫描不会读到作者自己的作品。

## Testing

- `shelf/shelf_test.go`：
  - 清单写下再读回，按最近打开排序；更新一本时保留打开时间；
  - 重新定位，包括新位置已在书架上；移除；
  - 坏的 JSON、未知版本、未知字段、相对路径都报错，且不当成空清单；
  - 第一次启动只收作品库里直接带 `work.yaml` 的文件夹。
- `desk/welcome_test.go`：
  - 打开的作品记进书架；从侧栏菜单新建，位置跟着名字落在作品库里；
  - 侧栏菜单直接切换作品，"全部作品…"回书架；
  - 列表和卡片切换并记住；从书架移除不动文件夹；
  - 重新启动时打开上次的作品；
  - 文件夹被移走后变灰、点不开，重新定位后恢复；重命名写回 `work.yaml`；
  - 添加没有作品的文件夹会报错；书架移空后显示原来的欢迎内容；
  - 读不了的 `works.json` 报错，打开作品后也不被覆盖。
- `cmd/poc` 布局测试：同一配置目录下再开一个窗口显示书架，空配置目录显示欢迎内容。
- 截图（`SHOT=dir go test ./desk -run ShotShelf`）：列表、卡片、新建弹窗、空书架、侧栏作品名。侧栏菜单是系统原生菜单，无头测试截不到，由界面测试覆盖。
