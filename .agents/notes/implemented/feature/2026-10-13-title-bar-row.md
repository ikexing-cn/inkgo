# Agent Note: 标题栏自己占一行，放菜单

Status: implemented

## Problem

2026-10-09 起标题栏并进了各栏的顶部（[标题栏并进各栏顶部](../../archived/feature/2026-10-09-merged-title-bar.md)，这一篇取代它，那一篇同批归档）：窗口的三个按钮浮在工具栏或右栏那一行的右上角，省下一行的高度。用下来有三处不顺：

- 窗口按钮和功能按钮挤在同一行。工具栏、右栏的标签行、检查页的右半边都要给窗口按钮空出 150 宽；右栏收起、展开，这块空位就从右栏换到工具栏，功能按钮跟着挪。
- 「续写一句」「起草本章」「快照」「导出」「外观」没有自己的地方，收在工具栏的「更多」里；「快捷键」在换作品的菜单里。
- 「收起侧栏」只在有顶栏的两页（正文、讨论）能用：侧栏收起以后，「展开侧栏」要有一行可放。

作者 2026-10-13 拿另一个软件的截图问：「header要不要独立拆分出来……不把关闭按钮和功能区绑在一块。这样空间冗余更多，也能做……这样的传统菜单设计。」

先在原型里做出来（`AGENTS.md` 界面那节第 2 条）。作者看过，三处都答了：少 40 高「可以接受，但是我希望专注写作的情况下，这个也隐藏」；去掉「更多」「可以」；菜单的分法「可以，原型也可以先加上去撤销 重做」。同一天作者说「可以，改吧。同步原型设计到软件」，软件照原型改了。

## Decision

规则写在 `DESIGN.md` 的「标题栏」一节；原型是 `prototype/app.js` 的 `titlebar`，软件是 `desk/titlebar.go`。

- 标题栏自己占窗口最上面一行，高 40（`titleHeight`，和窗口按钮的高度一样），底色和侧栏相同，下面一条分隔线。
  - 左边：侧栏的开关，然后是「文件」「编辑」「视图」「帮助」四个菜单。
  - 右边：窗口的三个按钮。它们是系统画的，浮在页面上；这一行按 `c.TitleBar()` 报的宽度把右边留出来（macOS 上是左边）。中间空着，按住拖窗口（`DragWindow`）。
  - 它在 `App.View` 里画一次，在各页的上面：书架也有。
- 下面各栏不再给窗口按钮让位：工具栏、右栏的标签行右边的空位去掉，检查页右半边顶上的空位去掉，设置、作品分类、书架顶上那条透明的拖动区去掉。
- 侧栏的开关只有标题栏里这一个，每一页都在同一个地方，四页都能收起侧栏。
  - 书架没有侧栏可收，它是灰的，不拿掉（菜单不会跟着左右挪）。
  - 收没收起记在作品文件夹的 `desk.json` 里（`side_hidden`），和右栏收没收起记在一处；没有这个字段就是没收起。
  - 重命名、新建章节或文件夹要在树里那一行上打字：侧栏收着就先摆出来。
- 专注写作时标题栏也收起，只剩工具栏和正文。窗口的三个按钮回到工具栏那一行的右端，工具栏按 `c.TitleBar()` 给它们让位，这一行这时按住能拖窗口。菜单点不到，快捷键照常；F11 或工具栏上的「退出专注」回来。
- 菜单是命令的总表，每行带快捷键；这一页做不了的是灰的，不拿掉。
  - 文件：新建章节（Ctrl+N）、新建文件夹｜保存（Ctrl+S）、快照、导出…｜设置…
  - 编辑：撤销（Ctrl+Z）、重做（Ctrl+Y）｜查找替换（Ctrl+F）、重命名（F2）｜续写一句（Ctrl+J）、起草本章（没有章纲时灰着，右边写「请先填写章纲」）
  - 视图：收起/展开侧栏、收起/展开右栏、专注写作（F11）｜外观（跟随系统、浅色、深色）
  - 帮助：快捷键…（Ctrl+/）
  - 「撤销」「重做」没有可退、可重来的一步时是灰的（`Editor.CanUndo`、`Editor.CanRedo`）。
  - 「导出…」每一页都能点：不在正文页时只有「全书」可选，没有哪一章是「本章」（2026-10-16 起还有「指定范围」，见[导出成 Word](2026-10-16-export-to-word.md)）。
  - Ctrl+/ 原来只在侧栏在的时候管用，现在每一页、专注写作时都管用。
- 工具栏的「更多」去掉，里面的五样进了菜单；工具栏只剩 ‹ ›、查找、专注写作、展开右栏和待处理。换作品的菜单里的「快捷键…」挪到「帮助」。
- 开着一个菜单时，指针移到旁边的名字上就换过去；再点一下名字、按 Esc、点别处都收起。菜单是软件自己画的（[自己画菜单](2026-10-12-own-menus.md)的 `dropMenu`），最窄 220。
- 光标还给正文。按一下标题栏，键盘的焦点就从正文到了被按的那个名字上，菜单收起以后 mygo 把焦点还给那个名字，不还给正文；mygo 没有公开的办法让一个按钮按下时不拿焦点。所以标题栏自己记着（`barState`）：
  - 没有菜单开着、焦点也不在标题栏上的每一帧，记下正文这时有没有光标。
  - 菜单收起（选了一行、Esc、再点一下名字）、点了侧栏的开关、或者焦点落回标题栏的某个名字上时，原来有光标就还给正文。
  - 点了别处收起的不还：焦点该在点的那个地方。
  - 原型里原来也不还，软件做了以后照 `DESIGN.md` 补上，办法不同：按标题栏时不让浏览器挪焦点（`mousedown` 的 `preventDefault`）；重画时标题栏、主体、侧栏、正文那一页各有名字（`data-k`），有名字又不要了的节点（菜单后面那层遮罩）直接拿掉，不再把后面的挪到它前面去。原来菜单一开一关，正文那块就被重建或者挪一次，光标就丢了。
- 菜单里选的那一行晚一帧才做（`barAct`）。选的那一帧里焦点还在菜单上；对话框是在它出现的那一帧记下「关掉以后焦点还给谁」的，当帧就打开，记下的是已经没有了的菜单行，关掉以后焦点哪儿也不在。等到下一帧，光标已经回到正文，对话框关掉就还给正文，查找、重命名的输入框也是从正文手里接过焦点。mygo 在有点击的那一帧里会把界面再搭一遍，这一遍不算，要让过去。
- 右上角的提示往下挪 40，仍在顶栏下面。
- 弹出的菜单各自有名字（`dropMenu` 给面板加了 `c.Key`）。原来 mygo 按先后次序认它们；标题栏一下多了四个，次序会随哪个开着而变。

### 前后跳转

这一半是从被取代的那一篇搬过来的，做法没有变，只是按钮换了地方：

- ‹ › 在正文工具栏的最左边，「卷名 › 章名」的前面，只在正文页有；侧栏收起、专注写作时也在。原来在别的页点 ‹ 会先回到正文页再跳，现在别的页没有这两个按钮。
- 打开另一章时，当前这章记进「后退」，「前进」清空，和浏览器一样。最多记 50 章。
- 跳到的章已被删掉时跳过它，接着找前一个。
- 历史只在这次打开作品期间有效，不存盘；切换作品时随正文页状态一起清空。

## Alternatives considered

- **保持原来的样子（标题栏并在各栏顶部）** — 正文多 40 高，780 高的窗口里多一行多的字；这是作者 2026-10-09 自己定的。没有选：作者这次倾向拆开；并在一起的代价（三处让位、命令没地方放、侧栏只能在两页收）是每加一样东西都要再付一次的。
- **标题栏用系统的 32 高** — 只多占 32。没有选：窗口按钮的高度作者 2026-10-09 试过 32、52，定的是 40；菜单的字和侧栏开关在 32 高里上下只剩 2 的余量。作者要矮一点，改的是一个数。
- **拆开，但不放菜单，只放侧栏开关和作品名** — 少一套要维护的东西。没有选：拆开以后这一行左边大半是空的，而「更多」里那几样正缺地方；作者提的就是菜单。
- **菜单和「更多」都留着** — 老地方还找得到。没有选：同样五样东西在两处，改一处要记得改另一处；菜单每一页都在，「更多」只在正文页。
- **用系统的菜单栏** — 键盘（Alt、助记字母）和读屏都是现成的。没有选：`DESIGN.md` 定了菜单都自己画；系统菜单栏在标题栏下面另占一行，样子也跟不上深浅色。
- **把 ‹ ›、面包屑也搬进标题栏，省掉工具栏那一行** — 高度一行不多。没有选：标题栏是整个窗口的，面包屑和查找、待处理是正文这一页的；搬上去以后换到别的页它们要消失，又回到「窗口的」和「这一页的」挤在一行。
- **专注写作时留着标题栏** — 窗口按钮不用换地方，菜单也还点得到。原型里起先是这样做的，作者要它也收起：专注写作就是只看正文。
- **专注写作时连窗口的三个按钮也收起** — 最干净，像全屏。没有选：窗口还是一个普通窗口，没有这三个按钮就没法用鼠标最小化、关掉。
- **菜单里加关于、退出** — 传统菜单都有。没有加：软件还没有名字，「关于」没有东西可写；退出就是关窗口。
- **选了哪一行，当帧就做** — 少一个要记的状态，命令快一帧。没有选：从「帮助」打开快捷键一览、再按 Esc 关掉，光标不回正文，要再点一下才能接着打字；`TestTheBarGivesTheCaretBack` 就是在这一步上挂的。
- **不管焦点，菜单收起以后让它留在标题栏的名字上** — 不用记状态，是 mygo 本来的行为。没有选：点一下「视图」又收起，接着打字，字打不进正文；写作软件里这比多一个状态要紧。
- **自己画窗口按钮，标题栏完全照原型** — 原型里那三个按钮的样子、位置都是画出来的，软件能和它一模一样。没有选：最小化、最大化、贴边布局、按钮的悬停态都得自己做，各平台的习惯也不一样；系统的按钮和原型已经很接近。

## Consequences

- **收益**：
  - 窗口的和这一页的分开了：各栏不再给窗口按钮让位，右栏收起、展开时工具栏上的按钮不挪。
  - 每个命令在菜单里有一行，带快捷键；四页、书架上都看得到。
  - 侧栏在每一页都能收起，开关不换地方。
- **代价与已知上限**：
  - 正文少 40 高（专注写作时不少）。
  - 专注写作时菜单点不到，只会用菜单的人要先退出专注。进出专注写作，工具栏上的按钮要左右挪，给窗口按钮让位。
  - 「续写一句」「起草本章」在窗口左上角，离正文远；常用的话要回到工具栏上放一个。
  - 「帮助」里只有一行。
  - 键盘：Alt 打开菜单、左右键在菜单之间换，都没有做；菜单开着以后里面的键和别的菜单一样。
  - 「编辑」既是菜单的名字，也是「作品分类」和设置里一个文字按钮的名字，同一屏上会出现两个。测试里菜单的名字是 `菜单栏-编辑`，不会点错。
  - 菜单里选的命令晚一帧做，眼睛看不出来；测试里点完一行要多走一帧。
  - 光标还给正文靠的是每帧记一次焦点在哪。Tab 从正文走不到标题栏（正文自己收着 Tab），所以「焦点在标题栏的名字上」只会是点出来的；哪天正文放开 Tab，这一条要重看。
  - 2026-10-15 更正：上面说 mygo 没有让按钮按下时不拿焦点的办法，不对，有 `KeepFocus`。别的对话框入口现在用它（见[对话框关掉，键盘回原处](2026-10-15-dialogs-give-the-keyboard-back.md)）。标题栏没有改用它：菜单的第一行是 `AutoFocus` 的，mygo 记「浮层关掉以后焦点还给谁」是在建完浮层里面的东西之后，那时焦点已经在第一行上，记下的就是第一行，菜单一收焦点哪儿也不在。这里的 `barState` 正好绕开了它，所以留着。
  - 导出：开着一章时从菜单打开先选着「本章」，和原型一样（2026-10-13 随[多标签页](2026-10-13-chapter-tabs.md)改的，原来先选「全书」；2026-10-16 起又一律先选「全书」，见[导出成 Word](2026-10-16-export-to-word.md)）。
  - 「设置…」在书架上是灰的，和原型一样：设置是从一部作品里打开的。
  - 标题栏左边的开关和四个菜单一共 220 来宽，加上窗口按钮也比窗口能缩到的最窄宽度（1000）窄得多，不用折行。

## Verification

- `go test ./desk`（`desk/titlebar_test.go`）：
  - `TestTheTitleBarHasItsOwnRow`：标题栏在最上面一行，它下面的工具栏、右栏不给窗口按钮留位置；专注写作时没有标题栏，工具栏让出窗口按钮的宽度。
  - `TestTheSidebarIsPutAwayOnEveryPage`：四页都能收起、展开，记进 `desk.json`；书架上开关是灰的。
  - `TestTheMenusDoWhatTheySay`：四个菜单每一行做它说的事；撤销、重做没有可退的一步时是灰的；指针移到旁边的名字上换菜单；Esc、再点一下名字收起。
  - `TestMenuRowsOffThePageOfProse`：不在正文页时只管正文的那几行是灰的；导出只有全书。
  - `TestAMenuOpensOnASlowClick`：按下、过几帧再松开，菜单还是开着。
  - `TestTheBarGivesTheCaretBack`：开了菜单又收起、点了侧栏的开关、从菜单打开对话框再关掉以后，接着打的字进正文；点别处收起的不抢焦点。
- `TestChapterHistory`、`TestSideRowsOnEveryPage`：‹ › 只在正文页，后退、前进、跳过已删除的章。
- 原来点「更多」的测试改成点菜单（`clickMenu`）。
- `npm run verify-prototype` 的「the title bar, and the sidebar put away on every page」「the menus」：原型里的同样几条，包括用过标题栏以后光标还在正文。
- 截图核对了正文、讨论、检查、书架四处，四个菜单，侧栏收起，专注写作，设置，深色（`SHOT=<目录> go test ./desk -run TestShot`、`SHOT=<路径> go test -run TestLayout ./cmd/poc`）。
- 没有在真的窗口里点过：系统画的窗口按钮和这一行右边留的位置对不对得上，只由测试里 `SetTitleBar` 假装的宽度查过。
