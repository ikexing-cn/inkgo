# Agent Note: 又一次真机走查的修正：没说过话的讨论不进列表也不再新开、侧栏讨论写日子

Status: implemented

## Problem

2026-10-16 作者授权自主改进体验，agent 用 kimi-cu 在真实窗口里打开 `cmd/sample` 的测试作品，从头点了一遍。截图测试和单测看不出以下别扭，只有真的用起来才碰得到：

- 讨论页侧栏的"＋"每点一次就建一个新对话，正文页右栏的"新讨论"也是。点了不说话再点，列表里就多出一串叫「新对话」的空行，只能一条条右键收起。
- 讨论页侧栏的讨论行写"10-16 00:42"，右栏的讨论列表和原型写"今天 / 昨天 / 10-14"。同一份列表两处写法不同，几点几分对找一段讨论也没有用。
- 一段讨论在作者去了别处时说出第一句（右栏发出后切到讨论页的另一段），侧栏里它还叫「新对话」，要等下次重开作品才改成那句话。

## Decision

- **没说过话的讨论不进列表**：`App.blank` 记着哪些讨论还一句话都没有（和 `titles` 一起在 `refresh` 里读）。讨论页侧栏和右栏的讨论列表都不列它们；当前打开的就是空讨论时，列表里没有高亮的那行，页面本身就是空讨论的样子。
- **新开讨论先用空着的那段**：侧栏"＋"、右栏"新讨论"都走 `blankSession`：当前这段是空的就留在这里；否则用任意一段没收起的空讨论；都没有才 `Store.NewSession`。所以连点"＋"不会多出文件，空讨论在一部作品里最多一段（以前点出来的旧空文件也会被先用掉）。收起的空讨论不拿来用：作者收起了它，就不让它回来。
- **收起后换到有话的讨论**：收起正打开的那段时，换到最近一段没收起、说过话的；都没有才新开（仍走 `blankSession`），不会换进一段空讨论又被当成"还在列表里"。
- **回复中的讨论标题跟着更新**：`refresh` 每次都重读正在回复的那段（`talkSession`）的标题和是否为空，作者在别处时它说出的第一句也立刻成为侧栏里的标题。
- **侧栏讨论写日子**：讨论页侧栏的讨论行和右栏一样用 `talkDay`：今天、昨天、月-日。

## Alternatives considered

- **空讨论照样列出，只是不让"＋"重复建** — 列表里始终看得到"我开了一段新的"，和多数聊天软件一样。但空讨论没有标题可写，只能叫「新对话」，和"当前没高亮任何一行"相比只多了一个没内容的行；原型里点"＋"也只打开一段新讨论的样子，列表里不加行。
- **关掉空讨论时删掉它的文件** — 磁盘最干净。但讨论文件是作品格式的一部分，删文件要处理"正在回复时被删""外面同步过来又出现"这些情况；留着一个空文件、下一次新开时复用，什么都不用删。
- **侧栏照旧写到分钟** — 同一天里多段讨论分得更细。但列表是按时间排的，先后已经看得出；几点几分要从左往右读才知道是哪天，日子才是找讨论时用得上的。

## Consequences

- 新开讨论不再产生多余的空文件；`Store.Sessions` 照旧全列，界面自己滤掉。
- 测试作品或旧版留下的多个空讨论，界面上都看不见，新开时逐个用掉。
- 右键收起的计数（"已收起 N 段对话"）不算空讨论。
