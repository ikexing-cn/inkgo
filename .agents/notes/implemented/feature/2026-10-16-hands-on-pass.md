# Agent Note: 又一次真机走查的修正：没说过话的讨论不进列表也不再新开、时间都按离今天多远写、新名字跨章只列一条、类似情况只算同一句设定

Status: implemented

## Problem

2026-10-16 作者授权自主改进体验，agent 用 kimi-cu 在真实窗口里打开 `cmd/sample` 的测试作品，从头点了一遍。截图测试和单测看不出以下别扭，只有真的用起来才碰得到：

- 讨论页侧栏的"＋"每点一次就建一个新对话，正文页右栏的"新讨论"也是。点了不说话再点，列表里就多出一串叫「新对话」的空行，只能一条条右键收起。
- 讨论页侧栏的讨论行写"10-16 00:42"，右栏的讨论列表和原型写"今天 / 昨天 / 10-14"。同一份列表两处写法不同，几点几分对找一段讨论也没有用。
- 一段讨论在作者去了别处时说出第一句（右栏发出后切到讨论页的另一段），侧栏里它还叫「新对话」，要等下次重开作品才改成那句话。
- 检查全书后，「老周」在第四章、第七章各被查出是新名字，检查页列了两条「新出现」。第二条写"「第七章 老陈」起出现"，其实第四章就有了；作者对第一条点「忽略」，第二条还在，同一个决定要做两遍。原来的决定是"一章一条，不合并"（[正文和设定的检查](2026-10-10-consistency-check.md)），不一致的地方按章分开有道理，新名字是加不加进设定的事，跟章无关。
- 「林晚是左撇子，这里却用右手握螺丝刀」的详情下面，"其他章节的类似情况"列的是第八章「一个人走进了没有灯的巷子」。那是林晚怕黑的问题，只因两条都对着「人物 · 林晚」这一条设定就算成类似。一条人物设定常写好几件事，按条比太粗。
- 改写和起草的进度条、快照里的 AI 记录写"deepseek/deepseek-flash · Default"：斜杠前是服务的 ID。设置里、讨论的模型菜单里服务都按名称写（DeepSeek），原型这里也是"服务名/模型"。
- 原型里改写要求空着也能点"改写"；软件里按钮是灰的，`writing.Rewrite` 也拒绝空要求（"请写下要怎么改"）。
- 检查详情里，新名字右边那张卡片（"可加入设定 · 人物"）比左边的正文卡片高出五像素：左边标题行有"查看原文"链接，右边没有，标题行矮一截。
- 起草本章的对话框写"用 deepseek/deepseek-flash · 推理 Default"，上面那条改成服务名时漏了这一处。
- 时间的写法各处不同：备份写"今天 10:32""昨天 23:15"，回收站、设定的修改记录、本章摘要的来源、"已恢复到……的版本"写"10-16 01:34"，快照列表写到秒"10-16 01:34:05"，书架又是另一套。作者看"10-16"还得想一下是不是今天。备份那套在一月会写成"1-06 08:05"（月份没补零）。原型新做的事写"刚刚"，和书里带来的"今天 10:20"摆在一起。
- 正文页右栏的讨论框，软件里回车换行、Ctrl+Enter 发送，框里框外都没写；原型里那是一行输入框，回车就发出去。讨论页的框旁写着"Ctrl+Enter"，快捷键列表也写"讨论 · Ctrl+Enter 发送"。作者在右栏按回车，等着发出去，结果只是换了一行。
- 在书架上新建一部作品，打开后讨论框下面是黄色的「选择讨论模型」：模型按作品记在 `work.yaml`，新作品是空的，作者得再去菜单里挑一遍上一部书一直在用的那个。原型里新建的书沿用已选的模型（`uses` 在 `KEPT` 里）。

## Decision

- **没说过话的讨论不进列表**：`App.blank` 记着哪些讨论还一句话都没有（和 `titles` 一起在 `refresh` 里读）。讨论页侧栏和右栏的讨论列表都不列它们；当前打开的就是空讨论时，列表里没有高亮的那行，页面本身就是空讨论的样子。
- **新开讨论先用空着的那段**：侧栏"＋"、右栏"新讨论"都走 `blankSession`：当前这段是空的就留在这里；否则用任意一段没收起的空讨论；都没有才 `Store.NewSession`。所以连点"＋"不会多出文件，空讨论在一部作品里最多一段（以前点出来的旧空文件也会被先用掉）。收起的空讨论不拿来用：作者收起了它，就不让它回来。
- **收起后换到有话的讨论**：收起正打开的那段时，换到最近一段没收起、说过话的；都没有才新开（仍走 `blankSession`），不会换进一段空讨论又被当成"还在列表里"。
- **回复中的讨论标题跟着更新**：`refresh` 每次都重读正在回复的那段（`talkSession`）的标题和是否为空，作者在别处时它说出的第一句也立刻成为侧栏里的标题。
- **侧栏讨论写日子**：讨论页侧栏的讨论行和右栏一样用 `talkDay`：今天、昨天、月-日。
- **新名字跨章只列一条**：
  - `listedChecks` 把同名的「新出现」并到书里最早的那一条（`checkItem.also` 记着后面几章的）。检查页、待处理、侧栏"检查"的条数都用它；正文里的虚线和章末"本章有 N 处待处理"仍按章算（`checkItems`），第七章里的「老周」照样画虚线。
  - 列表第二行写"人物 · 「第四章 钟表铺」起出现，共 2 章"，只出现在一章时不写"共"。详情的正文卡片是第一次出现的那句，下面"其他章节中也出现"列出后面几章的原句（不一致那里同样位置写的是"其他章节的类似情况"，并带处理状态；新名字没有各章分开的状态，不写）。
  - 「忽略」照旧只给第一条记 `meant`，但 `checkItems` 把记过 `meant` 的新名字在所有章里都当作已忽略，以后别的章再查出它也不列。「加入设定」本来就按名字消掉各章的。
  - 待处理里这一条在打开的章也有时，算"本章"的，点开到这一章的那句；忽略用的键仍按第一条，换章不会让它回来。
  - 原型同步：何主任那条带上第 86 章，列表写"共 2 章"，详情列出第 86 章的原句；原来的"起出现 4 次"去掉。
- **类似情况只算同一句设定**：不一致的详情列"其他章节的类似情况"时，除了同一条设定，还要两条所指的设定原话（`Says`）落在设定的同一句里（`overlap`：各自向两边扩到句号、问号、感叹号、分号或换行，两段相交）。"怕黑"和"天黑以后不进没有灯的巷子"在一句里，算类似；"怕黑"和"左撇子"不算。哪一条没给原话或原话在设定里找不到，照旧算类似。
- **模型写服务名**：`modelLabel` 把记录里的"服务 ID/模型"换成"服务名/模型"，本机配置里已经没有那个服务时照旧写 ID。记录本身（快照、`AIRecord.Model`）不改，仍存 ID。
- **原型照软件：改写要写要求**：原型的"改写"在要求空着时不可点，回车也不发；`walk.ts` 打开改写栏时核对按钮是灰的。软件这边不动：改写是照作者的话改，空着发出去模型只能自己猜要改什么。
- **卡片标题行一样高**：检查详情两张卡片的标题行最低 22（带链接时的高度），有没有链接都对齐。
- **起草对话框也写服务名**：`serviceModel` 从 `modelLabel` 拆出来，起草对话框那一行也用它。续写采纳时记在标记里的仍是 ID：那是记录，界面上不显示。
- **时间都按离今天多远写**（`DESIGN.md` 文案一节新加一条）：
  - `desk/when.go` 的 `dayOf` 写哪天：今天、昨天，今年的"10-06"，往年的"2025-10-06"。`when` 在后面加几点，用于备份、回收站、修改记录、摘要来源、快照列表、恢复快照的提示；`opened`（书架）今天、昨天写几点，更早的只写哪天；`talkDay`（讨论列表）只写哪天。原来分散在 backup.go、welcome.go、beside.go 的三个各写各的，合成这一处。
  - 讨论的标题只存第一句话，不再在前面拼"10-16 00:42 · "再由 `sessionParts` 拆开；列表上的日子由 `talkDay` 从讨论的 ID（建立的时刻）算，跨年也不会错。
  - 原型：`BOOK.clock` 是假书里的"现在"（10:40），新做的事（备份、快照、回收站、修改记录、AI 摘要、新作品）都记成"今天 10:40"，不再写"刚刚"。
- **讨论框都是 Ctrl+Enter 发送**：右栏和讨论页一样，回车换行，Ctrl+Enter 发出去。右栏窄，没地方像讨论页那样在发送键旁写"Ctrl+Enter"，就写在框里的提示后面（"输入消息，Ctrl+Enter 发送"）；两处发送键的悬停提示都写"发送（Ctrl+Enter）"。原型右栏的框改成多行、跟着字长高（最多七行，和软件一样），按键共用 `sendKey`。

- **新作品沿用模型**：`create` 建好作品后，把讨论和写作的模型照搬进新的 `work.yaml`（`lastModels`）：有作品开着就用它的；从书架上新建时，用书架上最近打开、讨论模型的服务还在本机配置里的那一部（`workspace.ReadWork` 只读 `work.yaml`，不打开作品）。写作模型的服务不在了就留空（空着即用讨论模型）。都没有时照旧空着，讨论框里写「选择讨论模型」。之后各作品各改各的，互不影响。

- **没开作品时窗口叫「写作软件」**：书架页和启动时的窗口标题原来写"写作"，任务栏上看像个动词；照 `DESIGN.md` 软件没名字时写"写作软件"。

## Alternatives considered

- **空讨论照样列出，只是不让"＋"重复建** — 列表里始终看得到"我开了一段新的"，和多数聊天软件一样。但空讨论没有标题可写，只能叫「新对话」，和"当前没高亮任何一行"相比只多了一个没内容的行；原型里点"＋"也只打开一段新讨论的样子，列表里不加行。
- **关掉空讨论时删掉它的文件** — 磁盘最干净。但讨论文件是作品格式的一部分，删文件要处理"正在回复时被删""外面同步过来又出现"这些情况；留着一个空文件、下一次新开时复用，什么都不用删。
- **新名字照设计稿写"起出现 N 次"** — 次数比章数更能看出这个名字分量多重。但检查只知道各章查出了它，要数次数得把全书正文读一遍，每查完一章就重读一次；章数是检查结果里现成的，"出现在几章"也足够说明它不是一闪而过。
- **把各章的新名字在检查时就合并（发给模型已知的新名字）** — 从源头上不重复，`.check.json` 里也只有一条。但每章的检查是独立的、可以单独重查，合并在文件里就要处理"第四章改了、那一条被删"时第七章那条要不要补回来；在显示时合并，各章文件照旧只管自己。
- **类似情况按原话逐字相交来算** — 最直接，不用管句子。但模型给同一件事引的原话长短不一，"怕黑"和"天黑以后不进没有灯的巷子"说的是一回事却不相交，会把真正的类似情况漏掉；人物设定里一句话通常就是一件事，按句算更贴近。
- **侧栏照旧写到分钟** — 同一天里多段讨论分得更细。但列表是按时间排的，先后已经看得出；几点几分要从左往右读才知道是哪天，日子才是找讨论时用得上的。
- **一分钟内写"刚刚"** — 原型就是这么写的，读起来最有"刚做完"的感觉。但它会自己变：摆在屏幕上的"刚刚"过一分钟要变成"今天 10:41"，得有个钟一直叫界面重画；作者刚做完的事，"今天 10:40"也一样看得出是刚才。原型那样写是因为它没有真的钟，改成记假书里的"现在"。
- **右栏回车就发，照原型** — 右栏是随手问一句的地方，一行框回车发出最省事，许多聊天软件也是这样。但同一段讨论在两处用两种键，作者在讨论页按惯了回车换行，到右栏会把半句话发出去；反过来在讨论页按回车等着发，又只换了行。一段话常要分几行写，回车拿去发送，换行就得另记 Shift+Enter。
- **新作品的模型留空，让作者每部书自己挑** — 不同的书可能想用不同的模型（长篇用便宜的，短篇用贵的），空着能提醒作者这是这部书自己的设置。但多数人只配了一两个服务，每建一部书都把同一个模型再挑一遍只是多一步；沿用之后想换，讨论框下面的菜单一点就换，也只改这一部。
- **把模型记在本机的偏好里，不再按作品记** — 一处改、处处生效，最省事。但作品文件夹搬到另一台电脑、或和别人共用时，`work.yaml` 里的选择跟着书走才说得清这部书用的是什么；按作品记是原来的格式，改了要迁移。
- **快照列表照旧写到秒** — 同一分钟里存的两份（打开时一份、紧接着 AI 改写前一份）标题不会一样。但每份下面还写着"打开时""AI 改动前"和字数，分得开；到秒的六位数字让一列时间更难扫，原型也只写到分。

## Consequences

- 新开讨论不再产生多余的空文件；`Store.Sessions` 照旧全列，界面自己滤掉。
- 测试作品或旧版留下的多个空讨论，界面上都看不见，新开时逐个用掉。
- 右键收起的计数（"已收起 N 段对话"）不算空讨论。
- 「忽略」一个新名字后，它在任何一章都不再报；要找回只能删掉那一章的 `.check.json` 里那条的 `meant` 或重新查那一章（重查时原句没变会把 `meant` 带过去）。
- 检查页的条数可能比各章章末的条数加起来少：同一个新名字在章末各算一处，在检查页只算一条。
