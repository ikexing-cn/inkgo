## Decision

- **没说过话的讨论不进列表**：`App.blank` 记着哪些讨论还一句话都没有（和 `titles` 一起在 `refresh` 里读）。讨论页侧栏和右栏的讨论列表都不列它们；当前打开的就是空讨论时，列表里没有高亮的那行，页面本身就是空讨论的样子。
- **新开讨论先用空着的那段**：侧栏"＋"、右栏"新讨论"都走 `blankSession`：当前这段是空的就留在这里；否则用任意一段没收起的空讨论；都没有才 `Store.NewSession`。所以连点"＋"不会多出文件，空讨论在一部作品里最多一段（以前点出来的旧空文件也会被先用掉）。收起的空讨论不拿来用：作者收起了它，就不让它回来。
- **收起后换到有话的讨论**：收起正打开的那段时，换到最近一段没收起、说过话的；都没有才新开（仍走 `blankSession`），不会换进一段空讨论又被当成"还在列表里"。
- **回复中的讨论标题跟着更新**：`refresh` 每次都重读正在回复的那段（`talkSession`）的标题和是否为空，作者在别处时它说出的第一句也立刻成为侧栏里的标题。
- **侧栏讨论写日子**：讨论页侧栏的讨论行和右栏一样用 `talkDay`：今天、昨天、月-日。
- **新名字跨章只列一条**：
  - `listedChecks` 把同名的「新出现」并到书里最早的那一条（`checkItem.also` 记着后面几章的）。检查页、待处理、侧栏"检查"的条数都用它；正文里的虚线和章末"本章有 N 处待处理"仍按章算（`checkItems`），第七章里的「老周」照样画虚线。
  - 列表第二行写"人物 · 「第四章 钟表铺」起出现，共 2 章"，只出现在一章时不写"共"。详情的正文卡片是第一次出现的那句，下面"其他章节中也出现"列出后面几章的原句（不一致那里同样位置写的是"其他章节的类似情况"，并带处理状态；新名字没有各章分开的状态，不写）。
  - 「忽略」照旧只给第一条记 `meant`，但 `checkItems` 把记过 `meant` 的新名字在所有章里都当作已忽略，以后别的章再查出它也不列。「加入设定」本来就按名字消掉各章的。
  - 待处理里这一条在打开的章也有时，算"本章"的，点开到这一章的那句；忽略用的键仍按第一条，换章不会让它回来。
  - 原型同步：何主任那条带上第 86 章，列表写"共 2 章"，详情列出第 86 章的原句；原来的"起出现 4 次"去掉。
- **类似情况只算同一句设定**：不一致的详情列"其他章节的类似情况"时，除了同一条设定，还要两条所指的设定原话（`Says`）落在设定的同一句里（`overlap`：各自向两边扩到句号、问号、感叹号、分号或换行，两段相交）。"怕黑"和"天黑以后不进没有灯的巷子"在一句里，算类似；"怕黑"和"左撇子"不算。哪一条没给原话或原话在设定里找不到，照旧算类似。
- **模型写服务名**：`modelLabel` 把记录里的"服务 ID/模型"换成"服务名/模型"，本机配置里已经没有那个服务时照旧写 ID。记录本身（快照、`AIRecord.Model`）不改，仍存 ID。
- **原型照软件：改写要写要求**：原型的"改写"在要求空着时不可点，回车也不发；`walk.ts` 打开改写栏时核对按钮是灰的。软件这边不动：改写是照作者的话改，空着发出去模型只能自己猜要改什么。
- **卡片标题行一样高**：检查详情两张卡片的标题行最低 22（带链接时的高度），有没有链接都对齐。
- **起草对话框也写服务名**：`serviceModel` 从 `modelLabel` 拆出来，起草对话框那一行也用它。续写采纳时记在标记里的仍是 ID：那是记录，界面上不显示。
- **时间都按离今天多远写**（`DESIGN.md` 文案一节新加一条）：
  - `desk/when.go` 的 `dayOf` 写哪天：今天、昨天，今年的"10-06"，往年的"2025-10-06"。`when` 在后面加几点，用于备份、回收站、修改记录、摘要来源、快照列表、恢复快照的提示；`opened`（书架）今天、昨天写几点，更早的只写哪天；`talkDay`（讨论列表）只写哪天。原来分散在 backup.go、welcome.go、beside.go 的三个各写各的，合成这一处。
  - 讨论的标题只存第一句话，不再在前面拼"10-16 00:42 · "再由 `sessionParts` 拆开；列表上的日子由 `talkDay` 从讨论的 ID（建立的时刻）算，跨年也不会错。
  - 原型：`BOOK.clock` 是假书里的"现在"（10:40），新做的事（备份、快照、回收站、修改记录、AI 摘要、新作品）都记成"今天 10:40"，不再写"刚刚"。
  - 讨论里每一句话下面（作者的和 AI 的）也用 `when`："今天 00:50"。原型里每句话记着自己的 `at`（"昨天 22:11"），新说的记 `stamp()`；讨论自己的 `at` 只是哪天，列表里写它。
  - 「最近 7 天」各天和最早的备份只说哪天，用 `dayOf`："今天""昨天""10-14"，往年的带年份（"2025-10-03"）。备份那句抽成 `kept`。原型的 `BOOK.days` 和"最早 09-28"同样。
- **起草对话框的思考程度不带前缀**："用 DeepSeek/deepseek-flash · High；可在设置中「AI」配置里更换。"，和进度条一样；设置里下拉框的读屏名字改成"讨论的思考程度""写作的思考程度"，和原型一样。DESIGN.md 那条把"推理"也写进不要加的前缀里。
- **作品分类的表单说出是加还是改**：名称不空时，表单下面用灰字写"将添加新分类。"，或"将修改已有的分类“人物”，现在的落点是“设定库”。"；标签改回"名称"，括号里那句由这行说了。和新建作品对话框位置下的"将新建该文件夹。"一个做法。DESIGN.md 表单那条加上：填的会动到已有的东西，在表单下面用灰字说明。原型同样。
- **讨论框都是 Ctrl+Enter 发送**：右栏和讨论页一样，回车换行，Ctrl+Enter 发出去。右栏窄，没地方像讨论页那样在发送键旁写"Ctrl+Enter"，就写在框里的提示后面（"输入消息，Ctrl+Enter 发送"）；两处发送键的悬停提示都写"发送（Ctrl+Enter）"。原型右栏的框改成多行、跟着字长高（最多七行，和软件一样），按键共用 `sendKey`。

- **新作品沿用模型**：`create` 建好作品后，把讨论和写作的模型照搬进新的 `work.yaml`（`lastModels`）：有作品开着就用它的；从书架上新建时，用书架上最近打开、讨论模型的服务还在本机配置里的那一部（`workspace.ReadWork` 只读 `work.yaml`，不打开作品）。写作模型的服务不在了就留空（空着即用讨论模型）。都没有时照旧空着，讨论框里写「选择讨论模型」。之后各作品各改各的，互不影响。

- **稿纸一列**（`DESIGN.md` 布局一节新加一条）：`overProse` 是和正文同宽、同左边的一列（两边 `editor.PadX`，最宽 `editor.MaxTextWidth`，居中），章标题和章纲、AI 那条都放在里面；AI 那条照原型成了卡片（边框、`rCard`、`side` 底色）。卷页两边也改成 `editor.PadX`，卷名和章名一样 700 粗。
- **查找条在标签条下面**：照原型挪到章标题上面，一整条 `side` 底色、下面一道线。章标题那一块给了 key（`head`），查找条来去时章纲框里的光标不丢。
- **浮条不盖住选中的字**：上面放不下时放到整段选区下面（`RangeBox`）；选区下面也出了视野才照旧放在第一行下面。
- **选中的字就是要找的**：`openFind`（Ctrl+F、工具栏、编辑菜单都走它）在选区不跨段时拿选中的字当查找词，从选中的那一处数起（"2 / 2"）；查找框里的字全选上，接着打就换掉。查找条开着时再按 Ctrl+F，光标回到查找框。原型同样（`openFind`）。

- **没开作品时窗口叫「写作软件」**：书架页和启动时的窗口标题原来写"写作"，任务栏上看像个动词；照 `DESIGN.md` 软件没名字时写"写作软件"。
- **没有 `sessions/` 也能打开**：`workspace.Open` 只在 `sessions/` 存在却不是文件夹时报错；不在就当还没有讨论，`NewSession` 先建它；`.writer/` 不在，`savePrefs` 存 `desk.json` 前先建它。`chapters/`、`.writer/` 原来就不是非有不可。打开作品失败时，提示的标题写"打开作品「书名」失败"（取文件夹名），详情是原来的错误。
- **本机第一次打开的作品先进正文**：照原型。`.writer/desk.json` 还没有时当作上次停在正文（`prefs{Writing: true}`），之后照旧回到上次停在的讨论或正文。新建的作品也先进正文（暂无章节、新建第一章）。
- **设定里已有东西的作品，空讨论接着往下聊**：标题"接着聊这部作品"，说明"AI 会参考已有的设定和正文。"，示例问题换成"接下来的情节怎么走""哪些设定还没想清楚""梳理一下人物关系"。设定还空着才写"从一个初步的想法开始"和原来那三句。原型同样（`begun`）。
- **导出默认段首空两格**：每次打开导出对话框都勾着「段首加两个全角空格」，照原型；不要的作者取消勾选。
- **提示条按说的事配图标**（`DESIGN.md` Components 的「提示条」）：软件多一种 `hint`（`a.hint`），不带图标，和做完了的一样三秒消失。"请先在正文中选中……"两句、"设定为空，无可对照内容""各章均已检查，正文无新改动""该作品已在书架上""该段原文已修改，在本章中未找到"改用它；作品分类表单没填完（分类名、落点）原来报错（红色、带"复制详情"），也改成提醒。原型里做完了的提示都标成 `ok`，出错的图标改成 `danger`。
- **倒计时细线用 `faint`**：提示条上只有图标带颜色，做完了和提醒都三秒消失，线一样是灰的。
- **检查失败不当作没查出问题**：右边空着、又有一章检查失败（不在检查中）时，标题写"检查未完成"，图标换成警告，下面写"「某章」检查失败：……"；几章失败时说书里排最前的那章。原型同样改，正在检查时两边都只说"正在检查…"。
- **整份设定里每条带名字**：`prompt.Whole` 在有名字的条目前面写全部名字（顿号隔开）和冒号，"林晚、晚晚：主角，二十六岁……"。讨论、续写、改写、起草发的整份设定和"AI 参考内容"里的列表都用它，讨论规则那一句说明冒号前是名字、第一个是正式名称。已经存下的旧回复，列表照旧（记录是发的时候写的）。原型的列表同样改。
- **「保存分类」名称和落点都填了才能点**：软件和原型都这样，和别的表单一致。`saveCategory` 和原型的 `saveCat` 里那两句提醒留着，原型在落点里按回车仍走它。
- **答案带着它回答的问题发**：`prompt.Text` 是条目的内容一行，答案后面加"（回答：问题）"，和右栏的写法一样。`Whole`、检查的条目行、look_up_setting 的结果和它的匹配都用它；讨论规则那一句说明括号里的是作者回答的问题。目录行（`Short`）仍只有答案的第一句，要看全文用 look_up_setting。原型"AI 参考内容"的列表同样改。
- **表单里就说出按下去以前就知道的事**（`DESIGN.md` Components 的「表单」）：要填的空着，主按钮灰；填的用不了，那一栏下面红字写为什么、怎么办，主按钮也灰。新建作品的位置下面按磁盘上的实际情况写："将新建该文件夹。""该文件夹为空，作品将建在其中。"，用不了的"该文件夹中已有文件""该位置是一个文件""无法打开该文件夹"（后面都接"请更换名称或位置。"）是红字，空着写"请填写作品位置。"。`placeFor` 是唯一的判断：对话框在位置改了以后看一次磁盘（不每帧看），`create()` 按下时再看一次兜底。原型同样，三个按钮灰着点不动。`create()` 里按 `a.path` 建作品那条路界面上早已走不到，删掉。
- **模型服务表单随填随说**：`model.Check` 按栏给出存不下的原因（ID、名称、协议、地址、环境变量、模型），`validateProvider` 就是取它的第一条；`aiport.Service.Check` 把它交给界面。表单每帧算一次（`serviceInForm`）：ID 有问题在 ID 那一排下面红字，地址有问题红字代替"远程服务…"那句，环境变量在它的框下面，模型在表下面；空着的只让按钮灰。新服务 ID 和已有的重了说"该 ID 已被「DeepSeek」使用，请换一个"。新服务的 ID 空着时按名称取（`idFrom`：拉丁字母小写，从第一个字母起留数字、- 和 _，空格当 -），取出的摆在 ID 框里做占位字；名称里没有拉丁字母就取不出，要自己填。原型同样。模型 ID 和后面的中文之间空一格。
- **服务表单打开就在眼前，新的能收回**：点「编辑」或「添加服务」后，那张卡片滚进视野（`ScrollIntoView`，比视野高就从卡片顶上露起；`bk.shown` 记着上一帧开着的是哪个，只在刚换的那一帧滚）。新服务的按钮行最左多一个「取消」，收起表单、什么也不存——已有服务有上面的「收起」，新的没有。新服务的 key 框写"留空则不用 key"。地址的毛病按作者要改的地方分开说（`model.checkBaseURL`）："API 地址须以 http:// 或 https:// 开头""API 地址里没有域名""API 地址不能带账号、查询参数或锚点"；环境变量说"环境变量名只能用字母、数字和 _，不能以数字开头"，和 ID 那句一个说法。原型同样（`data-reveal`）。
- **目标字数和每日目标同一个读法**：`countOrNone`（原型同名）——空着算没有，填了要是正整数，0 也不算。起草对话框不对时框下红字"目标字数须为正整数，或留空"，「开始起草」灰；每日目标不对时框下那句说明换成红字"每日目标须为正整数，留空则不设。"，目标照旧是上一次填对的数。原型另记 `goalSet`（填对的那个），字数旁边用它。原来每日目标填 0 等于不设，现在 0 不算数、要清空才是不设。

## Alternatives considered

- **空讨论照样列出，只是不让"＋"重复建** — 列表里始终看得到"我开了一段新的"，和多数聊天软件一样。但空讨论没有标题可写，只能叫「新对话」，和"当前没高亮任何一行"相比只多了一个没内容的行；原型里点"＋"也只打开一段新讨论的样子，列表里不加行。
- **关掉空讨论时删掉它的文件** — 磁盘最干净。但讨论文件是作品格式的一部分，删文件要处理"正在回复时被删""外面同步过来又出现"这些情况；留着一个空文件、下一次新开时复用，什么都不用删。
- **新名字照设计稿写"起出现 N 次"** — 次数比章数更能看出这个名字分量多重。但检查只知道各章查出了它，要数次数得把全书正文读一遍，每查完一章就重读一次；章数是检查结果里现成的，"出现在几章"也足够说明它不是一闪而过。
- **把各章的新名字在检查时就合并（发给模型已知的新名字）** — 从源头上不重复，`.check.json` 里也只有一条。但每章的检查是独立的、可以单独重查，合并在文件里就要处理"第四章改了、那一条被删"时第七章那条要不要补回来；在显示时合并，各章文件照旧只管自己。
- **类似情况按原话逐字相交来算** — 最直接，不用管句子。但模型给同一件事引的原话长短不一，"怕黑"和"天黑以后不进没有灯的巷子"说的是一回事却不相交，会把真正的类似情况漏掉；人物设定里一句话通常就是一件事，按句算更贴近。
- **侧栏照旧写到分钟** — 同一天里多段讨论分得更细。但列表是按时间排的，先后已经看得出；几点几分要从左往右读才知道是哪天，日子才是找讨论时用得上的。
- **一分钟内写"刚刚"** — 原型就是这么写的，读起来最有"刚做完"的感觉。但它会自己变：摆在屏幕上的"刚刚"过一分钟要变成"今天 10:41"，得有个钟一直叫界面重画；作者刚做完的事，"今天 10:40"也一样看得出是刚才。原型那样写是因为它没有真的钟，改成记假书里的"现在"。
- **右栏回车就发，照原型** — 右栏是随手问一句的地方，一行框回车发出最省事，许多聊天软件也是这样。但同一段讨论在两处用两种键，作者在讨论页按惯了回车换行，到右栏会把半句话发出去；反过来在讨论页按回车等着发，又只换了行。一段话常要分几行写，回车拿去发送，换行就得另记 Shift+Enter。
- **新作品的模型留空，让作者每部书自己挑** — 不同的书可能想用不同的模型（长篇用便宜的，短篇用贵的），空着能提醒作者这是这部书自己的设置。但多数人只配了一两个服务，每建一部书都把同一个模型再挑一遍只是多一步；沿用之后想换，讨论框下面的菜单一点就换，也只改这一部。
- **把模型记在本机的偏好里，不再按作品记** — 一处改、处处生效，最省事。但作品文件夹搬到另一台电脑、或和别人共用时，`work.yaml` 里的选择跟着书走才说得清这部书用的是什么；按作品记是原来的格式，改了要迁移。
- **AI 那条照旧横跨整栏、不加边框** — 它是"眼下在做什么"的状态，横跨整栏更像工具栏的一部分，和正文分得开。但它说的是正文里的某一段（改哪几句、起草到哪），和正文对齐才看得出是在说这里；宽窗口里它的按钮跑到离正文很远的右边。
- **浮条上面放不下时压到章标题上面，照原型** — 浮条总在选区上面，位置最一致。但编辑器之外是章标题和章纲那一行，浮条画过去要知道上面有多高、查找条开着时还会压住查找框；放到选区下面只看编辑器自己。
- **Ctrl+F 不带选中的字，照原型** — 浏览器就是这样，打开的总是上次找的。但写作时找一个名字通常就是因为在正文里看到它，选中再按 Ctrl+F 省掉一遍打字；Word、VS Code 都这样。选区跨段时不带，免得把几段话塞进一行框里。
- **快照列表照旧写到秒** — 同一分钟里存的两份（打开时一份、紧接着 AI 改写前一份）标题不会一样。但每份下面还写着"打开时""AI 改动前"和字数，分得开；到秒的六位数字让一列时间更难扫，原型也只写到分。
- **打开时把缺的标准文件夹都补建上** — 一处补齐，之后各处写文件都不用再管文件夹在不在。但书架读作品信息（`describe`）、改名也走 `workspace.Open`，只是看一眼就往作者的文件夹里写东西不对；真正非有不可的只有 `sessions/`，在第一次新开讨论时建就够了。
- **第一次打开时有章节的进正文、没章节的进讨论** — 空作品先在讨论里把想法聊出来，合"从想法到设定再到正文"的顺序。但原型里新建的书也先进正文，作者看过的就是这个流程；要分开还得在打开时多读一遍目录树，只为挑一页。
- **照原型只给那六句带勾** — 原型是作者看过的。但原型里"已保存""已导出到……"不带勾、"已加入设定"带勾，说不出分法，软件这边新加一句提示时也就没有依据；按"做完了 / 先做什么 / 出错"分，一句提示该用哪种一看就知道。
- **提示都不带图标，只有出错的带** — 最简单，不用分哪句算做完。但"已采纳改写""已加入设定"是作品真的被改了的地方，一个勾让作者放心；原型本来也给它们带勾。
- **检查页左栏也列出失败的章** — 失败的章一眼可见，不用等右边空着。但左栏是待作者处理的条目，失败的章作者能做的只是重试，放进去会让"全部 N"的数对不上；章末的状态行已经写了失败和原因，这里只要不说反话就够。
- **名字另起一行或放进括号**（"林晚（晚晚）"） — 括号读起来更像正文。但条目内容里本来常有括号和冒号；一律"名字：内容"和目录行"分类 · 名字：第一句"一个样，模型和作者看一种写法就够。已放弃、悬而未决的条目在列表里成了"已放弃：老陈：……"，两个冒号，原型目录行"悬而未决：地点：……"本来就这样。
- **只在界面的列表里补名字，请求不动** — 不碰发给模型的内容，缓存不受影响。但列表是"发了什么"的记录，界面上加了、请求里没有，就说了假话；而模型看不到名字才是要修的。改了之后，各作品下一次请求的设定部分缓存不命中一次。
- **回答时把问题并进答案的内容里存下**（"问：……答：……"） — 不用改发送的格式，存下的就是 AI 读的。但作者写的那句被改了，右栏显示、修改时都多出不是作者写的字；问题本来就单独存着，发的时候拼上就够。
- **位置说明照旧，只把「创建」变灰** — 改动最小。但作者看到按钮灰了不知道为什么，固定那句"须不存在或为空"又不说这个文件夹是哪种；说明本来就在那一栏下面，照实写最省事。
- **服务表单只把重复的 ID 挡下，别的照旧按了再说** — 重复 ID 是会丢东西的那一处，别的只是晚一步知道。但刚写进 DESIGN.md 的规则马上就有了例外，而这张表单是软件里栏最多的，作者最容易在这里来回按保存试错。
- **按有没有正文决定空讨论的说法** — 有正文、没设定的书也算开了头。但讨论页不读目录树，为一句空状态去读不值；讨论里定下的东西记进设定，设定空着时"从一个想法开始"说的正是从这里起。
- **同名时把按钮改成「修改分类」** — 按钮本身就说了要做什么，不多占一行。不用：按钮上只放得下动词，说不出那一条现在落在哪；而作者要对的正是落点，新建作品的位置说明也是放在表单下面的一行灰字。

## Consequences

- 新开讨论不再产生多余的空文件；`Store.Sessions` 照旧全列，界面自己滤掉。
- 测试作品或旧版留下的多个空讨论，界面上都看不见，新开时逐个用掉。
- 右键收起的计数（"已收起 N 段对话"）不算空讨论。
- 「忽略」一个新名字后，它在任何一章都不再报；要找回只能删掉那一章的 `.check.json` 里那条的 `meant` 或重新查那一章（重查时原句没变会把 `meant` 带过去）。
- 检查页的条数可能比各章章末的条数加起来少：同一个新名字在章末各算一处，在检查页只算一条。
- 走查里看到、还没改的几处（没选文字时的「记为回收」、回答丢名字、检查失败时的「已检查至」等）记在[真机走查里看到、和作者过了以后才改的几处](2026-10-16-hands-on-leftovers.md)，2026-10-19 和作者过了，都改了。
