# Agent Note: 待处理：需要作者看的事汇在正文顶栏一处

Status: implemented

## Problem

设计稿（Claude Design 项目里的 `待处理.dc.html` 和 `总览.dc.html`）定下的规矩是"写的时候不打扰"：正文里只有浅色标记，需要作者处理的事集中到一个地方，作者有空时去看。设计里汇到这里的有三类：设定对不上（一致性检查）、伏笔、备份失败。

现在只有伏笔有现成的数据：右键"标记为伏笔"、按章存在 `.marks.json`、文字删光后变成"失去锚点"。一致性检查和备份还没做；伏笔也还没有"回收"。

2026-10-09 与作者对齐了做法（下面每条都是作者确认过的）。

## Decision

- **位置和样子照设计稿**：正文顶栏最右边一个"● 待处理 N"按钮（琥珀色圆点），点开是 380 宽的浮层，挂在按钮右下：
  - 标题"待处理"，右边切换"全部 N / 本章 N"；
  - 中间按组列出，每组默认列 3 条，多的显示"还有 N 条"，点开后变"收起"；列表最高 520，再多就滚动；
  - 底部"全部忽略"。
  - 没有待处理时不显示按钮。
- **这次只接伏笔一组**，两种情况：
  - **失去锚点**：伏笔标的文字被删光了，显示"「雨夜的电话」原句已删"；
  - **没回收**：埋下之后又写了 **30 章以上**（默认，设置里可以改，见[伏笔](2026-10-10-foreshadowing.md)），显示"「红色钥匙」41 章没回收"。章数按章节树里的顺序数，从埋的那一章数到全书最后一章。已回收和已放弃的不列。
  - 括号里是作者写的备注，没有备注就用标的原文，最多 16 个字。
  - 设定对不上、备份两组各是一个 `pendGroup`，都已接上：备份失败时列一条，点一下重试，见 [备份](2026-10-09-backup.md)；检查发现的问题每条一条，排在最前，点一下去「检查」页，见 [一致性检查](2026-10-10-consistency-check.md)。
- **数据从哪来**：
  - 其他章读磁盘：`Store.Marks()` 一次读出所有章的标记，按 `ReadChapter` 同样的方法重新找回位置。每次切换章节（`openNode`）时重读一遍，这时上一章刚存过盘。
  - 正在写的这一章用编辑器里的标记，删掉伏笔文字的那一刻就会出现"原句已删"，不用等存盘。
- **失去锚点后还记得原文**：以前存盘时每个标记的 `quote` 都按当前文字重算，失去锚点的标记 `quote` 就变成空的，说不出原来标的是什么。现在：
  - 编辑器的 `Mark` 多了 `Quote`，标记时或读入时记下所标的文字；
  - 存盘时失去锚点的标记保留传进来的 `quote`，不再重算。
- **点一条**：关掉浮层，跳到那一章，选中标记的文字；失去锚点的就把光标放在原来的位置。
- **全部忽略**：只忽略当前列出来的（在"本章"下就只忽略本章的）。忽略记录存在作品文件夹的 `.writer/desk.json`（`ignored`），以后不再出现；新产生的照常出现。忽略的键是"伏笔/种类/章节 ID/标的原文"，所以作者改了标的文字，它会重新出现。没有单条忽略和撤销忽略。
- 代码：`desk/pending.go`（数据、按钮、浮层）、`desk/write.go`（顶栏、切换章节时重读）、`desk/setting.go`（忽略记录）、`desk/theme.go`（琥珀色）、`workspace/chapters.go`（`Marks`、存盘保留原文）、`editor/doc.go`（`Mark.Quote`）。

## Alternatives considered

- **先按 `伏笔.dc.html` 把伏笔做完整（回收、列表、互跳），再做待处理** — 有了回收，"没回收"才有正常的出口，不会只能靠忽略。不这样做，是因为作者想先把汇总的地方立起来，其他功能做好后往里接；样例作品章数还少，"30 章没回收"眼下碰不到。代价写在下面。
- **只做浮层外壳，先不接数据** — 改动最小。但没有数据的界面没法试用，也验证不了"本章"切换、跳转和忽略。
- **每次存盘都重读全书标记** — 数据总是最新。但 300 章时每次停笔都要读几百个文件；其他章只有切换过去改了才会变，切换章节时重读就够了，正在写的这一章用编辑器里的。
- **把忽略记录存进设定或单独的文件** — 忽略是作者的决定，可以和作品数据放一起。但它只影响这个界面显示什么，和右栏宽度、每章光标位置一样是界面状态，放在已有的 `.writer/desk.json` 里最省事。

## Consequences

- 收益：作者删掉伏笔原句的当下就能看到提醒，可以撤销或去处理；以后一致性检查、备份有了统一的出口。
- 代价：
  - 写这篇时伏笔还没有"回收"，埋了很久的只能忽略；2026-10-10 起有了，回收过和放弃的不再列，见[伏笔](2026-10-10-foreshadowing.md)。
  - 改了标的文字，忽略过的会重新出现。
  - 没有单条忽略，也没有撤销忽略；忽略过的要手动编辑 `.writer/desk.json` 才能找回。
  - 设计稿里分组名在滚动时固定在顶上，mygo 没有 sticky，这次没做。
