# Agent Note: Ctrl+= / Ctrl+- 缩放整个界面

Status: implemented

## Problem

作者习惯 VSCode：Ctrl+= / Ctrl+- 放大缩小整个界面（侧栏、按钮、间距等比变），Ctrl+滚轮只调正文字号。此前两者都调正文字号，读远处屏幕或想把侧栏、按钮一起放大时没有入口。[走查修正](2026-10-09-walkthrough-fixes.md)记录正文字号的独立偏好。

mygo 早期没有原生内容缩放；当前 v0.7.1 提供 Context.SetZoom，无需 fork 或逐处乘尺寸，见[依赖升级](../process/2026-10-13-mygo-0.4.md)。原型的 ZOOMS、zoomFits、zoomNext、zoomBy、winSize 和视图菜单是交互标准。

## Decision

整个窗口使用 mygo Context.SetZoom(z)。desk.App.View 在每帧开始应用本机档位，帧末再次应用本帧按键或菜单的结果；mygo 在显示前按新尺寸重建，输入坐标、输入法、菜单跟随同一个缩放。

- 档位使用 mygo zoomSteps 的 50%–200% 一段：50、67、75、80、90、100、110、125、150、175、200。shelf.ZoomSteps 是读偏好与命令共用的来源。
- Ctrl+= / Ctrl+- / Ctrl+0 在所有页面放大、缩小、恢复实际大小；Ctrl+Shift+= 同样放大。正文字号仍由 Ctrl+滚轮调节，与界面档位独立。快捷键表的正文组写「Ctrl+滚轮 正文字号增大 / 减小」，全局组在打开快捷键列表之前写「Ctrl+= / Ctrl+- / Ctrl+0 界面放大 / 缩小 / 实际大小」。
- 视图菜单在手机预览后分隔，显示「缩放 125%」这类当前百分比，再列放大、缩小、实际大小三行及快捷键，分隔后接外观。到头或屏幕放不下时放大禁用，最低档缩小禁用，100% 时实际大小禁用。
- 档位存进 shelf.Shelf.Zoom（zoom,omitempty），即时保存到 works.json，所有作品共用。0 表示 1；读到不在档位中的非零值时取最近档，越界取最近端点。恢复 100% 时清零，使默认值不落盘。
- 窗口最小尺寸为 1000z×680z，向上取整为整数 DIP；缩小时只降低限制，不缩小窗口。窄窗口继续按 c.Size() 是否小于 1180 判断，该尺寸已经除以 z；desk 中的侧栏、右栏、纸边不另换算。

### 宿主与帧的边界

desk 不持有 mygo.Window。cmd/inkgo 提供 ZoomFits 和 ZoomChanged：前者只读原子缓存的当前屏幕 WorkArea，后者记录最新档位并在帧外串行调整窗口，不把 Context 或 Element 带出帧。未挂 ZoomFits 时，测试允许全部档位。

Windows 后端 Bounds、SetSize 和 Screen.Displays 的 WorkArea 都用 DIP；后端分别按窗口和屏幕 DPI 换算，应用不再乘 ScaleFactor。宿主在窗口移动、调整大小和显示器变化时重读 DisplayMatching(w.Bounds()).WorkArea，并使窗口重画，因此换屏后菜单按新可用区域判断。

Windows SetMinimumSize 只记录 minW/minH，不会自动撑大现有窗口。宿主先 SetMinimumSize，再读 Bounds；不足的轴用 SetSize(max(当前宽, 最小宽), max(当前高, 最小高)) 撑大。启动时窗口选项使用保存的档位，创建后再做一次检查，覆盖恢复的旧窗口尺寸。连续缩放在帧外按最新请求串行执行。

## Alternatives considered

- **不管最小尺寸，让排版窄过 1000（VSCode 就这样）**：最简单，屏幕多小都能放大。不用，是因为窄窗口的排版只做到 1000：侧栏、右栏、纸边已经是窄的那一套，再窄正文一行放不下三十来个字，标题栏的工具会挤；要支持就得再做一套更窄的排版。
- **Ctrl+= 仍调正文字号，界面缩放只放在菜单里**：不改作者的手感。不用，是因为作者要的就是 VSCode 那样 Ctrl+= 缩放界面、Ctrl+滚轮调字号，两样都在键盘上。
- **不改 mygo，在应用里自己缩放**：主题字号和 `desk/` 里写死的字号、间距、宽度都乘一个系数。好处是不碰依赖。但要改遍整个 `desk/`，以后每处新写的尺寸都得记得乘；mygo 自带控件的内部间距改不到，放大后显得挤。mygo v0.7.0 有了 `SetZoom`，这条不再需要。
- **fork mygo 自己加缩放**：几十行就能做出来。2026-10-09 没做，是因为要不停地合上游；现在上游有了，也就不用了。

## Consequences

- 侧栏、正文、工具与间距由工具包统一缩放，保留字形清晰度；应用不用维护另一套随档位变化的尺寸。代价是较大档位要求较大的物理窗口，小屏幕可用档位较少。
- 保存的档位在启动时保留；当前屏幕不足以容纳更大一档时只禁止继续放大，不擅自改写偏好。系统 DPI、多屏移动、输入法候选位置与真实窗口调整仍需实机复核；本次按任务约束不启动软件窗口。
- desk/zoom_test.go 覆盖全局按键、重读偏好、菜单顺序与百分比、禁用行、屏幕限制和缩放后的窄布局；缩放不改正文字号，重置也保留独立字号。shelf/zoom_test.go 覆盖旧偏好、读写、最近档与越界。cmd/inkgo/zoom_test.go 验证尺寸限制、只撑大不足的轴和缩小时不缩窗口。
- Ctrl+滚轮分层验证：editor 的 TestCtrlWheelZooms 检查事件分派，desk 的 TestSizeTheText 与缩放测试检查字号回调及作品偏好；mygo Tester.Wheel 不携带修饰键，不能用它模拟组合滚轮。生产中的 Zoom: a.sizeText 保持原样。
- 布局测试新增写作页 125%、150% 和视图菜单 125% 截图；设置 SHOT 后运行 go test ./cmd/inkgo -run Layout 生成。验收运行 go vet ./...、go test ./desk/... ./shelf/... ./cmd/inkgo/... ./prefs/...、npm run verify-ui、npm run verify-notes。
