# Agent Note: 正文页：章节树、纯文本存储与快照

Status: implemented

## Problem

讨论和设定文档已经能用，但链路停在设定：作品还没有地方写正文。`editor/` 里的原生编辑器有输入法、断行、撤销、标记、灰字续写和补全，但只在 `-editor` 演示里出现，不读写文件，也没有章节。作品文件夹预留了 `chapters/`，没有任何读写代码。

本篇是[产品总提案](../../proposed/feature/2026-10-07-idea-pool-discussion.md)路线第 5 步"接入正文编辑器"的第一期，回答该篇开放问题里"章节版本快照的格式"。方案在 2026-10-08 与作者逐条确认，共 26 个问题。作者明确的前提：

- 正文以作者亲笔为主；
- 也接受作者写好章纲后由 AI 生成初稿、作者再改；
- 不只服务网文，章节结构要自由。

AI 辅助（续写、改写、按章纲起草）是第二期，见[AI 辅助写作](2026-10-08-ai-assisted-writing.md)。本篇只记第一期，不涉及 AI。

## Decision

### 章节树

- 任意层级的树（`workspace.Tree`），节点分两种：**文件夹**只有子节点，**文稿**有正文。
- 文件夹和文稿都可以带一份"纲"：文件夹的是卷纲，文稿的是章纲。纲是作者自己的提纲，第二期起草时作为 AI 的依据。
- 软件里可以新建、改名、拖动、上移下移、移到别的文件夹、删除。新建的节点放在当前文稿之后，或者当前文件夹的末尾。

### 磁盘格式

- 磁盘目录照搬树结构，放在 `chapters/` 下（`workspace/chapters.go`）：
  - 文件夹就是文件夹；
  - 文稿是 `标题.txt`；
  - 纲是同名的 `标题.outline.txt`，为空时不留文件；
  - 标记是同名的 `标题.marks.json`，没有标记时不留文件。
- 每个文件夹里有一个 `.order`，是 JSON 数组，按顺序记录每个子节点的 ID、原标题、文件名、是否文件夹。文件名本身表达不了顺序和身份。
- **文件名由 `fileName` 从标题得出**：
  - `<>:"/\|?*` 换成对应的全角字符，控制字符删掉；
  - 去掉末尾的点和空格，最长 80 字；
  - 开头的 `.` 换成全角，避免变成隐藏文件；
  - 以 `.outline` 或 `.marks` 结尾、或者是 Windows 保留名（`CON`、`NUL` 等）时加 `_`；
  - 同一文件夹里不分大小写重名时加 ` (2)`。
  
  `.order` 里保留原标题，界面显示原标题。
- **读树时对齐 `.order` 和磁盘**：
  - `.order` 里有、磁盘上没有的条目丢掉；
  - 磁盘上有、`.order` 里没有的文件夹和 `.txt`，作为新节点排在末尾，分配新 ID；
  - ID 不合法或重复时重新分配；
  - 有改动就写回 `.order`；
  - 拒绝符号链接。
- `.txt` 里一行一段，不存缩进。`workspace.CleanProse` 读入时去掉每行开头的空白，换行统一成 `\n`。
- 编辑器的 `Prose` 模式负责显示（`editor/`）：
  - 首行缩进两字；
  - 粘贴时去掉每行开头的空白；
  - Tab 不插入"　　"。
- **标记按"位置 + 原文片段"存**。读入时依次尝试：
  1. 原位置的文字还是那段原文，就用原位置；
  2. 否则找离原位置最近的同一段原文；
  3. 都找不到，标为 `Orphaned`，和编辑器里文字删光时一样。
- 三种标记：伏笔（作者手标，带备注）、AI 采纳（按 Tab 采纳的续写）、AI 起草（第二期起草的文字，`editor.MarkAIDraft`）。
- **回收站**：删除的节点连同子树移到 `trash/<ID>/`，旁边的 `.trashed.json` 记录原标题、原父节点和删除时间。
  - 恢复时回到原父节点的末尾；原父节点不在了就回到最上层。
  - 彻底删除时，节点和它子树里所有节点的快照（`history/<ID>/`）一起删掉。

### 外部改动

- 正文页每 2 秒重读一次树，并比较打开中文稿的大小和修改时间。变了就读出正文，和编辑器上次写盘的文字比较；两者都先经过 `CleanProse`，所以只是加了缩进不算改动。
- **打开中的文稿被改了正文**：编辑器上方出现提示，暂停自动保存，作者在两边里选：
  - "用磁盘上的"：编辑器里的文字存一份快照（`external`），换成磁盘上的；
  - "保留我的"：磁盘上的文字存一份快照，编辑器里的写回磁盘。
- **没打开的文稿被改了**：下次打开时读新内容，标记按原文片段重新定位。
- **改名或移动**：
  - 在软件外改名或移动，认作删掉旧节点、新增新节点。旧节点的快照还在 `history/` 里，数据不丢，只是不再和新节点关联。
  - 打开中的文稿因此消失时，编辑器保留文字并提示，作者可以"存为新章节"，放到最上层的末尾。

### 保存与快照

- **自动保存**：停止输入 1.5 秒后写盘，纲也一样，没有 Ctrl+S。切换章节、离开正文页、切换或关闭作品时也会立刻写盘。
- **快照位置**：`history/<节点ID>/<时间>.txt`，旁边同名的 `.json` 记录触发原因、标题、字数和当时的标记（`workspace/history.go`）。放在作品目录里、`.writer` 之外，随作品备份。
- **何时存快照**（`TakeSnapshot`，内容和最近一份相同时不存）：
  - 打开文稿时，正文不为空；
  - 连续编辑时，每 10 分钟随写盘存一份；
  - 从快照恢复之前；
  - 外部改动时，被换掉的一边；
  - AI 改动之前（第二期使用，原因已预留为 `ai`）。
- **保留**：最近 7 天全部保留，更早的每天只留最后一份。每次存快照时清理。
- **界面**：快照列表按时间倒序排列，显示原因和字数。右边可以预览，也可以和当前版本对比：按段落对齐，改过的段落再逐字比较，删掉的字标红划线，新写的字标绿。"恢复这个版本"先存一份当前版本，再整章替换，包括标记。

### 写作页

- 左侧导航新增"正文"页（第 3 页）：
  - 左栏是章节树，替换会话列表。窄窗口下也不折叠成图标栏，因为树就是这一页的导航。
  - 章节树支持拖动：拖到文件夹上，放进它的末尾；拖到文稿上，放到它前面；拖到树下方的空白处，放到最上层的末尾。右键菜单提供重命名、新建、上移、下移、移到、移到回收站。
  - 中间是编辑器，章纲在顶部，可以折叠。选中文件夹时显示卷纲和子节点列表。
  - 右栏是设定，和讨论页同一个面板，同样可以收起。之后右栏加了"讨论"标签，宽度也可以拖动，见[写作时的讨论侧栏](2026-10-08-discussion-beside-the-prose.md)。
- 上次打开的节点记在 `.writer/desk.json` 的 `chapter` 里，重开作品时回到它。停在正文页关掉的作品，重开时也直接回正文页，见[第一次真机走查的修正](2026-10-09-walkthrough-fixes.md)。
- **从正文"加入设定"**：
  - 入口是编辑器右键菜单或顶栏按钮；
  - 作者可以把选中的原文改写成自己的说法，选好分类后，作为作者的条目加入设定正文；
  - 出处是 `Source{Chapter, Quote}`，指向节点 ID 和那段原文；
  - 加入前先写盘，保证原文就在磁盘上的正文里。
- **出处校验**（见[设定文档与后台记账](2026-10-08-setting-document-and-background-bookkeeper.md)）：
  - 不带消息的章节出处不能带会话；带消息的出处可以同时标章节，表示那句是作者在讨论里引用的正文（见[写作时的讨论侧栏](2026-10-08-discussion-beside-the-prose.md)）；
  - 加入时，原文必须在那一章当前的正文里；
  - 打开作品重放修订时不再核对章节出处，因为正文本来就会继续改。
- **字数**：只数非空白字符，中文一字一数。顶栏显示本章字数和全书字数，树里每章旁边显示字数。
- **章内查找与替换**：Cmd+F 打开；匹配处在编辑器里高亮，当前一处颜色更深。"全部替换"在撤销记录里只算一步。替换正好覆盖一个标记的文字时，标记跟着新文字走，不会失去位置。
- **导出全书**：按树的顺序拼成一个 `.txt`，开头是作品名，每个文件夹和文稿前写标题；可选在段首加"　　"。有系统对话框时让作者选位置；没有时写到作品里的 `导出/作品名.txt`。后来（2026-10-09）可以只导出本卷或本章，见[走查修正](2026-10-09-walkthrough-fixes.md)。
- 全书搜索和每日字数目标以后再做。后来全书搜索见[在全书里找](2026-10-09-find-in-the-whole-book.md)；每天写了多少已在顶栏显示（见[走查修正](2026-10-09-walkthrough-fixes.md)"今天写了多少"和"每日目标"）。

## Alternatives considered

- **卷和章两级** — 对网文作者最自然，界面和导出语义都简单。但作者明确不只写网文，要"自由"，选了任意层级的树。
- **文件按 ID 平铺，树结构全在一份清单里** — 改名、移动只改清单，没有文件名非法字符和外部改名的问题，实现最稳。但磁盘上全是编号，离开软件就读不了；作者选纯文本，正是为了离开软件也能读、能用。
- **任何节点既有正文又有子节点（Scrivener 式）** — 自由度最高。但"导出全书""字数"的语义变模糊，实践中也很少用；文件夹加文稿两种已经够自由。
- **章纲写进设定的"情节"分类或单独一份大纲** — 大纲集中在一处，便于通览全书结构。但章纲和章节分离，写到第 80 章要去大纲里找；起草时也要先定位"哪段大纲对应这章"。纲贴着节点存，起草直接可得。
- **每章一个 Markdown 或 JSON** — Markdown 能在文中直接记标记，JSON 能把正文和标记放在一起。但 Markdown 的特殊语法会混进正文，拷进发布平台前要清理；JSON 换个工具就打不开。
- **只自动保存、版本交给 git** — 实现最少，git 的历史比自制快照强大。但大多数写作者不用 git；"改坏了找回昨天那版"和"AI 改写前留一份"都是刚需。
- **按内容把外部改名的文件认回原节点** — 作者在资源管理器里改名也不丢历史关联。但内容匹配会误判，比如开头相同的两章；改名本来就该在软件里做，外部操作也只丢关联、不丢数据。
- **段落存全角空格"　　"** — 所见即所存，用其他工具打开也是排好版的样子。但 AI 输出和手打的格式容易不一致，各平台对缩进的要求也不同；存干净的段落，显示和导出时统一处理。
- **用文件系统监听代替每 2 秒比较** — 改动即时发现，不用轮询。但三个平台各有一套监听机制，纯 Go 下要引入依赖；外部改正文是少见情况，比较一次大小和修改时间几乎没有开销。
- **外部改动时自动合并两边** — 作者不用选择。但合并散文没有可靠的规则，合错了作者很难察觉；让作者选一边，另一边存快照，什么都不丢。

## Consequences

- **收益**：
  - 正文是普通文件夹里的纯文本，离开软件也能读、能改、能备份；
  - 快照、回收站和外部改动处理都保证"不丢字"；
  - 设定条目可以追溯到正文里的原文。
- **代价**：
  - `.order` 和文件名要来回对齐，改名和移动都要动文件；
  - 在软件外改名会丢掉快照的关联；
  - 每次编辑仍会重新断全部行，上万字的长章节可能需要按段落增量断行；
  - 几百章、每章每天几十份快照时，`history/` 的文件数会很多，需要观察，必要时改为每章一个只追加文件。
- **还没验证的**：
  - Windows 资源管理器里改大小写、网盘同步中途写半个文件等情况；
  - 真机拖动排序的手感。

## Testing

- `go test ./workspace`：
  - 树和磁盘一致（新建、改名、移动、删除、恢复）；
  - 非法标题能存能读；
  - 外部新增的文件被收进树；
  - 标记按原文片段重新定位；
  - 快照去重与保留规则；
  - 彻底删除清掉快照；
  - 字数与导出；
  - 章节出处的校验。
- `go test ./editor`：全部替换一次撤销、`Prose` 模式不存缩进。
- `go test ./desk`（`write_test.go`）：
  - 停顿后写盘、重开回到上次的章节；
  - 外部改动两种选择、只差缩进不提示、外部改名后存为新章节；
  - 快照恢复；
  - 查找替换；
  - 加入设定；
  - 回收站和右键菜单；
  - 拖动；
  - 标记重开后还在；
  - 导出。
- `SHOT=<path> go test -run TestLayoutWriting ./cmd/poc`：正文页、快照对比、外部改动提示、文件夹页、查找栏的截图。
