# Agent Note: 讨论读得到大纲

Status: implemented

## Problem

[大纲页](../../implemented/feature/2026-10-19-outline-cards-and-timeline.md)做好以后，作者在讨论里问「小祥这条线断了几章」「林晚下井是在档案室之前还是之后」，AI 答不上：它只能搜正文、读正文、查设定、搜讨论，看不到卡片和情节线。

- 故事的先后只在大纲里。正文按写的先后排，有回溯的章，读正文推不出谁先谁后，只能猜。
- 没放进章节的卡片是作者想好了还没写的事，正文里根本没有。
- 起草一章时，AI 带着章纲和上一章全文，却不知道这一章的卡片，也就是作者在大纲里说好要在这一章发生的事。

2026-10-19 作者说「做讨论读大纲」。

## Decision

AI 只读大纲，不改。这一期不让 AI 新增、挪动或改卡片。

### 讨论多一个工具 `read_outline`

AI 要用时自己查，不是每次都整份附上。参数都可选；给了几个时按 line > chapter > query 只用第一个：

- `line`：情节线的名字。返回这条线的卡片。
- `chapter`：章名或卷名，和搜全书结果里写的一样。返回那一章（卷里各章）的章纲、卷纲和卡片。
- `query`：一个词。返回发生了什么、说明、故事中的时间里有这个词的卡片。
- 都不给：先列各条情节线各几张、未放进章节几张，再列全部卡片。

返回的格式：

- 一张卡片一行，按故事的先后排，行首是它在全书故事里的序号（「#12」），后面依次是故事中的时间、发生了什么、写在哪一章（没放的写「未放进章节」）、情节线、说明，用「｜」隔开，例如「#1｜时间：去年｜发生：下井｜「第二章」｜情节线：小祥」。有了序号，不同的线之间也比得出谁先谁后。写在回收站里的章、或已不在书里的章的卡片，算未放进章节。说明压成一行，过长截到 200 字。
- 查卷时按卷里各章的先后分组，每组先给那一章的章纲；没有卡片的章只在第一页列出，全卷都没有卡片时写「这一卷没有卡片」。
- 起草、改写附上的「本章的卡片」用同一种行（`discussion/outline.go` 的 `cardLine`）。
- 一次最多 200 张，多了照 `search_book` 的写法说从哪接着列（`from`）。
- 不露出卡片和情节线的 ID。章用章名指，和别的工具一样。
- 大纲文件读不出来时，工具说「大纲文件读不出来」，按失败处理，不编内容。

讨论规则（`discussion/prompts.go` 的「查阅」）补两句：

- 大纲是作者排的卡片，先后是故事里发生的先后，可能和章节的先后不同。
- 问到情节先后、某条线的进展、还没写的打算时，先用 `read_outline` 查。大纲和正文对不上时，以正文为准，并告诉作者哪里不一致。

### 起草、改写带上这一章的卡片

- 起草、改写跟着的那一章有卡片的，把它们作为一个固定部分附上，放在章纲后面。新的部分是 `workspace.PartCards`，「AI 参考内容」里写「本章的卡片 N 张」。
- 起草的规则从「照章纲写」改成「照章纲和本章的卡片写」。
- 起草对话框的第一句随之变成「AI 仅将章纲和本章的卡片扩写为正文，不添加这些之外的重大情节」，下面「将带上本章的 N 张卡片、上一章全文……」。这一章没有卡片的，照旧。

### 作者看得到

照 DESIGN.md「模型看到的，作者也看得到」：

- 回复上方那一行写「查了大纲「小祥」这条线」「查了大纲「第87章：停电」的卡片」「查了大纲「档案柜」」「查了大纲」。
- 点开是查到的几张：「2 张卡片：周祥来当学徒（今年·四月，「第1章：巷口」）→ 小祥改口叫她“姐”（十月六日夜，「第87章：停电」）」。软件里点开显示的是工具返回的原文（和别的工具一样，`desk/chat.go` 的 `looked`），即上面那种一张一行的格式，比原型的一句话长。

样子在原型：

- `prototype/pane.js`：`LOOK` 的「纲」，和 `outgoing` 的「本章的卡片」。
- `prototype/book.js`：「这一章的节奏怎么样」里 10:03 那条回复。
- `prototype/dialogs.js`：起草对话框。

AI 关着时没有讨论，什么也不发，不用另做。

## Alternatives considered

- **每次讨论都把整份大纲附上** — 最强的理由：AI 不用想起去查，问先后的时候一定答得上；卡片短，几十张也就几千 token。没有用：长篇几百上千张卡片，几万 token 每轮都发，多数轮次用不上，和[去掉章节摘要](../../implemented/simplification/2026-10-16-no-chapter-summaries.md)时定下的「钱不花在作者看不见的地方」相反；讨论里查设定、查正文都是用到再查，大纲照一样的路子。
- **让 AI 也能记卡片（像记设定那样）** — 最强的理由：讨论里定下的情节，顺手记进大纲，作者少抄一遍。没有用（这一期）：大纲是作者自己排的先后，AI 插一张卡片要决定排在哪、放哪条线、哪一章，错了作者要去时间线上找出来挪；设定有「待确认」这一层兜着，大纲还没有。等作者用过一阵再看要不要做成提议。
- **起草时附上全书的卡片** — 最强的理由：AI 知道后面要发生什么，能提前铺垫。没有用：全书的卡片多，起草本来就带了上一章全文；要铺垫，AI 可以在讨论里用 `read_outline` 自己查。

## Consequences

- `discussion/outline.go` 是 `read_outline` 和 `cardLine`；工具排在 `search_talks` 后面、`note_setting` 前面。大纲读不出来时工具失败，说「大纲文件读不出来」；起草、改写照常，只是不带卡片。工具只读，不写 `outline.json`。
- `workspace.PartCards` 排在 `PartOutline` 和 `PartOutlines` 之间；「AI 参考内容」写「本章的卡片 N 张」，发送的那一行写「本章的卡片」。`Preloaded` 走 `fixedOf`，起草对话框的 token 数里已经算进卡片。
- 起草对话框打开时在 `desk/ai.go` 的 `openDraft` 数一次这一章的卡片（`writeView.draftCards`），之后不每帧读文件。`discussion.fixedOf` 记录实际带上的卡片数，`Preloaded` 连同 token 数通过端口返回；对话框标题的卡片数使用 `openDraft` 独立数的 `draftCards`，预加载失败也保留，提示里的卡片数写端口返回的实际数量。
- 检查：
  - `discussion` 的 `TestReadOutline`、`TestReadOutlinePagesAndFailures`：四种查法、序号、未放进章节、回收站里的章、查卷的分组和分页、坏文件、label、不露 ID、不写文件。
  - `discussion` 的 `TestFixedCardsAndPreloaded`：起草和改写多出 `PartCards`，没有卡片或大纲坏了时没有，以及规则里的句子。
  - `desk` 的 `TestDraftDialogWithCards`、`TestDraftNoteCardsBeforePreviousChapter`：对话框的两句。
  - `npm run verify-prototype` 的「a long talk」点开「查了大纲」那一行。
- 2026-10-20 由 Codex 实现，Claude 审查：返工一轮，改了工具次序和查卷分页。

## Risks

- AI 可能不记得去查，照旧凭正文猜先后。先靠规则里那两句和工具说明；用一阵看实际的讨论，不够再考虑在讨论开头附一份情节线的概览（几条线、各几张）。
- 卡片是作者的草稿，可能和正文对不上。规则要 AI 以正文为准，并告诉作者，不替作者改。
