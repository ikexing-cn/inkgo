# Agent Note: 正文和设定的一致性检查

Status: implemented

## Problem

设定定下来以后，写到几十章，正文很容易和它对不上：人物怕黑却一个人进了黑巷子，名字写成同音字，新人物出场了设定里却没有。作者自己很难逐章对照。

设计稿 `Consistency.dc.html`（B1、B2）、`Pending.dc.html`、`Settings.dc.html` 已经画了这件事的样子：单独一页「检查」集中处理，写作时只在章末一行字和正文里的浅色虚线提示，不弹窗；什么时候检查由作者选。[待处理](2026-10-09-pending-list.md)也留了「设定对不上」一组等它。

作者 2026-10-10 说"先做一致性检查，做完再统一告诉我"，中间的取舍由 agent 决定，作者验收。

## Decision

### 存放

- 每章可以有一份检查结果，和正文放在一起：`章名.check.json`（`workspace.Check`），随章节移动、进回收站、恢复（`companions`）。
- 内容是：检查时正文的哈希（`ProseHash`）、字数、模型名、时间，和发现的问题（`Finding`）。
- 一条问题有：ID、种类、一句话标题、正文里的原句（`quote`），以及按种类不同的内容：
  - `conflict`（对不上）：对应的设定条目 ID，和那条设定里矛盾的那半句（`says`）；
  - `name`（名字写错）：设定里的正确名字；
  - `new`（新出现）：新名字、建议的分类、一句话说明。
  - `meant`：作者点过「是故意的」或「不用记」。
- 严格按 JSON 读，未知字段报错。种类不认识、没有 ID、没有原句的写不进去。

### 一次检查

- `writing.Writer.Check` 读磁盘上的这一章，用写作模型、按它选的思考程度，一次调用。
- 给模型看的是：
  - 设定正文和「已删除」的条目，按编号列出，带分类和名字，不带 ID；放不下时保留新的；「等你决定」的不给；
  - 作品的分类；
  - 作者说过「是故意的」的原句；
  - 章名和正文。正文超过上下文预算的四分之三时只给前面一部分，并告诉模型。
- 模型只回一个 JSON。读不了就报错，不存。
- 每一条都要核对过才留下，核对不过的直接丢掉：
  - 原句必须在正文里找得到（容许模型抄的时候多了或少了引号、空格，`discussion.Locate`），存的是正文自己的字；
  - `conflict` 的编号必须是给它看过的条目；`says` 在条目里找不到就留空；
  - `name` 的正确名字必须是设定里的名字，原句本身不能也是设定里的名字；
  - `new` 的名字必须在正文里出现，不能已经在设定里，不超过 12 个字；分类不认识就归到「其他」。
- 一章最多留 20 条。正文不到 200 字（`writing.MinCheck`）、设定正文为空都不查。
- 作者标过「是故意的」的，只要原句还在，就原样带到新的结果里，不重复报。

### 什么时候查

- 存在 `.writer/desk.json` 的 `check_when`，三选一：
  - **写完一章就查**（默认，空值）：离开一章时，这次打开期间存过正文、够 200 字、设定不为空、没查过或查过以后改了，就排队（`leaveCheck`）；
  - **我点了才查**（`manual`）：只在作者点「现在查」「再查一次」时查；
  - **边写边查**（`always`）：停笔 8 秒、已经存盘时查；同一版正文只自动查一次，失败了不反复重试。
- 后台队列一次一章，三分钟超时，和摘要的队列各跑各的（`desk/check.go` 的 `checks`）。换作品时丢掉排队的。
- 「再查一次」（还没查过时叫「检查全书」）先数出没查过或改过的章，告诉作者"有 N 章，每章用一次 AI，一共 N 次"，点「开始检查」才排队；都查过就只提示一句。检查中可以「停下」。

### 什么算解决了

不存"已解决"的状态，每次按当前的正文和设定算：

- 原句不在正文里了：算改好了。正在写的这一章按编辑器里的文字算，改掉的当下就不再列；离开这一章、进入「检查」页时把这些条目从文件里删掉（`pruneCheck`）。
- `conflict`：对应的条目没了，或者 `says` 不在条目里了，算设定改过了。
- `name`：设定里没有这个名字了，不再列。
- `new`：设定里有了这个名字，不再列。
- 「是故意的」「不用记」：记在文件里，不再列，下次检查也不再报。

### 界面

- **侧栏**多一项「检查」，有问题时右边显示条数。
- **「检查」页**（照 B1）：
  - 左边 360 宽：标题、"查到第 N 章 · 再查一次"、四个分类（全部 / 对不上 / 名字写错 / 新出现，各带条数）、列表；
  - 右边：标题、"1 / N · 下一条"，正文和设定并排两张卡片，矛盾的字加底色，卡片上有「看原文」「看设定」；同一条设定在别的章也有问题时列在下面，标过的写"你标过「是故意的」"；
  - 底部按钮：左边「以后再说」（跳到下一条），右边依次是「是故意的」「改设定」「改正文」，主按钮在最右。
  - 「改正文」「看原文」打开那一章并选中原句；「改设定」「看设定」同时在右栏打开那条设定。
  - 名字写错：右边卡片是设定里那个名字的条目，按钮是「是故意的」「改正文」。
  - 新出现：右边卡片是"可以加入设定 · 分类"和名字、说明，按钮是「不用记」「加入设定」。加入时以作者的名义写一条设定正文，带名字和这一章的出处。
- **章末一行**（照 B2，专注模式下不显示）：这一章查得怎么样、什么时候查（点开是三个选项的浮层）、右边是存盘状态。有问题时点这句话去「检查」页。可以查的时候多一个「现在查」。
- **正文里**：有问题的原句下面一条浅色虚线（`Editor.SetDoubts`，不进撤销、不存盘，和伏笔的点线分开）。
- **设置 · 提醒与检查**多一组「检查正文和设定」，同样三个选项。伏笔那一行的文字顺便改成设计稿现在的说法。
- **待处理**多一组「设定对不上」，排在最前，点一条去「检查」页的那一条。「全部忽略」只是不在待处理里列，「检查」页里还在。
- 代码：`workspace/check.go`、`writing/check.go`、`desk/check.go`，`editor/paint.go`（虚线），`desk/shell.go`（页面和侧栏）、`desk/write.go`（章末一行、离开时）、`desk/pending.go`、`desk/foreshadow.go`（设置）、`desk/setting.go`（`check_when`），`discussion/shared.go`（公开 `Locate`、`Decode`）。

### 和设计稿不一样的地方

- B1 的主按钮「改正文」画在最左，这里放在最右：作者定过"主按钮在右"。设计稿随这次改动同步。
- 设计稿没画「名字写错」「新出现」的右半边，也没画空状态、检查中、失败的样子，这里按同一套版式补了。
- 设计稿列表里写"第87章 1 处 · 第79章 2 处""第52章起出现 6 次"，是跨章合并的；这里一章一条，不合并，不数次数。
- 「现在查」和"再查一次"前的确认浮层是设计稿没有的。
- 设计稿原来写"前面也有类似的地方"；这里列的是别的章里同一条设定的问题，不分前后，所以写成"别的章也有类似的地方"。设计稿随这次改动同步。

2026-10-14 起 AI 可以整个关掉（见[可以整个关掉 AI](2026-10-14-disable-ai.md)）：关着时没有检查页，正文底下不写检查的状态，不排检查，虚线不画；检查结果留在盘上，重新开启后照旧。

## Alternatives considered

- **把"已解决"存成状态** — 作者点过就确定地消失，不依赖原句还在不在。但作者多半是直接去改正文或改设定，不会回来点；按当前内容算，改了就自己消失，少一步，也不会出现"标了已解决其实没改"。
- **全书一次检查，把所有章一起给模型** — 能发现跨章的前后矛盾。但几十章就超出上下文，一次的花费也没法预估；一章一次可以排队、可以只查改过的。跨章矛盾留给以后。
- **检查结果放在 `.writer` 里当缓存** — 它可以重新生成。但重新生成要花钱，作者标的「是故意的」也在里面，丢了会重复打扰；所以跟着章节走。
- **用整理模型或不推理** — 便宜。但判断矛盾比写摘要难，误报多了作者就不看了；先用写作模型和它选的思考程度，作者嫌贵可以改成「我点了才查」。
- **改正文时直接替换**（比如一键把「林婉」换成「林晚」） — 名字写错时最省事。但设计稿定的是"作者点了才改"，而且替换要考虑同一章里别处的同名；这次只带到原句，选中它。
- **虚线做成一种标记（`MarkKind`）** — 位置跟着编辑走，不用每次重新找。但标记会存进 `.marks.json`、进撤销栈；检查结果不是作者标的，按原句每次重新定位就够了。

## Consequences

- 每章多一个可选的 `.check.json`；旧作品没有它照常打开。
- 默认每离开一章改过的正文用一次写作模型，和自动摘要各算一次。作者可以改成只在点的时候查。
- 误报靠两层挡：核对不过的丢掉；作者点「是故意的」后不再报。漏报没有办法，这是提示不是保证。
- 模型抄错原句的那一条会被丢掉，作者看不到，也不知道丢了几条。
- 正文太长时只查前面一部分。2026-10-14 起界面上说了（见[审查后的一批修正](../bug-fix/2026-10-14-review-fixes.md)）：`.check.json` 多一个可选的 `read`（模型拿到了前多少字，读全了不写），页脚写「第 N 章仅检查前 5000 字，未发现不一致」或「…，有 M 处待处理」，悬停说「后文超出上下文预算，可在设置中提高预算」（文案作者 2026-10-14 确认）。后文还是没有查。带 `read` 的文件，旧版本的程序读不了（不认识的字段会报错）。
- 2026-10-14 改正一个从 `3bb2dc6` 起就有的丢数据的错：正文页第一次打开一章时，`enterWriting` 先设好 `w.node` 再 `openNode`，`openNode` 先叫 `leaveCheck`，这时那一章的正文还没读进来，`pruneCheck(w.node, "")` 把这一章检查找到的问题都当成原句已不在，从 `.check.json` 里删掉了。现在 `leaveCheck` 在编辑器还没建（`w.ed == nil`）时什么都不做。
- 没有用真实模型和真实程序走过：作者当时在用电脑，不能操作界面。提示词在真实模型上的误报率、JSON 是否稳定都还没验证。

- `writing/check_test.go`：

  - 标过「是故意的」的带到下一次并告诉模型，原句没了的忘掉；
  - 回答不是 JSON、正文太短都报错。
- `desk/check_test.go`：
  - 点「现在查」后章末、侧栏、待处理都数出 3 条；从待处理点进「检查」页的那一条；

  - 「改正文」回到那一章并选中原句，改掉后当下不再列，离开时重新检查；
  - 选「我点了才查」后离开不检查，「检查全书」先说明次数再开始，选择随作品保存；
