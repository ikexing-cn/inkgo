# Agent Note: AI 写的字等作者采纳，作品记下用量

Status: implemented

## Problem

这是 [AI 基建](../architecture/2026-10-15-ai-infrastructure.md)五步里的最后一步 e，接在[讨论长了压缩成摘要](../architecture/2026-10-15-compacting-a-long-talk.md)之后。

- 续写按 Tab 才进正文，改写点「采纳」才进，起草却在开始时存一份快照，然后直接流式写进正文。[AI 辅助写作](2026-10-08-ai-assisted-writing.md)当时这么定，理由是起草是作者明确要的整章初稿。DESIGN.md「AI 写的字要作者采纳」写的是没有例外，原型 2026-10-15 也改成了先看再采纳。
- 第 a 步起每次请求都带回服务商算的用量，但只有讨论回复和摘要事件记着；续写、改写、起草、检查、摘要的用量没地方记，作者看不到一部作品在 AI 上花了多少。第 d 步以后讨论每次发得更多，更该看得到。
- 内置模型表里有价格（[第 a 步](../architecture/2026-10-15-model-limits-and-usage.md)），一直没用上。

## Decision

起草和改写一样先作为提议显示，点「采纳」才进正文。每条讨论回复写这次用了多少 token。每次请求的用量和估算花费记进作品文件夹，设置「AI」里能看。

### 起草也是提议

编辑器里改写和起草共用一个提议（`editor/ai.go` 的 `proposal`）：要换掉的 [a, b) 划红色删除线，AI 写的绿色接在后面，正文一变提议就失效。提议记着采纳时打什么标记：改写打「AI 采纳」，起草打「AI 起草」。

- `ProposeDraft(a, b)` 开一个空的起草提议，`ProposeMore` 把流来的字接在后面，视图跟着它的末尾走。原来的 `BeginDraft`、`DraftAppend`、`EndDraft`（直接写进文档，结束时补一步撤销）删掉。
- 接在已有内容之后，提议放在文末，原文不划；覆盖已有内容，整章划掉。
- 起草期间、写完等着采纳时，正文只读。编辑器里和磁盘上的正文都不变。

写字页（`desk/ai.go`）照原型：

- 写完，标题下面一行「起草 N 字，绿色为起草。」（覆盖时加「，红色删除线为将被覆盖的原文」），按钮「放弃」「重新起草」「采纳」。
- 采纳：先存快照（「AI 改动前」，带这次的记录），再一步写进正文，打「AI 起草」标记，提示「已采纳起草；可撤销恢复原文，原版本已存入快照」。快照从开始起草挪到了采纳的时候，和改写一样：没采纳的起草不留快照。
- 停止：写了的留着等作者定，那一行写「已停止，起草 N 字……」；一个字没写，当没起草。
- 出错：写了的同样留着，提示「起草没有写完：……；已写的部分可以采纳」；一个字没写，提示「起草失败：……」。原型没有出错这一种，照停止办。
- 重新起草：丢掉这一份，按刚才的字数和方式再起草一次。
- 离开这一章、离开正文页、关掉 AI、改用磁盘上的版本时，没采纳的起草和改写一样丢掉（`stopAI`）。原来起草保留写到的地方。
- Ctrl+S 不再等 AI：没采纳的字不在正文里，当场保存。原来提示「AI 正在修改本章，完成后自动保存」。
- 起草对话框的说明照原型改成「……写完先供你查看，采纳后才写入正文，写入前保存快照；……」。
- 2026-10-15 连真实服务试的时候发现：点了「采纳」，按钮拿走了键盘又随即消失，Ctrl+Z 没有反应，提示却写着「可撤销」。原型也一样。现在点过这一行的「采纳」「停止」「取消」、放弃起草、按 Esc 关掉改写要求，键盘都回到正文（`w.ed.Focus()`），采纳以后光标在 AI 写的字后面；原型照改，DESIGN.md「AI 写的字要作者采纳」加了这一条。放弃改写以后，软件里改写要求重新出来、键盘在它里面，原型却收起这一行回到正文；软件的做法早于原型成为基准，哪边为准待作者确认。作者定了照原型，见[AI 基建第二轮](../architecture/2026-10-15-ai-second-pass.md)。

改写的「采纳」「放弃」和起草走同一套（`acceptProposal`、`dropProposal`），`write.proposed` 从改写的 `Job` 改成提议它的那次请求（`aiRun`），起草要用它记的字数、停没停、覆不覆盖。

### 每条回复的用量

讨论回复下面那一行，时间、模型、等级之后加「· N token」。N 是服务商算的输入加输出，按 K、M、B 写（DESIGN.md 文案那一条）。没有用量的旧回复不写。2026-10-15 起各步的用量记在各自的事件上，N 是这一轮所有请求的和（见[AI 基建第二轮](../architecture/2026-10-15-ai-second-pass.md)）。

### 作品记下用量

2026-10-16 起这一节和下面「设置里看」由[AI 记录](2026-10-16-ai-record-and-trace.md)取代：每次请求在 `ai-log.jsonl` 里记一行，`usage.json` 不再写，旧的累计数显示成「此前」。

- 每次请求的用量记进作品根目录的 `usage.json`，和 `work.yaml` 并排，随作品备份。按「服务商/模型」各一行：请求数、输入、缓存命中、缓存写入、输出、推理、估算花费和币种，按第一次用到的先后排。
- 只有一处记账：`ai.open` 建模型时给客户端包一层 `counted`，它的 `Complete` 返回后，用量不为零就记一笔。讨论（工具调用的每一步各算一次）、压缩、续写、改写、起草、检查、摘要都经过这里；失败和中途停下的请求，服务商给了用量也记（2026-10-15 起截断、被过滤的也记，见[模型层](../architecture/2026-10-08-model-layer-on-goai.md)）。
- 花费按记账那一刻的内置价格算（`model.Cost`）：没进缓存的输入、缓存命中、缓存写入、输出各按各的价；单次输入超过分档线的，整次按高档价。表里没有的模型不估，那一行只记 token。币种和这一行之前的不同时，不加进花费。
- 记账失败不让请求失败：花费只是给作者看的估算。
- 读的时候校验：每行要有模型名、不重复、数不为负、有花费就要有币种，有不认识的字段也报错。文件坏了，打开设置时提示是哪个文件、第几项；修好之前，之后的请求也不再记。
- `workspace.Store` 加 `Spend` 和 `Spent`，在作品的锁里读改写。

### 设置里看

- 设置「AI」的「本作品使用」（2026-10-15 起叫「本作品的模型」）下面一组「本作品用量」，说明「按内置价格估算，以服务商账单为准。」每个模型一行：模型 ID、「输入 1.7M，缓存命中 72% · 输出 59.2K」、「约 $4.44」或「无价格」。没用过写「尚未使用 AI。」
- 只能看，不能清零。打开设置或切到「AI」时读一次。
- 「AI」配置第 a 步起就是选了就存，没有保存按钮；没配讨论模型时发送照旧提示「请先配置讨论模型」。提案里这一条不用再改。

## Alternatives considered

- **起草保留直接写入，在 DESIGN.md 注明例外**（从提案搬来）：最强的理由是作者明确点了「起草」，写进去的位置是空的或者接在后面，有快照可以撤销，少点一下。没有用：规则留了例外就说不清，「AI 写的字要作者采纳」才简单。
- **只记 token，看的时候按现在的价格算花费**：最强的理由是文件简单，价格表改了，过去的花费跟着重算。没有用：有的模型按单次输入分档计价（Claude Haiku 5.5 过 10 万、GPT 6 系列过 27.2 万变贵），合计以后分不出哪些请求过了线；按当时的价格算也更接近当时的账单。代价是表里后来才有价格的模型，之前的请求不估。
- **从各处的记录里加出来**：讨论事件、摘要、检查结果里都可以记用量，看的时候加总。最强的理由是不用新文件。没有用：检查和摘要会被下一次覆盖，取消的请求和续写不留记录，加不全；打开设置还要读全部讨论日志。
- **记在 `.writer/` 里**：最强的理由是不进备份，同步盘不会跟着每次请求动。没有用：用量是这部作品的，换电脑或者从备份恢复以后应该还在。
- **在 `discussion.Model` 上加回调**：最强的理由是离发请求最近。没有用：`discussion` 和 `writing` 用不着知道作品记账；`ai` 本来就是建客户端、接上作品的地方，包一层就够。

## Consequences

- **收益**：
  - AI 写的字一律要作者采纳才进正文，没有例外；起草不满意，放弃以后正文和磁盘都没动过，也不留一份没用的快照。
  - 作者看得到每条回复和整部作品在 AI 上用了多少、大约花了多少。
  - 记账只有一处，以后加新的请求不会漏记。
- **代价和风险**：
  - 起草多点一下「采纳」。
  - 每次请求多读写一次 `usage.json`（几百字节）；作品文件夹多一个文件，同步盘和备份会跟着动。
  - 估算靠内置价格表：表外的模型、自己架的服务不估；币种用表里的，现在都是美元。
  - 用量只在打开设置时读，开着设置时后台摘要、检查花的不会马上显示。
  - 接在已有内容之后起草时，提议开头的换行在上一段末尾画出一小块绿底。
  - 「停止」和写完以后的「采纳」在同一个位置：起草刚好写完时点「停止」，点到的是「采纳」；改写的「取消」和「采纳」也一样。连真实服务时碰到过一次，怎么防待作者定。作者定了这一行换成采纳的半秒内点了不算，先做进原型、看过以后照做（见[AI 基建第二轮](../architecture/2026-10-15-ai-second-pass.md)）。
  - 2026-10-15 连 DeepSeek 试过，见[连真实服务走了一遍](../architecture/2026-10-15-ai-infrastructure.md#连真实服务走了一遍)：14 次请求以后，设置里那一行是「输入 19.2K，缓存命中 64% · 输出 12.4K」「约 $0.02」，和 `usage.json` 一致，按表里的价格手算也对得上；没有和服务商的账单核对。
- **测试**：
  - `go test ./editor`：`TestADraftWaitsToBeTaken`：起草流进来时正文不变，提议是流来的字；改写的提议不接着长；采纳以后一步写进正文，打「AI 起草」标记，撤销、重做。
  - `go test ./desk`：
    - `TestDraftAChapterFromItsOutline`：起草期间和写完只读，正文和磁盘都不变，没有快照；Ctrl+S 不等；采纳以后才有快照和标记，键盘在正文，按一次 Ctrl+Z 撤销；
    - `TestStopADraftKeepsWhatCame`：停止以后留着等采纳，「重新起草」，「放弃」，一个字没写就当没起草，出错时留着已写的；停止、放弃以后键盘在正文；
    - `TestRewriteASelection`：改写开始、采纳、按 Esc 关掉改写要求以后键盘在正文，采纳以后按一次 Ctrl+Z 撤销；放弃以后键盘在正文，「重新改写」用原来的要求改同一段；
    - `TestTurnTheAIOffAndOn`：关掉 AI 时没采纳的起草丢掉，正文和磁盘不变；
    - `TestWhatWasSent`：每条回复下面的 token 数；
    - `TestTheWorkShowsWhatItSpent`：「本作品用量」的每一行、「无价格」、「尚未使用 AI。」，打开时才读。
  - `go test ./workspace`：`TestSpentAddsUp`（按模型累加、先后、币种不同不加、落在作品根目录）、`TestSpentIsChecked`（每条校验和报错里的文件名）。
  - `go test ./model`：`TestCost`（各部分的价格、分档线前后、表外的模型）。
  - `go test ./ai`：`TestRequestsAreCounted`（每次请求记一笔，失败的也记，没有用量的不记，花费按内置价格）。
  - `npm run verify-prototype` 的「a draft」「AI turned off」「what was sent」「models and services」查原型；「a rewrite」「a draft」采纳以后按 Ctrl+Z、Ctrl+Y。
  - `SHOT=<dir> go test ./desk -run ShotAI` 多截一张写完等着采纳的起草。
