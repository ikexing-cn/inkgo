# Agent Note: 多语言用 mygo，书语言与界面语言分开

Status: implemented

## Problem

界面翻译不能改变书的计数、排版与 AI 输出语言，也不能把译文当作控件身份。

## Decision

界面使用 mygo i18n，中文 `zh-Hans` 为源语言，生成的 Go 和原型目录入库。宿主消息在 `locales/`，扩展消息在各自 `<id>text`；修改后运行 `ext-locales` 和 `prototype-locales`。内置发布检查要求翻译齐全，不能以此宣称已实现外部扩展的命名空间隔离与缺译回退。

菜单、帮助行、设置页、待处理分组使用稳定 ID，名称存函数，显示时取词。`App.LocaleChanged` 递增语言修订号，扩展派生表、标题和其他文案缓存失效。设置保存本机选择，空值跟随系统；启动不再强制中文。底层返回结构化错误，由宿主或扩展在显示时翻译；存盘的历史日志保留产生时的文字。

`workspace.Work.Language` 使用 `workspace.Language`，支持 Chinese (`zh-Hans`) 和 English (`en`)；读旧书补中文，新建必须显式提供有效值。字数、单位、分类默认值、token 估算、导出排版和 AI 正文输出跟书语言。英文按词数，混合汉字按字素计数；共用 `internal/grapheme` 的 BMP kind 表与整段 segmenter 回退。按原文 rune 换算字节偏移以处理坏字节。64 KiB kind 表比双位表快，Each 逐段预检避免回调重复。

提示词本身继续使用一种语言，输出语言按书注入。导出范围名称和新情节线默认名跟界面语言。原型与应用共用源消息；界面文案与布局规则只归 `DESIGN.md`。导入界面尚未实现，后续照原型带正文语言选择。

### 消息与生成链

key 是带区域前缀的小驼峰语义 ID，生成函数名随 key 变化；消息用整句加占位符，数量使用 plural，参数在 @key 的 placeholders 声明。底层不导入文字包，只返回错误码或类型。扩展使用 `<id>text` 子包，避免同文件与宿主 locales 同名，也避免 archive/format 底层顺手依赖文案。mygo 0.7.4 只生成主表，旧篇对是否自补扩展生成器记录的原话是「我们自己补吧」；现由 `internal/extlocales` 实现。

生成器检查 key 齐全、参数一致和语法，并拒绝扩展间及与主表重名，因为原型当前平铺消息。这是现有实现的限制，扩展命名空间不是已经完成的承诺。显示名称保存函数，不能初始化时取定或把译文用于排序。

### 原型、mygo 文案与数字

应用消息复用原型对应 key，不按字面相近另造；新可见功能先做原型，错误说明可直接加消息。原型专用 key 可保留。英文术语及具体字样以 `locales/en.json`、原型和 DESIGN.md 为准，不复制术语表。

mygo 系统角色菜单由 `mygo.menuAbout`、`mygo.menuHide`、`mygo.menuQuitApp` 覆盖中文空格等差异；原型仍用自己的 appAbout 等 key。`scripts/prototype/locales.ts` 不生成 mygo.* 函数，但按实际回退顺序核对两边显示一致。以后 toolkit 文案差异沿此入口处理，不能只改其中一份。

数字由 mygo/ICU 按语言分组；数量参数用 int，带小数用 double 和精度 skeleton，不能为取消分组改成 String。中文万字消息同时声明 value 与 full，让各语言可用完整数值且通过参数检查；token 的 K 写法以 DESIGN.md 为准。书语言决定 character/word 单位，不能固定为英文 characters。

### 历史验证与实现入口

迁移期间强制 zh-Hans 的启动代码已删除。`internal/sourcecheck` 检查全仓非测试、非生成 Go 的汉字字面量，测试钩子及固定身份等按白名单说明放行；`TestEnglishInterfaceDrawsNoHan` 检查实际绘制文字，避免把 Label 测试钩子算成漏译。其读取测试器私有绘制信息的做法依赖 mygo 内部结构。

字素快路径的依据：EPYC 9254、200ms、六次中位数，中文重复句旧 rune/改前/改后为 51.18/86.63/23.73 µs，对话体 93.56/177.90/40.43，混合 50.72/231.15/171.25，英文 197.73/212.31/209.09。双位表虽只占 16 KiB，中文/对话/混合 37.14/38.33/191.39 µs 比 kind 的 25.18/31.14/176.27 慢，超过当时 5% 门限，故采用 64 KiB kind；初始化 260.67 µs。Each 逐段预检为 64.27 µs（改前 91.29，直接 segmenter 577.51），不缓存已输出位置以免重复回调。坏字节必须按原文偏移换算；随机 Prefix/Suffix 对照保留 1500 例，避免平方复杂度拖慢测试。生成探针、BMP 边界和升级后重生成的步骤见 `internal/grapheme`。

书语言的具体规则见 `workspace/language.go` 及其测试，导出见 `ext/export/format`，token 估算见[既有取舍](2026-10-08-token-estimate-by-character.md)。新建支持语言选择，导入尚无应用入口，不能把原型表单当作完成实现。

## Alternatives considered

- **go-i18n v2** — 最强的理由是 Go 社区最常用，有 `goi18n extract/merge` 流程，CLDR 复数齐全。没选：mygo 自己的控件已经走 mygo 的 i18n，再起一套就有两个「当前语言」和两套回退；go-i18n 缺 key 在运行时才报错，mygo 生成的函数在编译时就报；go-i18n 的文档说运行时改 bundle 和读取并发不安全，插件带表进来不方便。
- **x/text/message + gotext** — 最强的理由是官方扩展库。没选：gotext 只从 Go 代码抽字符串，功能一直没做完，相关提案从 2022 年开着。
- **Fluent（hakastein/gofluent、lus/fluent.go）** — 最强的理由是消息模型最完整（terms、attributes）。没选：Go 实现都还没到 1.0，一个缺数字、日期函数，一个是借助 LLM 从 fluent.js 移植的。
- **中文原文当 key（gettext 式）** — 最强的理由是代码里直接看得到文案，缺译时自然回退。没选：改一个字就得改 key，AI 改文案时会顺手让一批译文失效。
- **迁移时以应用现在的字为准，原型跟着改** — 最强的理由是应用的字在真窗口里用过，迁移只抽不改，不会顺手改掉意思。没选：原型是界面的标准（AGENTS.md），英文表和术语也是照原型的字定的；以应用为准要把 1104 条里对不上的重写一遍，英文跟着重译。
- **提示词随界面语言翻译** — 最强的理由是模型看到的和作者用的是同一种语言。没选：每种语言都要单独调、单独测；输出语言要跟的是书，不是界面。


## Consequences

界面切换语言无需重开，书的计数、默认分类、排版和 AI 输出不随界面误变；结构化错误保留可翻译性。生成函数在编译期暴露 key 变化，原型与应用共用表减少双份文案。

代价是生成目录及缓存失效必须一起维护，key 改名要全仓迁移；原型 Intl 与 Go CLDR 版本可能产生细微数字差异。英文拉长与伪语言的布局仍需截图核对，不能用消息齐全测试代替。扩展目前不能同名 key，运行时缺译回退与内置发布齐全检查尚未独立验收；外部命名空间继续留 proposed。提示词保持一种语言减少逐语言调测，但输出语言约束仍需书语言的请求测试。
