# Agent Note: 讨论长了压缩成摘要，原话留在日志里

Status: implemented

## Problem

这是 [AI 基建](2026-10-15-ai-infrastructure.md)五步里的第四步 d，接在[讨论用工具查全书、当场记设定](../feature/2026-10-15-talk-looks-up-and-notes-the-setting.md)之后。

- 讨论只发最近四轮对话，更早的话模型看不到。作者早先说过的偏好、「这条线先放着」这类不算设定的话，过了四轮就丢了。
- 只发四轮也浪费容量：DeepSeek 的窗口有十几万 token，讨论只用了一小部分。
- 要发全部对话，就得在快装不下时把旧的收起来，不然请求会超出模型的上限，或者把整份设定挤成目录。

## Decision

讨论发全部还没压缩的对话。估计这次请求要超过模型的压缩阈值时，先把最早的几轮整理成一份摘要，之后的请求用摘要代替它们。原话不删。

### 什么时候压缩

每次发言和重试，存下作者的话以后、请求回复以前，`Engine.compact` 估计一次：还没压缩的对话全发，这次请求有多大。估计的办法是让 `Assemble` 在不限的空间里试装一次，再用 `prompt.Size` 加上各部分和开销。

- 上限取两者里小的：上下文上限乘压缩阈值，和能发送的上限（上下文上限减最大输出）。压缩阈值配在模型上（`CompactAt`，默认 80%，见[上下文上限配在模型上](2026-10-15-model-limits-and-usage.md)）。
- 设定按整份算。只有一种例外：对话压到只剩 20% 时整份设定也装不下，那它反正只能发目录，就按目录算。所以压缩是为了保住整份设定，设定反正发目录时不会白压。
- 超过上限就压缩：从最早的一轮起，压到剩下的对话不超过上下文上限的 20%（`keepPercent`）。比例写死，不设配置项。
- 最后一轮总是留着原话：作者接着说的，多半是在接上一轮。

### 怎么写摘要

- 摘要由讨论用的模型写，推理等级和讨论一样。
- 请求照讨论请求的样子拼（`lay`）：规则和工具、设定、之前的摘要、要压缩的那几轮，最后一条换成写摘要的要求（`discussion/prompts.go` 的 `digestAsk`）。前面这些和刚发过的讨论请求一字不差，服务商按前缀算的缓存用得上。工具照带，但发 `tool_choice: none`，模型只能写摘要。
- 要求分四栏，栏名照原型：在聊什么、作者的态度和偏好、还在商量的、下一步，每栏以「## 」起头。另外几条要求：
  - 设定里已有的只写编号，不复述；
  - 作者说定的，和 AI 提过、作者没表态的，分开写；
  - 有之前的摘要，就和它合成一份。
- 要压缩的轮次一次请求装不下时，从最早的一轮起装满为止，写一份摘要；再装下一批，这时之前的摘要就是刚写的那份。一直写到压完为止。
- 一轮本身就装不下时（比如换了窗口小的模型），作者的话和回复各截掉后半，结尾写「……（后面太长，略去）」。
- 写摘要失败，这次发言也失败，报「整理之前的讨论失败，原文已保存：……」。作者的话已经存下，可以重试；已经写好的那几份摘要留着。
- 压缩时界面照旧显示「正在思考…」，摘要不流式显示。

### 存在哪

- 摘要是讨论日志里的一个事件，`role: digest`。`through` 是它覆盖到的最后一轮回复的 ID；另外记模型、等级、推理、用量和 `sent`。
- 校验：摘要要有正文和 `through`，不回复某句话，不调工具；`through` 只有摘要能带。
- 原话一句不删，「搜讨论」（`search_talks`）照样搜得到。摘要本身不进搜索。
- 一轮压没压，看它的回复排在 `through` 前面还是后面（`uncompacted`）。
- 重试一句早先的话时，只看那句话之前的讨论；但写在那句话之后的摘要也带上（`Engine.read`），因为压缩可能就是为这次重试做的。

### 讨论请求

[每次请求由同一个拼装器装](2026-10-15-one-budget-for-every-request.md)里讨论的部分改成：

- 发的先后：规则 → 设定 → 摘要 → 还没压缩的对话 → 作者这次的话。摘要放在系统提示的最后，前面一句「之前的讨论已经整理成下面的摘要。原话还在，要用时用 search_talks 查。」
- 装的先后：
  1. 规则和作者的话；
  2. 设定目录的占位；
  3. 摘要，必须放下，放不下报「之前讨论的摘要超出模型的上下文上限，请在设置中「AI」配置里调大上下文上限」；
  4. 附上的正文；
  5. 对话：不再只取最近四轮，没压缩的全发，从新往旧放，放不下就停；
  6. 整份设定，放不下就发目录。
- 记录的部分多一项 `PartDigest`，排在设定目录后面。

### 界面

照原型（`prototype/pane.js` 的 `digest`）：

- 最新那份摘要覆盖到的最后一轮下面，居中一行「以上 N 轮已整理成摘要」，后面一个箭头。N 是这一行以上的轮数。
- 点开是摘要：按「## 」分栏，栏名加粗，最后一句「摘要由 AI 写成，有误可在对话中指出。」只能看，不能改。
- 旧的摘要已经合进新的，不再显示。
- 「AI 参考内容」的各部分多一项「讨论摘要」，排在设定和查阅结果之间。
- 那一行不算发言，「N 条发言」不变。

## Alternatives considered

- **压缩摘要让作者能改**：最强的理由是能直接纠正摘要的错。暂不做：要多一个编辑界面；作者在对话里纠正，下次压缩会收进去。
- **单独发一个写摘要的请求**，只带写摘要的规则、设定目录、之前的摘要和要压缩的对话：最强的理由是请求短、规则专一，模型不会被讨论规则带着去回复作者。没有用：讨论请求的前缀已经在服务商的缓存里，照它拼，压缩的大头按缓存价算；模型也看到和讨论时一样的整份设定，判断哪些已经记下更准。为了不让它回复作者，最后那条要求明说「这一次不回复作者，也不查阅、不记设定」，并且不让它调工具。
- **回到阈值以下就停**：一批一批压，每压一批量一次，不超了就停。最强的理由是压得少，留下的原话多。没有用：刚低于阈值，下一轮又要压，几乎每轮都多一个请求；提案定的是压到 20%。
- **最后一轮也压**：最强的理由是严格守住 20%。没有用：「第二个方向不错」这样的话离了上一轮的原话就接不上；最后一轮大到放不下时，讨论请求自己会挤掉它。

## Consequences

- **收益**：
  - 讨论记得住更早说过的话：没压缩的全发，压缩过的有摘要，原话可以搜。
  - 窗口大的模型，容量用得上。
  - 摘要和原话都在日志里，作者看得到摘要写了什么（DESIGN.md「模型看到的，作者也看得到」）。
- **代价和风险**：
  - **变贵**：每次请求发的对话比原来多，原来最多四轮。前缀缓存能抵掉一部分；第 e 步显示用量以后，看实际数字再调。
  - **摘要失真**：压缩可能丢掉或说错细节。原文还在，「搜讨论」能找回；摘要作者看得到。
  - **编号看不懂**：摘要照提案只写设定的编号，作者在界面上看不到编号，读到「见 [12]」不知道是哪一条。要显示成条目的名字，得先在原型里做。
  - **估算和实际不符**：压不压按估算定，和服务商的计数可能差得多（见[按字符估计 token](2026-10-08-token-estimate-by-character.md)）。
  - 压缩时要多等一个请求，界面上只有「正在思考…」。
  - 2026-10-15 连 DeepSeek 试过（见[连真实服务走了一遍](2026-10-15-ai-infrastructure.md#连真实服务走了一遍)）：deepseek-flash 上下文 14K、阈值 50%，第 6 轮压了前 2 轮。摘要 547 字，四栏都有，作者的偏好和还在商量的都写对了，引设定写成「[2]」这样的编号（上一条）；那次请求输入 2120、缓存命中 1152，输出 1792 里推理 1409。之后的回复读摘要接得上。
- **测试**：
  - `go test ./discussion`：
    - `TestALongTalkIsCompacted`：超过阈值才压；摘要请求照讨论的样子拼，不让调工具；摘要事件的各项；回复读摘要和之后的几轮；原话还在，「搜讨论」搜得到；再压时合进上一份；
    - `TestCompactionTakesWhatOneRequestHolds`：一次装不下分几次，每份接着上一份，压到只剩 20%；
    - `TestAFailedCompactionIsRetried`：失败时作者的话存着，重试时读到写在那句话后面的摘要；
    - `TestATurnTooLongIsCut`；
    - `TestTalkSeesTheSettingAndTheTurns`：没压缩的对话全发。
  - `go test ./workspace`：`TestModelOutputKeepsReasoningForReview` 查摘要事件的校验。
  - `go test ./desk`：
    - `TestTheTalkShowsWhereItWasCompacted`：那一行的位置，点开、再点收起，「讨论摘要」一项，新摘要取代旧的；
    - `TestADigestSplitsAtItsHeadings`。
  - `go test ./prompt`：`TestBudgetRecordsItsParts` 查 `Size`。
  - `npm run verify-prototype` 的「a long talk」查原型。
